因为你这组写法里，轴5和轴6的延时其实是一样的。

在 SelfCheck.TcPOU#L20 这行里：

backoff_delay : ARRAY[1..7] OF TIME := [T#0MS,T#0MS,T#0MS,T#0MS,T#2S,T#2000MS,T#0MS];


数组下标和轴号是一一对应的，也就是：
  • 第1个值是轴1
  • 第3个值是轴3
  • 第5个值是轴5
  • 第6个值是轴6

所以这组参数的实际含义是：
  • 轴3: T#0MS，不等待
  • 轴5: T#2S
  • 轴6: T#2000MS

而 T#2S 和 T#2000MS 是完全相同的时间，所以轴5和轴6“等两秒后一起动”是正常结果，不是异常。

对应的等待逻辑在 SelfCheck.TcPOU#L272：

IF backoff_delay[i] = T#0ms THEN
    wait_timer[i](IN:=FALSE);
    mv_abs_exec[i] := TRUE;
    stu[i] := 8;
ELSE
    wait_timer[i](IN:=TRUE, PT:=backoff_delay[i]);
    IF wait_timer[i].Q THEN
        wait_timer[i](IN:=FALSE);
        mv_abs_exec[i] := TRUE;
        stu[i] := 8;
    END_IF
END_IF


这段逻辑里，轴3如果是 T#0MS，理论上会直接走上面的分支，不会被这个延时数组拦住。所以“轴3不动”这件事，多半不是这行 backoff_delay 直接导致的，而更像是下面几种情况之一：
  • 轴3当时根本没走到 72/8 这个回退阶段
  • 轴3进了回退，但 MC_MoveAbsolute 没成功触发
  • 轴3有报错、被中止，或者机械上被卡住了

最值得现场盯一下的量是：
  • G.selfcheck_stu[3]
  • fb_move_abs[3].Error
  • fb_move_abs[3].CommandAborted
  • G.axis[3].Status.Error

如果你想要的效果是：
  • 轴3立刻回
  • 轴5等 2 秒
  • 轴6比轴5再晚 0.5 秒

那就应该写成：

backoff_delay : ARRAY[1..7] OF TIME := [T#0MS,T#0MS,T#0MS,T#0MS,T#2S,T#2500MS,T#0MS];
