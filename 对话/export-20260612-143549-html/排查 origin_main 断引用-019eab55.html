Codex · 2026-06-09 15:44
这是本地 Git 引用坏了，不是 GitHub 远端分支坏了。

我刚看了一下仓库状态，关键现象是：

## main...origin/main [gone]
warning: ignoring broken ref refs/remotes/origin/main


并且本地这个文件存在：

.git\refs\remotes\origin\main


但内容是一串空字节：

...


正常情况下，这个文件里应该是一行 commit hash，比如：

85da85ace0ed2948de17df03d5a6e78e13573ec1


所以日志里的意思是：

cannot lock ref 'refs/remotes/origin/main'
unable to resolve reference 'refs/remotes/origin/main'
reference broken


Git 想更新本地的远端跟踪分支 origin/main，但发现这个引用文件内容损坏，无法解析成 commit hash，于是更新失败。

不过这句也很重要：

Everything up-to-date


说明你的 git push -u origin main 本身没有发现需要推送的新提交，或者远端已经是最新的。失败发生在本地 Git 记录 origin/main 状态的时候，不一定表示 push 到 GitHub 失败。

修复方式通常是删除这个坏掉的本地远端跟踪引用，然后重新 fetch：

chcp 65001 > $null
$OutputEncoding = [Console]::OutputEncoding = [System.Text.UTF8Encoding]::new()

Remove-Item -LiteralPath .git\refs\remotes\origin\main
git fetch origin main
git branch --set-upstream-to=origin/main main
git status -sb


这不会删除你的本地 main 分支，也不会删除 GitHub 上的 main 分支；删的是本地缓存的 origin/main 这一条远端跟踪记录。
