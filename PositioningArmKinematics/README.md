# 定位臂 Eigen 运动学

数学模块只依赖Eigen，不连接ADS；现已由原ADS工程直接编译，并接入原WPF界面、
ArmManualAdsService和`下位机工程程序/250902/Untitled2`的PLC源码。不使用Pinocchio、Pink或Python。

## 依赖与构建

- MSVC x64，当前工程使用 `v142`。
- CMake 3.24 或更高版本。
- Eigen 3.4 或更高版本。

如果本机没有 Eigen，可使用 Conda 安装到模块目录：

```powershell
conda create --prefix .deps --override-channels -c conda-forge eigen=3.4.0 --yes
```

构建并运行离线测试：

```powershell
.\BuildAndTest.ps1 -Toolset v142
```

也可以直接指定 Eigen 安装前缀：

```powershell
.\BuildAndTest.ps1 -EigenRoot 'D:/path/to/eigen-prefix'
```

## 坐标与模型

全部运动学输入和输出采用倍福机械零位对应的坐标，轴1用米，轴2至5用弧度；程序角只用于显示，不可再次传入机械角接口。

- 基座 XYZ 固定，+Z 向上，轴2至4位置增大表示绕 +Z 逆时针旋转。
- 机械角全零时，200 mm、180 mm两根连杆均指向 -Y。
- 程序零位的机械角为轴2=90°、轴3=180°、轴4=180°、轴5=0°。
- 在程序零位，轴5沿 +X，轴4到工具中心线的456.3 mm偏移沿 +X，554.5 mm前端方向沿 -Y。
- 轴5机械角减小使前端抬起。对外的俯仰点动“抬头为正”。
- 固定安装高度被省略，`forward().position.z()`是虚拟高度，不能当成离地高度或避碰依据。
- 默认几何尺寸已填入；速度、编码器换算和轴1、2端点仍必须明确配置。
- 轴1实际行程为200 mm，但行程不确定上下端点的读数。测试中的0~200 mm端点不是实机标定。
- 本次协调控制按机械读数限制轴2在0~180°；轴3至5按用户要求不增加软件位置范围，现场NC限位仍需核对。

编码器换算和程序显示换算分开：

```text
mechanical[i] = (encoder[i] - calibration[i].zero) * scale[i] * direction[i]
program[1..4] = mechanical[1..4] - [pi/2, pi, pi, 0]
program[0] = mechanical[0]
```

倍福读数已是机械零位角度时，轴2至5的`zero=0, scale=pi/180, direction=+1`。
轴1已确认为毫米，比例为0.001，实际下端读数仍需填写。窗口内判定到位不会改写编码器、修改偏置或伪造精确零读数。

模型公式（长度为米、`q`为机械坐标）：

```text
a = q2 + q3 + q4 - pi/2
p = [0, 0, q1]
  + 0.200 * [sin(q2), -cos(q2), 0]
  + 0.180 * [sin(q2+q3), -cos(q2+q3), 0]
  + Rz(a) * Rx(q5) * [0.4563, -0.5545, 0]
Q = Quaternion(Rz(a) * Rx(q5))
```

`a`在程序零位为2π，与零姿态等价；只在姿态表达上等价，不对关节位置取模。
此时轴2连杆沿+X、轴3连杆沿-X，前端虚拟位置为`[476.3,-554.5,q1] mm`。
不能把程序偏置从正解连杆角中再次减去，否则会把折叠姿态算成伸直姿态。

## 点动接口

- `solveJog(current, {JogAxis, speed, duration})`：单模式带符号速度点动，平移米/秒，旋转弧度/秒。
- `solveCartesianJog`：直接指定小步位移的底层接口，拒绝同时给多个非零分量。
- X/Y：只动轴2、3、4，保持偏航；偏航：只动轴2、3、4，保持前端位置。
- Z：只动轴1；俯仰：只动轴5，允许前端圆弧移动。
- `solveJog`在近奇异区缩小实际点动速度，返回`speed_scale`；底层指定距离接口不改变请求距离，无法满足则拒绝。
- 逆解采用局部阻尼求解、限位、单步速度约束与支路连续检查。位置与姿态达到容差后才返回成功；失败时目标保持当前值。
- `forward` / `computePose`、`computeFrameJacobian`、`checkLimits`、`isNearSingularity`用于数学验证。
- `fromEncoder` / `toEncoder`仅转换机械角；`toProgramCoordinates` / `fromProgramCoordinates`转换显示角。

程序零位是平面折叠奇异位，XY/偏航不能从该位正常启用任意方向点动。
Z、俯仰与专用关节回位不经过平面逆解，不被这个奇异状态一并禁用。

## 程序归零

规划接口由ADS后台调用，不是倍福硬件找零，不会调用`MC_Home`或重置任何机械零点。

1. `isAtProgramZero`分别检查机械读数90°±3°、180°±3°、180°±3°、0°±1°，包含边界。
2. 四轴全部在窗口内时，`planProgramZeroReturn`返回`AlreadyAtZero`，目标为原始状态，轨迹为空，不强制精确对齐。
3. 窗口外时规划回到精确机械目标90°、180°、180°、0°，轴1保持输入位置。
4. 四个旋转轴均向目标单调运动，不夹紧关节终点、不用±360°等价角绕过限位。
5. 使用有界四参数关节曲线，局部优化前端相对起点的位置偏离与四元数姿态偏离，加上微小关节路径惩罚。它是低扰动启发式，不保证全局最优或末端完全不动。
6. 采用五次时间律；根据连续导数上界延长时间，使关节速度和加速度不超过配置值，首尾速度、加速度为零。
7. 检查末端偏离与转角预算，并利用单调关节路径的弧长上界覆盖采样点之间的偏离。

`HomeOptions`必须显式设置：

- `max_joint_travel`：本次允许轴2至5各自回位的最大角距离。
- `max_acceleration`：轴2至5的加速度上限。
- `max_tip_displacement`：整个过程中前端相对起点的最大位移预算。
- `max_tool_rotation`：整个过程中相对起始姿态的最大转角预算。

关节速度使用`ArmKinematicConfig.max_velocity`。不提供上述预算时，窗口外回位返回`InvalidInput`；
限位、回位距离、末端预算或采样数不满足时，返回相应错误，`target`保持输入、`samples`为空。
正常回位返回带时间、位置、速度、加速度的样本及位移/转角上界，可用于离线预览。

ADS发送曲线起点、终点、弯曲系数和时间，PLC使用与数学模块相同的五次时间律。
任意更换插补方式、重新定时或只发送最终位置都会丢失这些轨迹约束。
没有对运动曲线加加速度做额外约束；停止功能块使用原单轴区域配置的减速度和加加速度。

## 执行边界

没有自碰撞检查、人体碰撞检查、经验证的制动距离或实机验证。
归零也不是紧急撤离功能，不应在导丝/导管与人体接触时把“尽量不动”当作安全保证。
后台检查反馈有效且不过期、各轴已静止、驱动使能和故障状态；
PLC执行曲线时检查限位、速度、加速度、心跳、急停请求和跟随误差。
这些必要的停止和限位条件不是备用控制路径。

当前测试中的限位、速度、加速度和位移预算都是合成值，不可直接用于实机。

## 接入 ADS 工程

原`ADS.sln`直接编译数学模块源文件，不需先构建静态库，也不需要功能开关。
Eigen头文件路径为`PositioningArmKinematics/.deps/Library/include/eigen3`。
依赖目录不入Git，换机器必须显式提供Eigen 3.4头文件，缺失即构建失败。

```text
原界面定位臂面板 -> 管道命令 -> ArmManualAdsService
-> Eigen小步解算/程序回位规划 -> ADS曲线数据和提交序号
-> PLC ArmCartesian -> 五轴外部设定点
```

新增运动命令失败即取消并显示错误，不重试失败目标、不切换单轴Jog、不绕圈、
不夹紧越界目标、不用默认值代替未填写的端点。原有独立Jog保留，与协调曲线互斥。

原“定位臂手动控制”面板新增X/Y/Z/俯仰/偏航选择、正负按住点动、速度、
程序归零、停止、程序角和错误显示。XYZ速度为mm/s，转动为度/s；
正俯仰表示抬头，即轴5读数减小。松开、失去鼠标捕获或窗口焦点时取消点动。

每次使用前填写轴1下端的实际PLC读数，上端自动为下端+200mm。
归零另需填写最大轴角行程、前端偏离上限和姿态转角上限。
轴速度、加速度、停止减速度和停止加加速度使用原单轴区域设置。
这些数值不是新增的实机标定结果。新增输入当前不持久化。

点动名义位移为速度乘0.1s，近奇异区缩小位移；以五次时间律执行，必要时延长时间满足轴约束。
等待一段执行完毕后，从新反馈规划下一段。因此这是连续按住触发的小步点动，
不是恒速流式轨迹控制，实际平均速度受加减速和通信周期影响。
X/Y/偏航保持条件在每段目标处满足求解容差，关节插补中间不承诺精确笛卡尔直线。

### PLC接口

`G.arm_curve_data`为17个LREAL：0..4起点、5..9终点、10..14弯曲系数、
15总时间、16轴1下端，单位为mm、度和秒。
先写完整数据及`arm_curve_cancel=FALSE`，成功后单独提交`arm_curve_request`。
PLC仅在序号变化时锁存，回传`arm_curve_ack`、状态、错误和进度。
状态0/1/2/3/4分别为空闲/执行/完成/取消/错误。
主机操作续约期限300ms，PLC独立曲线心跳期限500ms。
缺少新符号直接报反馈无效，不兼容旧PLC、不自动退回旧控制方式。

`ArmCartesian`在MAIN调用，工程PLC和NC-SAF均配置1ms。
部署前必须核对任务同步、优先级、NC轴配置和跟随误差容差。
外部给定PLC任务优先级应不低于NC-SVB；当前工程为PLC20、SVB8，
尚未更改，因为MAIN还运行原介入机器人控制，需要现场统一评估调度。
停止功能块自身报错时保留错误和控制权，不自动复位或恢复运动。
