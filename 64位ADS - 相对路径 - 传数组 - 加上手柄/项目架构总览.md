## 1. 程序简介

血管介入手术机器人的上位机控制程序，C++ / Windows / Visual Studio。承担：

- 通过 **ADS 通讯**控制倍福（TwinCAT 3）PLC，从而控制 7 轴机器人运动；
- 通过 **TCP** 周期查询采集卡，读取机器人传感器的轴向力 / 扭矩电压；
- 把传感器电压经标定/解耦/死区/限幅，映射为力反馈手柄的下发指令；
- 力反馈手柄输入同时又作为机器人运动的指令源（双向闭环）。

入口：`main.cpp::main()`。运行模型：单线程主循环 + 力采样后台线程 + 力日志 writer 线程 + 可视化 HTTP/WebSocket 服务线程。

## 4. 主循环骨架（`main.cpp` L676-L2577）

主循环是单线程的，每拍按固定顺序执行：

```
1)  手柄 poll + 滤波（L678-L697）
2)  快退标志清零；降频读 from_left（L699-L720）
3)  按键解码 + 边沿处理（L722-L867）
4)  PLC 急停保持轮询（L870-L898，降频 1/10）
5)  freeze/estop 时清力反馈输出（L900-L904）
6)  键盘 _kbhit 处理：F/Z/C/S/1/2/Q/W/E/R（L907-L1030）
7)  导丝模式切换（L1033-L1130）
8)  PLC 自检/重同步轮询（L1133-L1183，降频 1/50）
9)  启动准备恢复路径（L1186-L1203）
10) 力感 CSV 元数据编码（mode/reverse/push_pull/rot_sign）（L1209-L1216）
11) 顶层模式分支构建 refer + 气缸指令（L1232-L2127）
    |-- 启动序列分支（L1499-L1633）
    |-- 导丝独立分支（L1635-L1653）
    |-- 常规导管/协同分支（L1655-L2117）
        |-- axis1 Follow/SwitchWait/FastMove/RestoreWait 状态机
        |-- 协同模式 axis6 增量叠加 + run_axis6_crawl_state
12) write_refer（L2127）
13) axis4 手动控制轮询（L2133-L2149，降频 1/20）
14) 气缸写入 + 快退标志写入 PLC（L2155-L2225）
15) 力感采样（按 period_ms 节拍）（L2228-L2315）
16) 力反馈诊断打印（限频 1Hz）（L2318-L2354）
17) process_force_feedback -> Handle::setforce_axis（L2356-L2370）
18) 力反馈值诊断打印（限频 1Hz）（L2372-L2393）
19) 手柄滤波 prev 更新（L2396-L2399）
20) 可视化状态推送 + UI 命令轮询（L2402-L2576）
```

每个步骤的详细语义请查对应模块文档。降频读取的位置不会影响控制正确性（PLC 侧这些变量不会突变），只为减轻 ADS 通信负担。

## 6. 线程模型

| 线程 | 启动方式 | 职责 | 停止条件 |
|---|---|---|---|
| 主线程 | `main()` | 主循环（运动 + 力反馈 + UI） | 主循环 break 后清理 |
| `TcpForceDaqClient::worker_` | `tcp_force_daq.start()` | 周期查询采集卡、解析、更新 latest_v_、触发 on_sample 回调 | `tcp_force_daq.stop()` |
| `ForceLogger::writer_thread_` | `force_logger.start()` | SPSC 环形缓冲消费者，把力样本落盘 CSV | `force_logger.stop()` |
| `VisServer` 内部线程 | `vis_server.start()` | HTTP/WebSocket 服务，推送状态、轮询 UI 命令 | `vis_server.stop()` |
| FLCatheter SDK 伺服循环 | `Handle::init()` -> `startServoLoop(SyncUpdate, NULL)` | 手柄底层伺服（SDK 内部） | 最后一个设备 `close()` 时 `stopServoLoop` |

线程间共享状态都用 `std::atomic` 或 `std::mutex` 保护（`TcpForceDaqClient` 用 `frame_mutex_` 保护 `latest_v_`，`ForceLogger` 用 SPSC 原子 head/tail）。

## 8. 维护总约定

每个模块 md 末尾都有自己的"修改XX时的维护要求"+"变更日志"小节。统一约定：

1. **任何修改都要先看相应模块文档的"维护要求"小节**，按那里的清单更新文档。
2. **变更日志必填字段**：日期 / 变更人（AI 模型版本或工程师 initials）/ 涉及文件与函数 / 行为变化要点 / 是否影响其他模块。
3. **跨模块改动**要在所有受影响模块的变更日志都追加条目，并在本 §7 / §8 同步更新已知问题清单。
4. **新增源文件**：在本 §3 矩阵添加一行；如果是新模块，新建独立 md 并在本 §2 索引添加一行。
5. **删除/重命名符号**：必须用全工程 grep 确认所有引用点，并在变更日志列出。
