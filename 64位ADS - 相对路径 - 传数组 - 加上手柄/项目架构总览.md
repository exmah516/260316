## 1. 程序简介

血管介入手术机器人的上位机控制程序，C++ / Windows / Visual Studio。承担：

- 通过 **ADS 通讯**控制倍福（TwinCAT 3）PLC，从而控制 7 轴机器人运动；
- 默认通过 **ADS** 读取力传感器，保留 TCP DAQ 作为显式可选采样源；
- 把传感器电压经标定/解耦/死区/限幅，映射为力反馈手柄的下发指令；
- 力反馈手柄输入同时又作为机器人运动的指令源；
- 以统一会话同时记录 100 Hz 力、50 Hz 位置/手柄和 Action 4 视频。

入口：`main.cpp::main()`。运行模型：单线程控制主循环 + 100 Hz ADS 通信线程 + 定位臂独立 20 Hz ADS 线程 + 可选 TCP DAQ 线程 + 异步 CSV writer + Media Foundation 相机线程 + 本地命名管道线程。所有磁盘和视频封装均不在控制主循环执行。

### 1.5.2 快退家族（容易混用的 5 个写法）

| 写法 | 严格含义 | 出处 |
|---|---|---|
| **axis1 快退** | 主循环里 axis1_crawl 进入 SwitchWait/FastMove/RestoreWait 阶段的口语统称 | 运动流程说明.md §6 |
| **axis6 快退** | 主循环里 axis6_crawl 进入相同三阶段的口语统称 | 运动流程说明.md §7 |
| `axis1_fast_return` | 写往 PLC 的 bool 标志，专指 axis1 链路快退（步 14 写入） | ADS通讯说明.md §3.6 |
| `axis6_fast_retract` | 写往 PLC 的 bool 标志，专指 axis6 链路快退（步 14 写入） | ADS通讯说明.md §3.6 |
| `CrawlState::Phase::FastMove` | 爬行状态机**阶段名**（四阶段之一），axis1/axis6 共用 | 运动流程说明.md §6.1 |
| `fast_move_active` | 力反馈代码里 `axis1_fast_return || axis6_fast_retract` 的合并别名 | 力反馈说明.md §4 |

文档里写"快退"时，**优先用 `axis1_fast_return` / `axis6_fast_retract` 这种符号名**，避免"快退/快速回退"口语化造成歧义。

### 1.5.3 手柄 582/587：语义角色 vs 物理 SN

`main.cpp` 顶部 `swap_handle_roles = true` 会交换两只物理手柄的角色。本文档体系内一律使用"**语义角色**"，不直接引用物理 SN：

| 语义角色 | 控制对象 | 力反馈输出字段 | 物理 SN（当前接线） |
|---|---|---|---|
| **handle_axis1（导管手柄）** | axis1/2/3/5 | `force_582_f` / `force_582_n` | 587（因 swap） |
| **handle_axis6（导丝手柄）** | axis6/7 | `force_587_f` / `force_587_n` | 582（因 swap） |

> 改 `swap_handle_roles` 后只改接线、不改文档；表格右列可能会更新，但左三列保持稳定。

### 1.5.4 三套坐标基准

| 名称 | 基准 | 字段表达式 | 主要用途 |
|---|---|---|---|
| **abs（绝对坐标）** | PLC 机械原点 | `plc_act_pos[i] + plc_init_pos[i]` | PLC 内部、`G.axisN_return_cmd.TargetAbs`、窗口边界 |
| **rel（相对坐标）** | `init_pos` | `plc_act_pos[i]` / `pos[i]` | `G.refer` / `G.Act_pos` 的读写值 |
| **from-left** | 左限位 | `abs - leftlimit[i]` | 监测/门控（如 axis3 投送停止位、axis6 入门门控） |

详见 [运动流程说明.md §2](运动流程说明.md#2-坐标系约定)。

### 1.5.5 轴编号 vs 数组索引

代码里所有 7 维数组（`pos[7]`、`plc_act_pos[7]`、`G.refer[7]` 等）都是 **0-based**：`[0]`=axis1、`[1]`=axis2、... `[6]`=axis7。PLC 符号名是 1-based（`G.axis1_*`...`G.axis7_*`）。在文档里写 `pos[1]` 时务必同时标注"axis2"，避免读者误把数组索引当成轴号。

## 4. 主循环骨架（`main.cpp` 主循环 `while(true)`）

`main()` 在控制流程初始化前先调用 `sensor_calibration_experiment::is_command()`。当首个参数为 `--sensor-calibration` 时，程序立即转入 `sensor_calibration_experiment::run()` 并在该函数返回后退出；该分流早于手柄角色对象及其 `init()`、WPF/`VisServer`、运动运行态和正常 ADS 控制链初始化，因此不会进入下述控制主循环。该模式下 `--self-test` 只运行离线数学测试，`--validate-only` 只定位并校验四份原 CSV，完整实验仅建立 ADS 只读连接并通过 `ADSReadSum` 同步读取四路 `INT16`，不执行 ADS 写操作。命令、现场步骤和结果判读详见 [传感器重新标定实验说明.md](传感器重新标定实验说明.md)。

正常模式完成初始 ADS 路由后启动 `AdsCommunicationService`。通信线程按 QPC 绝对截止时间独立运行 100 Hz Sum Read/Sum Write；主循环每拍等待下一快照并消费内存状态，不再用 `loop_count` 分频执行旧的高频直读/直写。设备必须已处于 `ADSSTATE_RUN`，程序不会替现场切换 PLC 状态，也不执行 Activate Configuration。

> 主循环位于 `main.cpp`，是 `int main()` 内、所有初始化完成后的 `while (true)` 死循环。以下编号只描述当前顺序；跨文档定位优先使用函数/类型名，不使用会随插入漂移的硬行号。

主循环是单线程的，每拍按固定顺序执行（步骤编号即"主循环第 N 步"，其他文档引用主循环位置时都用这个编号）：

```
1)  等待下一份 100 Hz AdsFastSnapshot；排空主机侧记录快照队列
2)  读取通信统计与 Notification 事件状态；判定 Running / SoftHold / Reconnecting / PlcRestarted
3)  首次失败立即保持最后参考、清力输出并丢弃故障期间手柄增量；恢复后重建实际位置与手柄基准
4)  同进程重连清瞬态但保留稳定模式/方向；PLC 重启则清调零、反馈、PI 和控制激活并等待人工恢复
5)  手柄 poll + EMA 滤波（axis1/axis6），生成按键边沿
6)  freeze/estop/host_comm_timeout 安全门控与键盘命令
7)  导丝模式切换（独立、协同递送、协同撤出进入与退出）
8)  消费自检、重初始化、急停和 axis4 OnChange Notification 状态
9)  启动准备恢复路径（startup.completed 但 !control_active 时 sync_all 兜底）
10) 主从位移欠账/PI 条件更新（与磁盘记录无关）
11) 顶层模式分支构建 refer[7] + 气缸指令
    |-- startup_sequence 分支（startup.is_active()）
    |-- 导丝独立分支（guidewire_mode == Independent）
    |-- 常规导管/协同分支（guidewire_mode == None 或 Cooperative）
        |-- axis1 Follow/SwitchWait/FastMove/RestoreWait 状态机
        |-- 协同双方向 axis6 增量叠加、动态窗口与串行换手 + run_axis6_crawl_state lambda
12) 计算纯净力和力过渡状态；组装 AdsOutputCommand
13) publish_output()：通信线程下一次 Sum Write 合并 refer、快退、气缸、axis4、平滑旁路和主机心跳
14) 统一记录：force.csv 消费每份 100 Hz 快照；motion.csv 取偶数序号形成 50 Hz；只入队，不做磁盘 IO
15) 主从位移 PI 健康门控与 process_force_feedback() -> Handle::setforce_axis()
16) 力反馈诊断打印（限频 1 Hz）
17) 手柄滤波 prev 更新（避免暂停/等待期间累积大跳变）
18) 以 30 Hz 推送 877 字节 VisState（含 ADS 诊断、定位臂和 axis4 点动状态）；消费版本化 VisCommand
```

每个步骤的详细语义请查对应模块文档。快速位置、力和看门狗状态来自同一 Sum Read 快照；低频状态由 Notifications 更新，避免旧的多组分频轮询造成时序分散。

## 6. 线程模型

| 线程 | 启动方式 | 职责 | 停止条件 |
|---|---|---|---|
| 主线程 | `main()` | 消费 ADS 快照、运动状态机、力反馈、记录入队与 UI 编排 | 主循环 break 后清理 |
| `AdsCommunicationService::worker_` | `ads_communication.start()` | 100 Hz QPC 调度、Sum Read/Sum Write、Notifications 注册、软保持/重连、看门狗恢复与诊断统计 | `ads_communication.stop()` |
| `TcpForceDaqClient::worker_` | `tcp_force_daq.start()` | 周期查询采集卡、解析并更新 latest_v_ | `tcp_force_daq.stop()` |
| `AsyncCsvWriter` worker | 每个 CSV `start()` | 排空 SPSC 队列、写盘、flush、报告错误 | 统一停止或专用表停止 |
| `Action4CameraRecorder::Impl::worker_` | 记录器构造 | Media Foundation 探测、采集、编码、预览共享内存与 MP4 封装 | 进程退出 |
| `ExperimentRecorder::stop_thread_` | 用户停止/写盘故障 | 等待相机封装和全部 CSV 排空，写最终 `session.json` | 单次停止完成 |
| `VisServer` 内部线程 | `vis_server.start()` | 本地命名管道状态推送和命令接收 | `vis_server.stop()` |
| FLCatheter SDK 伺服循环 | `Handle::init()` -> `startServoLoop(SyncUpdate, NULL)` | 手柄底层伺服（SDK 内部） | 最后一个设备 `close()` 时 `stopServoLoop` |

线程间共享状态使用 `std::atomic`、`std::mutex` 或单生产者/单消费者队列保护。服务启动后，高频周期及运行期专项低频 ADS 请求均由通信线程串行执行；ADS Notification 回调只复制数据，不从回调内发起 ADS 请求。控制线程不等待 CSV 写盘，只有程序退出复用同步停止路径等待文件完整关闭。
