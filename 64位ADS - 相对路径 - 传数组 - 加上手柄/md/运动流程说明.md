## 2. 坐标系约定

机器人共 7 个轴：

| 索引 | 角色 | 单位 | 备注 |
|---|---|---|---|
| 0 (axis1) | 导管线性 | mm | 主推/拉轴，物理 SN 587 手柄控制 |
| 1 (axis2) | 导管旋转 | deg | 跟随手柄旋转 |
| 2 (axis3) | 导管线性镜像 | mm | 跟随 axis1 平移 |
| 3 (axis4) | Y阀点动 | — | 仅 PLC 侧手动控制 |
| 4 (axis5) | 导管线性镜像 | mm | 跟随 axis1 平移 |
| 5 (axis6) | 导丝线性 | mm | 物理 SN 582 手柄控制 |
| 6 (axis7) | 导丝旋转 | deg | 跟随手柄旋转 |

**三套坐标基准**（容易混淆，务必区分）：

| 名称 | 基准 | 用途 | 字段 |
|---|---|---|---|
| **绝对坐标 abs** | PLC 机械原点 | PLC 内部、`G.axisN_return_cmd.TargetAbs`、窗口边界 `start_abs`/`end_abs`/`target_abs` | `plc_act_pos[i] + plc_init_pos[i]` |
| **相对坐标 rel** | `init_pos` | `G.refer`、`G.Act_pos` 的写入读出值 | `plc_act_pos[i]`、`pos[i]` |
| **from-left** | 左限位 | 监测/门控（如 axis3 投送停止位、axis6 入门门控） | `abs - leftlimit[i]` |

换算函数（`motion_sync`）：
```
from_left_to_abs(i, from_left_mm) = leftlimit[i] + from_left_mm
from_left_to_rel(i, from_left_mm) = from_left_to_abs(i, from_left_mm) - init_pos[i]
```

## 3. 窗口与跟随基准

### 3.1 axis1 爬行窗口（导管侧）

固定窗口，由 `ControlConfig` 决定：
```
axis1_window_left_from_left_mm  = 3.0   mm  (距左限位)
axis1_window_right_from_left_mm = 23.0  mm
```
窗口宽度 20 mm。`axis1_window_left_abs()` / `axis1_window_right_abs()` 输出绝对坐标边界。窗口边界**不随模式变化**，每次 `sync_axis1` / `sync_all` 都重置。

### 3.2 axis6 爬行窗口（导丝侧）

轴5相对窗口，进入独立/协同导丝模式时直接重建：
```
axis5_from_left_mm = axis5_abs - axis5_leftlimit
window_start_abs   = axis6_leftlimit + axis5_from_left_mm + axis6_window_min_gap_from_axis5_mm(1.0)
window_end_abs     = window_start_abs + axis6_window_size_mm(20.0)
```
因此窗口的 from-left 语义固定为 `[axis5 + 1, axis5 + 21]`，宽度 20 mm。

**窗口锁定机制**（`axis6_window_locked` + `axis6_locked_window_start/end_abs`）：
- 每次进入**独立导丝模式**时都按轴5当前实际位置直接重建并锁定，不再使用覆盖阈值判断；其快速回退和后续 `sync_axis6(..., rebuild_window=false, ...)` 继续复用锁定窗口。
- **协同递送与协同撤出**都不使用固定边界：两个链路都处于 `Follow` 时，每拍按 axis5 实际位置重建 `[axis5+1, axis5+21]` 物理相对窗口。axis6 到达远端 `axis5+21` 且相对运动继续朝远端时，快进到 `axis5+1`；到达近端 `axis5+1` 且继续朝近端时，快退到 `axis5+21`，即完整跨越20 mm窗口。进入、方向切换或回退恢复时的同步只负责重建初始基准。
- 普通导管模式 Follow 阶段轴6仍保持不动；仅普通导管在轴1触发回退时，让 axis6 按 axis1 回退位移反向等位移快进，并把目标夹紧在按当时 axis5 实际位置得到的 `[axis5+1, axis5+21]` 边界内。协同递送/撤出中的 axis1 换手都不联动 axis6。

**坐标方向**：现场 `from-left` 的 `600+ mm` 位于器械装卸/介入起始侧，数值随介入推进而减小，`<100 mm` 才接近介入终点。下面的 `670 mm` 保护位于起始侧，不是介入终点停车条件。

**axis6 上位机内部软限位（670 mm from-left）**：`axis6_abs - axis6_leftlimit` 允许等于 `670 mm`，但任何候选目标大于 `670 mm` 都会被阻断。检查覆盖 axis6 独立/协同 Follow 候选目标、axis6 自身计划动作终点，以及普通导管中 axis1 回退导致的 axis6 联动终点。联动目标会在发布夹爪组合、进入统一 `PlannedReturnCoordinator` 和写 PLC `return_cmd` **之前**完成预测；预测越限时不触发该回退、不切换夹爪，只阻断当前危险动作，下一拍重新评估。仅当 axis6 实际位置已经大于 `670 mm` 时才持续冻结相关链路，启动准备仍可用已经校验的安全目标把轴带回限制内。控制台与 WPF 都会给出警告。该保护只存在于 C++ 上位机，不新增 PLC ADS 符号，也不替代 PLC/NC 硬限位。

### 3.3 axis1 跟随基准与镜像（capture_axis1_follow_baseline / apply_axis1_mirror_from_abs）

每拍在 `Follow` 阶段：
1. `axis1_crawl.handle_ref` / `rot_ref` 保存上一拍手柄线性/旋转滤波值；
2. `axis1_crawl.base_rel` = 当前 axis1 实际 rel；`axis1_crawl.rot_base_rel` = 当前 axis2 hold；
3. 先计算原始线性增量 `(handle_now - handle_prev) × k_handle_to_mm × axis_push_sign`，再按当前模式执行单向门控：递送只保留负轴向增量，撤出只保留正轴向增量；
4. axis1 abs 目标只累加门控后增量；错误方向输入不改变目标，但本拍仍刷新手柄差分基准，因此不会在后续补发；
5. axis3 / axis5 只镜像 axis1 已被窗口、投送停止和单向门控接受的位移差（`apply_axis1_mirror_from_abs`）：`pos[2] = axis3_base_rel + (axis1_abs_cmd - init_pos[0] - axis1_crawl.base_rel)`，axis5 同；
6. 导管模式 Follow 阶段 axis6 保持在 `axis6_mirror_base_rel`，**不**镜像 axis1（注释明确说明这是设计决定）。

**镜像基准的初始化**：`sync_axis1` / `sync_all` 把 axis3/5/6 镜像基准都设为当前实际位置，避免基准陈旧导致突变。

## 4. 导丝模式（`guidewire_mode.cpp`）

### 4.1 模式枚举

```cpp
enum class GuidewireMode { None, Independent, Cooperative };
enum class CooperativeDirection { None, Delivery, Retraction };
```

- `None`：导管模式，物理 SN 587 控制 axis1/2/3/5；axis6/7 保持。
- `Independent`：导丝模式，物理 SN 582 控制 axis6/7；axis1/2/3/5 冻结（用 `independent_axisN_hold_rel` 锁存）。
- `Cooperative`：协同模式，物理 SN 587 控制 axis1 链路（含 axis3/5 镜像），物理 SN 582 控制 axis6/7。`Delivery` 与 `Retraction` 中两条线性链路都相互独立，并由同一套 axis6 相对窗口仲裁；实际方向由独立的 `CooperativeDirection` 决定。

### 4.2 进入门控（`check_axis6_guidewire_entry_gate`）

```cpp
axis6_abs = plc_act_pos[5] + plc_init_pos[5];
axis6_from_left_mm = |axis6_abs - leftlimit[5]|;
gate_passed = axis6_from_left_mm < guidewire_entry_axis6_from_left_max_mm (667.0);
```
该门限只排除起始侧最外端 `>=667 mm` 的进入请求；它不表示接近介入终点，也不会在 `<100 mm` 的终点区域禁用导丝。独立导丝进入成功后仍由 axis5 相对窗口与 `670 mm` 起始侧软限位约束。

### 4.3 进入独立模式（`enter_independent_guidewire_mode`）

1. 读 PLC 当前实际位置；用 axis1/2/3/5 当前值填充 `independent_axisN_hold_rel`（后续主循环会把这些值写到 `pos[0..4]` 来冻结）；
2. 平均 20 个手柄样本重建 axis6 `handle_ref` / `rot_ref`；重置 axis6 滤波器与 prev 基准；
3. 调用 `rebuild_axis6_window_from_axis5`，直接按轴5当前实际位置建立并锁定 `[axis5+1, axis5+21]` 窗口；
4. axis6_crawl 全部字段重置为 Follow 阶段初始态；
5. `enabled = true`；
6. 写一帧 refer，axis1/2/3/5 锁在 hold 值，axis6/7 跟随当前实际。

### 4.4 进入协同模式（`enter_cooperative_guidewire_mode`）

协同方向只由 UI 显式请求：`SetCooperativeDelivery=19` 进入双递送，`SetCooperativeRetraction=23` 进入双撤出。物理 `SN 587` 始终承担导管/axis1 语义，物理 `SN 582` 始终承担导丝/axis6 语义；进入协同后两只手柄的 b0/b6 不再切换方向或模式。axis4 点动和电缸5保持原语义。

两种方向共用入口门控：两只手柄必须在 C++ 进程启动时均成功打开，启动准备完成且控制激活，无暂停/PLC 保持/ADS 回退故障/屈曲恢复/力过渡实验，axis1 与 axis6 均在 `Follow`，并且没有残留 PLC Busy 回退或协同换手拥有者。两者还必须满足 axis6 相对 axis5 位于 `[1,21] mm` 动态窗口内；仅**协同递送**额外要求 `axis6_from_left_mm < 667`，**协同撤出**不使用该门限。

通过后调用 `sync_cooperative_guidewire(ctx, 20, true)`，同时重建两只手柄滤波基准、axis1/axis6 命令基准、旋转保持位和 axis6 窗口。协同递送与协同撤出可一键切换，但切换前必须再次通过门控并完成同一次双手柄重同步；该同步拍不产生 `refer` 位移，操作者重新移动手柄后才按新方向运动。任一门控或同步失败会保留既有安全状态，并由后端快照校正 UI 选中项。

协同 `Follow` 阶段中，导管手柄控制 axis1/2/3/5，导丝手柄控制 axis6/7。两只手柄分别独立执行当前协同方向的单向门控：协同递送各自只接受“推”，协同撤出各自只接受“拉”；一只手柄方向错误只丢弃自己的线性增量，不冻结另一只方向正确的手柄。两种方向中 axis6 都只接受导丝手柄增量，并按 axis5 **实际位置**维护双边 `[axis5+1,axis5+21]` 窗口；axis5 增量只用于判断相对间距正在靠近哪一侧，不再直接加到 axis6 目标。

协同换手采用串行仲裁 `CooperativeReturnOwner`：同一周期两轴都满足触发条件时 axis1 优先。拥有者由 `PlannedReturnCoordinator` 管理期间，另一条链路保持线性与旋转目标、丢弃手柄积压增量，也不会下发第二条 PLC `return_cmd`。拥有者正常完成后使用同一份新鲜 100 Hz 快照和两只手柄当前滤波值执行 `rebase_cooperative_after_return`，再经输出 generation 交接后释放另一条链路；重建失败会停用上位机运动控制并清除协同请求。

协同期间沿用导丝模式的力反馈保护，两个物理手柄的力输出持续为零；退出回普通导管模式后才按既有力反馈开关和标零状态恢复。暂停、PLC 保持、自检重新开始、ADS 回退故障、屈曲恢复请求和力过渡实验启动都会清除协同请求，防止恢复后自动重入。高频力日志 `mode_code`：`0=导管`、`1=独立导丝`、`2=协同递送`、`3=协同撤出`。

### 4.5 退出（`exit_guidewire_mode_to_normal`）

1. 立即把 `*guidewire_mode = None`；
2. 清窗口锁定 / 协同 ff 增量缓存；
3. 读 PLC 当前 axis2/7 实际值刷新 hold（避免陈旧 hold 让 axis2 偶发回零）；
4. 调用 `sync_axis1` 重建 axis1 链路基准（窗口、镜像基准、axis1_handle_filter）。

### 4.6 触发源

- 双手柄：物理 SN 582（导丝/axis6 手柄）的 `B0` 只在 `0->1` 按下沿切换导管/独立导丝模式，`B6` 只在 `0->1` 按下沿切换当前普通模式的递送/撤出方向；`1->0` 松开沿只刷新边沿基线，不改变模式或方向。
- 单手柄：键盘 `1`/`2` 切换导管/导丝角色（`single_handle_requested_mode`）。
- UI：`VisCommand::SetReverseMode` / `RequestModeSwitch` / `SetCooperativeDelivery(19)` / `SetCooperativeRetraction(23)`；普通四个模式按钮会明确退出协同请求。物理按下沿通过 `VisState` 事件计数同步 WPF 单选项，并在模式区显示红色触发提示。
- 协同递送和协同撤出期间忽略物理 `B0/B6`，协同方向仍只由 UI 显式选择。
- 模式方向只约束 `Follow` 阶段的线性手柄增量；axis2/axis7 旋转握把仍可双向转动，统一协调器中的自动计划动作不受该门控限制。

## 5. 启动准备序列（`startup_sequence.cpp` + `main.cpp` 状态机）

### 5.1 阶段枚举

```cpp
enum class StartupPhase {
    WaitForEnter,            // 等待用户选择
    ReleaseClamps,           // 阶段1：打开全部夹爪
    MoveAxis56ToLeftReady,   // 阶段2：1/5/6 走到左限位附近的准备点
    ClampCylinder34Wait,     // 阶段3：闭合导丝侧夹爪对 cyl3/cyl4
    MoveAxis356BackToReady,  // 阶段4：按 UI 最终目标移动 1/3/5/6
    ClampCylinder2AfterAxis3,// 阶段5：在 axis3 到位后闭合 cyl2
    RecoveryMoveAxis1267,    // 恢复阶段1：axis1/2/6/7 同时开始
    RecoveryMoveAxis5,       // 恢复阶段2：2秒后加入 axis5
    RecoveryMoveAxis3,       // 恢复阶段3：再2秒后加入 axis3
    Done                     // 完成
};
```

### 5.2 入口（`start_startup_sequence`）

1. 后端先校验 axis2/axis7 UI 目标均为 `[-360,360] deg` 内的有限数值；键盘和 WPF 两条入口最终都经过该检查；
2. 重新读取 PLC 当前实际位置，使用本次读数刷新 axis2/axis7 的共享 hold，并锁存 axis1/3/5/6 的直线保持基准，彻底断开上一运行周期缓存；
3. 读取 `G.startup_loading_ready`，并独立核对 axis1/3/5/6 距左限位是否分别处于 `[96,280,430,580] ±2 mm`。两项均成立时走标准装卸启动；否则走中断恢复启动。旧 PLC 没有该符号时仅按实际位置兼容判定；
4. 如果 `v_limit_scaled == false`：读当前 `v_limit` 并备份；轴 1/3/5/6 统一取四轴基础上限中的最小值作为共同基准，再乘 `startup_motion_speed_scale` 后写回 PLC，确保四轴限速数值一致且不会抬高任一轴原上限；轴 2/7 仍按各自基础上限乘比例。UI 默认比例为 `0.03`，未经过 UI 提交时配置结构的回退初值为 `0.005`；
5. 开始控制前写 `G.startup_loading_ready=FALSE` 消费资格位，并先写 `G.startup_smoothing_bypass=TRUE`，让 PLC 放弃上一进程的轨迹历史；
6. 标准启动首帧把 axis2/axis7 指向各自 UI 角度目标，直线轴保持入口位置；恢复启动首帧同时把 axis1、axis6 指向各自 UI 毫米目标，并把 axis2、axis7 指向各自 UI 角度目标。首帧写入成功后才进入对应状态，失败则不进入启动状态并尝试恢复原速度上限。

### 5.3 各阶段动作（`main.cpp` 主循环步骤 11 内 startup_sequence 分支）

**标准装卸启动**（PLC 资格位和实际装卸姿态均有效）：

| 阶段 | 气缸指令 | 轴目标 | 完成条件 |
|---|---|---|---|
| `ReleaseClamps` | 全部开（cyl1/2 open + cyl3=500,cyl4=0） | 直线轴维持当前 hold；axis2/7 已转向 UI 目标 | 经过 `startup_clamp_settle_delay_ms(300ms)` |
| `MoveAxis56ToLeftReady` | 同上 | axis1->startup_axis1_ready_from_left_mm(20mm)；axis5->startup_axis5_ready_from_left_mm(290mm)；axis6-> axis5+axis56_ready_gap_mm(305mm，间距15mm)；axis2/7 继续保持 UI 目标 | 1/5/6 三轴都到容差内；锁存 axis1 阶段2值 |
| `ClampCylinder34Wait` | cyl3=50,cyl4=500（夹紧） | axis5/6 保持准备点；axis2/7 继续保持 UI 目标 | 经过 300ms |
| `MoveAxis356BackToReady` | 同阶段3 | 1/3/5/6 按 `startup.final_axisN_from_left_mm`（UI 参数）移动；axis2/7 继续保持已从阶段1执行的 UI 目标 | 六轴全部到容差内（含 axis2/7 角度容差 0.2 deg） |
| `ClampCylinder2AfterAxis3` | cyl2=600（夹） | 同阶段4 | 经过 300ms 且全部到位 |
| `Done` | 恢复正常导管模式气缸 | `restore_startup_v_limit` 恢复速度上限 -> `sync_all(30)` 重同步 -> `control_active=true` | — |

**中断恢复启动**（PLC 未重启但机构已离开装卸位，或任一入口条件不满足）：

| 阶段 | 气缸指令 | 轴目标 | 完成条件 |
|---|---|---|---|
| `RecoveryMoveAxis1267` | 全程固定 `cyl1=open,cyl2=clamp,cyl3=open,cyl4=clamp` | axis1、axis2、axis6、axis7 同时开始，分别走向 UI 中各自的最终目标；axis3/5 保持入口实际位置 | 经过 2 s，不要求第一组先到位 |
| `RecoveryMoveAxis5` | 同上 | 第一组继续保持 UI 目标；axis5 开始走向自己的 UI 最终目标；axis3 继续保持入口实际位置 | 再经过 2 s |
| `RecoveryMoveAxis3` | 同上 | axis1/2/5/6/7 继续保持各自 UI 目标；axis3 开始走向自己的 UI 最终目标 | axis1/2/3/5/6/7 全部进入各自到位容差 |
| `Done` | 同上，随后由正常控制接管 | 恢复原 `v_limit` -> `sync_all(30)` -> `control_active=true` | — |

恢复路径中的“同时”指同一控制拍开始，不表示共用同一个目标数值。axis1/3/5/6 使用毫米目标，axis2/7 使用角度目标，禁止跨轴复用 axis1 的毫米值。

### 5.4 速度限制恢复（`restore_startup_v_limit`）

如果 `v_limit_scaled == true`，把备份的原速度上限写回 PLC，标志位置 false。
**重要**：标准或恢复路径全部到位后统一调用；入口失败时也会尽力恢复，避免启动期速度被永久压制。

### 5.5 触发路径

- 键盘 `S`：调用 `start_startup_sequence`（需 `startup.completed==false && phase==WaitForEnter`）。
- UI `ExecuteStartup`：参数校验（直线轴位置范围、相对关系、axis2/7 的 `[-360,360] deg` 范围、速度范围）通过后，把 `pending_startup` 写到 `startup.final_*`，再调用 `start_startup_sequence`。
- 键盘 `C` / UI `SelectDirectControl`：跳过启动准备，先消费 `G.startup_loading_ready`，再执行 `restore_startup_v_limit` + `sync_all(20)` -> `Done`。**直接控制模式**适合已经手动装夹到位的场景。

### 5.6 启动期平滑旁路

启动首帧 `refer` 写入前先同步写 `G.startup_smoothing_bypass = true`；之后在 `startup.is_active()` 时每拍维持 TRUE，告诉 PLC 当前处于启动期并断开上一进程的二阶轨迹缓存，改走传统速度限制/滑动平均路径。退出后写 FALSE。

### 5.7 手动屈曲恢复（机构间距恢复）

该模式仅由 WPF 的“屈曲恢复”开关显式启停，不做位置判断或自动触发。进入条件为：启动完成、控制激活、普通导管递送、axis1/axis6 均处于 Follow、无计划回退、无急停/暂停/ADS 故障、无力过渡实验。

- 进入时按实际位置锁存 axis1/2/7，axis3/5/6 以各自实际位置作为共同移动起点；
- 电缸1保持打开、电缸2保持夹紧、电缸3写 `cyl3_open`、电缸4写 `100`，等待 `spacing_recovery_clamp_settle_ms(150ms)` 后允许运动；
- 导管语义手柄（物理 SN 587）没有中位，继续使用既有的相邻采样位移差分；仅接受使 from-left 增大的手柄增量，反方向增量丢弃；
- axis3/5/6 每拍叠加完全相同的位移，命令侧速度限制为 `40mm/s`，停止推拉手柄后不继续追赶积压目标；
- 共同可用行程取 axis3/5/6 到各自安全上限（650/670/670mm from-left）的最小值，并要求 axis6-axis5 仍处于 `[1,21]mm` 窗口；
- 恢复期间仍屏蔽轴4点动、电缸手动覆盖和导管力反馈；普通/协同模式按钮保持可点击，点击后进入 `ExitSync`，完成稳定等待与 `sync_all(20)` 后自动应用最后一次目标模式请求；
- 退出时先保持最终目标，等待 axis3/5/6 进入 `0.2mm` 容差并稳定至少 `100ms`（最长等待 `2s`），再调用 `sync_all(20)` 按当前实际位置重建跟随基准；axis3 已离开投送停止区时同时解除投送停止锁存。

## 6. 六模式统一计划回退协调器（`PlannedReturnCoordinator`）

### 6.1 阶段

`axis1_crawl` / `axis6_crawl` 只保存各自 Follow 基准、命令位置和窗口；WPF 兼容阶段值由 `PlannedReturnCoordinator::compatibility_phase_for_axis()` 映射生成。触发后的公共生命周期只由一份 `PlannedReturnCoordinator` 管理：

```cpp
enum class PlannedReturnPhase : unsigned char {
    Idle,
    ClampSettle,          // 等夹爪输出确认应用后稳定 50 ms
    SubmitRequest,
    AwaitAccepted,        // 等待本次请求的 Busy=TRUE 或 Done=FALSE ACK
    AwaitDone,            // 等待 ACK 之后的新 Done=TRUE
    RetryClear,           // 仅 PLC 尚未启动时允许的一次安全清理/重试
    CancelWait,           // 清Req后等待PLC停稳、新鲜快照重建和实际位置保持输出确认
    AwaitFreshSnapshot,
    PublishHandoff,
    AwaitHandoffApplied,
    OptionalLead          // 仅普通导管递送可进入
};
```

六种 UI 模式映射为八个内部执行策略：导管递送/撤出、独立导丝递送/撤出，以及协同递送/撤出的 axis1 或 axis6 所有权。协调器任一时刻只管理一组动作；普通导管 axis1 可包含 axis1+axis6 两条联动腿，协同模式由 `cooperative_return_owner` 保证 axis1/axis6 串行，同拍同时触发时 axis1 优先。

力过渡实验与统一计划回退双向互斥：`begin_planned_return()` 在 `ft_exp.active()` 时拒绝创建任务；“开始力过渡实验”命令在 `planned_return.active()`（包含 `CancelWait` 和 `OptionalLead`）时同样拒绝。两者都会接管 axis1 的 `refer` / 快退旁路，因此互斥由同一主线程在入口处明确判定，不依赖本拍末尾谁最后覆盖输出。

| UI 模式 | 触发边与目标 | 重建范围 | 回退后动作 |
|---|---|---|---|
| 导管递送 | axis1 `3 -> 23 mm`；普通导管可联动 axis6 | Axis1 | 默认 axis1 自动先行 `1 mm` |
| 导管撤出 | axis1 `23 -> 3 mm`；普通导管可联动 axis6 | Axis1 | 直接恢复 Follow |
| 导丝递送 | axis6 相对窗口 `1 -> 21 mm` | Axis6 | 直接恢复 Follow |
| 导丝撤出 | axis6 相对窗口 `21 -> 1 mm` | Axis6 | 直接恢复 Follow |
| 协同递送 | axis1 `3 -> 23 mm`；axis6 双边目标为相对 axis5 的 `1/21 mm` | Cooperative | 直接恢复 Follow |
| 协同撤出 | axis1 `23 -> 3 mm`；axis6 双边目标为相对 axis5 的 `1/21 mm` | Cooperative | 直接恢复 Follow |

### 6.2 Follow 阶段

1. 计算 axis1 线性增量：`(handle_filtered - prev_handle_filtered) × k_handle_to_mm(750) × axis_push_sign(-1)`；
2. 死区过滤：`|increment| < linear_increment_noise_deadband_mm(0.02)` 时置 0；
3. 单向门控：普通导管递送只保留负轴向增量（“推”），普通导管撤出只保留正轴向增量（“拉”）；错误方向置 0；
4. `axis1_cmd_abs = clamp(axis1_follow_cmd_abs + directional_increment, window_left, window_right)`；
5. 触发保护：
   - `axis1_push_rearm_after_hold`：PLC 保持刚解除，必须反向拉一下才能继续推送（防误推）；
   - `axis1_delivery_stop_latched`：axis3 到达投送停止位（距左限位 ≤ 20mm）后，正向推送被锁；必须切换反向模式才能继续；
   - `axis1_reverse_switch_guard_active`：刚切换正反向时若距离触发边太近，临时锁触发（防抖）；
6. 触发快退条件（`axis1_ready_to_trigger`）：
   - 有有效增量；
   - 增量方向朝向触发边（正向时朝右、反向时朝左）；
   - 跟随未禁用；
   - 本拍跨入触发边，或实际位置已经到达/略微越过触发边且收到新的有效同向输入；
   - 不被反向切换保护阻塞；
7. 触发动作：
   - 设置 target_abs（反向 -> window_left；正向 -> window_right）；
   - 把本次执行轴、目标、重建范围、完成后动作及需要保持的其他轴位置一次性写入 `PlannedReturnCoordinator`；`CrawlState` 本身只保留 Follow 基准和窗口，不再持有独立回退阶段或固定等待计时；
   - 仅普通导管按“axis6 当前绝对位置减去 axis1 本次回退位移”计算 axis6 反向等位移联动目标；再把目标限制在按当时 axis5 实际位置得到的 `[axis5+1, axis5+21]` 窗口内，并检查 `670 mm from-left` 上位机软限位；两种协同方向的 axis1 换手都保持 axis6 不动；
   - 只有预测安全时才由统一协调器发布完整夹爪组合并进入 `ClampSettle`（见 §8）；预测越限则不发任何 axis1/axis6 PLC 回退请求，相关导管/导丝链路锁止在实际位置。

### 6.3 ClampSettle 阶段（切缸 + 夹爪预紧）

- axis1/axis6 的两侧电缸目标由协调器在同一份输出快照中发布，并记录该次 `publish_output()` 的 generation；只有通信线程报告 `applied_output_generation >= clamp_output_generation` 后，才确认夹爪命令已经成功写入 PLC，并从这个时刻开始计算 `pre_move_cylinder_wait_ms=50ms`；
- 普通导管 axis6 联动时取两条执行腿等待时间的较大值，当前 axis1/axis6 均为 50ms。未确认夹爪输出写入前不启动计时，也不提交任何计划动作参数；
- `ClampSettle` 只切换夹爪并保持各轴，不提前置快退旁路；`Prepare` 成功后才发布包含 axis1/axis6 快退旁路的保护输出；
- 镜像轴 3/5 及非执行轴使用触发时锁存的实际位置保持。

### 6.4 请求确认与 PLC 计划回退

- 夹爪输出确认并稳定 50ms 后，主线程以 `AdsPlannedReturnOperation::Prepare` 提交本次全部执行腿；通信线程在**同一次 Sum Write** 中写入 `Req=FALSE + TargetAbs/Velocity/Acc/Dec/Jerk`，清除旧完成状态并准备完整参数；
- 后续事务确认各执行腿均处于 `Busy=FALSE、Done=FALSE、Error=FALSE` 后，先发布并确认一代包含快退旁路、冻结参考和夹爪状态的保护输出；只有 `applied_output_generation >= commit_guard_generation`，主线程才提交 `Commit`。通信线程随后在一次 Sum Write 中把全部执行腿的 `Req` 同时置为 `TRUE`，并继续携带已经确认的保护输出，避免通信线程把 Commit 与旧输出配对；
- `Prepare/Commit/Clear` 不在主控制线程直接调用 ADS，而是复制进单生产者/单消费者固定容量队列：命令环为 32 槽，结果环为 128 槽，提交只返回单调序号，队列满或参数非法返回 0。通信线程在每个 100 Hz 周期至多选择一条命令，并把它的字段合并进该周期唯一一次输出 Sum Write；因此高频周期仍保持一次 Sum Read + 一次 Sum Write，没有额外 ADS 写请求，也没有主控制拍动态分配；
- Sum Write 逐项检查结果：常规 refer/快退/夹爪、正常完成清 Req 掩码及主机心跳属于核心项，任一失败都不推进 output generation 并进入通信软保持；只有固定队列中的计划字段单独失败时，核心通信拍仍可有效，而该命令序号返回 Failure。Commit 失败会同时返回逐腿 Req 子项成功掩码；事务响应不完整、结果不可判定或 Commit 等待超时时保守视为全部任务腿可能已启动；
- `Clear` 提交时立即更新 axis1/axis6 各自的序号屏障。消费者尚未开始处理、且序号早于该轴最新 Clear 的 `Prepare/Commit` 会直接标记失败并出队，不再发出 ADS 写；Clear 自身仍按 FIFO 到达 PLC。屏障只淘汰尚未开始的旧命令，已经写入 PLC 的运动必须继续依靠 Req 下降沿和 PLC 状态 40 受控停止；
- 计划动作期间相应 `refer` 保持为本次目标或保持位置，实际电机运动由 PLC `MC_MoveAbsolute` 完成；
- axis1/axis6 当前请求上限均为 `400mm/s`、`4800mm/s²` 加速度、`4800mm/s²` 减速度和 `70000mm/s³` jerk，分别为原 `200/2400/2400/35000` 的两倍；短窗口回退通常没有足够距离达到 `400mm/s`，实际峰值还受 NC/驱动限制；
- axis1 和 axis6 的 `Busy/Done/Error/ErrorId` 均由 ADS OnChange Notification 更新，不再为计划回退完成状态执行周期轮询；
- 每条执行腿先记录提交前事件序号。只有本次请求之后的新 `Busy=TRUE` 或 `Done=FALSE` 才算 PLC ACK；完成还必须收到 ACK 之后的新 `Done=TRUE`，且当前为 `Done=TRUE、Busy=FALSE`。旧 `Done/Error`、单独的 `ErrorId` 更新或另一轴事件都不能推进当前腿；
- 协调器只在“尚未观察到任一执行腿启动，且失败 Commit 没有任何可能成功/未知的 Req 子项”时允许一次安全重试：清全部本次 Req，等待一份新鲜快照并确认各腿 `Busy=FALSE、Error=FALSE`，重新校验窗口和软限位后进行第二次、也是最后一次下发。任一腿已 ACK/启动、被逐项结果标记为可能启动、重试已用尽、清理失败或状态复位超时，都直接进入故障保持，绝不重复可能正在运动的命令；
- 任一执行腿的新 `Error=TRUE`、从首条腿 ACK 起超过 `planned_return_execution_timeout_ms=5000ms` 仍未全部完成，或完成交接 Sum Write 失败，都会保持当前位置、清力输出并进入现有故障保持；已经启动的动作绝不因 5 秒超时自动重发。最近的非零 `ErrorId` 由对应轴回调锁存，不在故障边沿执行阻塞式手柄采样。

### 6.5 新鲜快照与非阻塞交接

- 全部执行腿完成后先记录当前 100 Hz 快照序号；协调器必须等到下一份有效新鲜快照，不能用 Done 之前的旧位置完成交接；
- Axis1、Axis6、Cooperative 三种重建范围分别调用非阻塞 `rebase_axis1_after_return`、`rebase_axis6_after_return`、`rebase_cooperative_after_return`。三者都消费同一份当前 PLC 快照和主循环已有滤波手柄值，不重新 `poll()`、不 `Sleep()`、不直接进行低频 ADS 读写；
- 重建后发布“按当前实际位置保持 + 清快退旁路 + 恢复夹持”的统一输出；该 `AdsOutputCommand` 在 `PublishHandoff/AwaitHandoffApplied` 期间持续携带本任务各腿的 `Req=FALSE` 掩码。通信线程把这些字段放进同一次 Sum Write，只有该 generation 成功才同时确认清 Req 和交接输出。若暂停或故障恰好发生在 Sum Write 已成功、主循环尚未推进阶段的窄窗口，取消链直接认可已应用的 `handoff_generation`，不会再等待重复清 Req 才可能产生的 Notification。这里是单一 ADS 事务，不宣称 PLC 扫描级 shadow/commit 原子协议；完成侧不再附加固定夹爪等待，也不再保留分轴完成链或阻塞式 `sync_*(3)`；
- 非普通导管递送模式在输出代次确认后直接回到 Follow。手柄在整个自动动作期间持续刷新差分基准，期间移动不会在恢复后补发。
- 暂停、急停、ADS 故障、模式切换或计划动作故障触发取消时，协调器进入 `CancelWait` 而不是立刻 reset。若 PLC 请求可能已生效，先异步提交本任务执行腿的 `Clear`；清写失败按 250ms 间隔继续重试。Clear 成功后仍需等待对应腿 `Busy=FALSE、Error=FALSE`，对取消时已启动/Busy 的腿还必须观察到基线之后的新 Notification，并取得 Clear 之后的新鲜有效快照；
- `CancelWait` 使用该快照和当前滤波手柄值执行相应范围的非阻塞 rebase，然后单独发布“全部相关轴保持当前实际位置 + 两个快退标志为 FALSE”的输出。即使常规 `motion_enabled` 已因暂停或回退故障关闭，这一拍保持命令仍可通过取消专用门控发送；只有 `applied_motion_output_generation >= cancel_hold_generation` 后才 reset 协调器。专用 motion generation 仅在本次成功 Sum Write 确实包含 `refer` 时推进，不能被急停/无效 ADS 拍发布的更高 `motion_enabled=false` 代次误确认。超过 5 秒仍未完成取消闭环时锁止上位机控制、清力输出并要求人工重新启动，但仍保留 `CancelWait` 和清理/停稳等待，不能在本地伪装为 Follow。

### 6.6 普通导管递送的 axis1 回退后单独先行

该功能只作用于普通导管**正向递送**（非独立导丝、非协同、非撤出）的 axis1 计划回退成功完成后。WPF 的“回退完成后轴1自动先行量”输入通过 `SetAxis1PostReturnLead=24` 写入，单位为 mm，范围 `[0,10]`，默认 `1.0 mm`；正值统一表示递送方向（axis1 绝对坐标减小），`0` 表示关闭，UI 拒绝负值。

协调器完成 §6.5 的新鲜快照重建和输出 generation 确认后，只有 `PlannedReturnPostAction::Axis1DeliveryLead` 才进入 `OptionalLead`。目标取“当前实际位置减去配置量”并限制在当前窗口内；全过程不等待下一次手柄前推，也不使用先行前 `40 ms` 固定计时。先行到位要求连续两份新鲜 100 Hz 快照同时满足位置误差 `<=0.01 mm` 和实际速度 `<=0.1 mm/s`，不再使用到位后 `30 ms` 固定计时。先行期间 axis3/5/6 与 axis2/7 保持当前实际位置，手柄增量继续逐拍丢弃，完成后再按当前快照执行一次 axis1 非阻塞重建并恢复 Follow。

`OptionalLead` 从先行目标开始发布时单独计时；5 秒内未满足连续两份到位条件即按计划回退故障处理：停止上位机运动控制、清力输出并进入实际位置保持取消闭环，不把先行超时当作成功 Follow，也不会重放先行目标。

先行走普通外部设定值平滑链，PLC 内部上限为 `traj_vmax[1]=80mm/s`、`traj_amax[1]=2000mm/s²`；计划回退则由 `MC_MoveAbsolute` 使用上述 `400/4800/4800/70000` 参数并绕过普通平滑链。因此回退的速度能力明显高于先行，先行的短距离阶跃只是起步较干脆，并不等于达到回退速度。

该先行不绕过原有 axis3 投送停止位；若已经到达投送停止位、配置量为零或窗口内无可用行程，本次自动先行会被跳过。暂停、PLC hold、ADS 回退故障、屈曲恢复、力过渡实验、启动准备、模式/方向切换和 axis6 软件限位锁止都会取消尚未完成的先行。取消时统一进入 `CancelWait`：若仍可能存在 PLC 回退请求，则精确异步清本任务执行腿；`OptionalLead` 本身没有活动的 PLC 回退 Req，可直接等待新鲜快照重建和已写入 `refer` 的 motion output generation。若 PLC 动作已经进入状态 10/20/30/31，Req 下降沿还会由 PLC 状态 40 执行 `MC_Stop`，停稳并按实际位置重建后才重新使能外部设定值；主机进入 CancelWait 不代表机械轴已经瞬时停下。短时 ADS 软保持恢复也不会续跑旧交接或自动先行，只恢复稳定模式。回退前两侧电缸目标仍按 §6.3 保留 `50 ms` 稳定等待，该安全等待不属于先行阶段，未被取消。

## 7. axis6 Follow 触发与统一计划动作（`main.cpp` 步骤 11 内 `run_axis6_crawl_state` lambda，独立/协同模式共用）

axis6 的 Follow 触发仍由 `run_axis6_crawl_state` 封装，独立模式和协同模式共用；一旦触发，夹爪稳定、PLC ACK/Done、安全重试和完成交接均转交同一 `PlannedReturnCoordinator`，不再维护 axis6 独立完成状态机。

### 7.1 独立模式

- axis1/2/3/5 全部冻结在 `independent_axisN_hold_rel`；
- axis6 线性增量直接来自物理 SN 582 手柄，并按模式独立执行单向门控：正向导丝只接受“推”，反向导丝只接受“拉”；
- `require_user_increment_for_trigger = false` 表示无需额外的协同本人输入判据，但触发仍要求门控后增量有效且朝向当前触发边；
- 夹爪组合使用 cyl3/cyl4（而不是 cyl1/cyl2），发布和 50ms 稳定计时遵循与 axis1 相同的输出 generation 规则。

### 7.2 协同模式

- `CooperativeDirection::Delivery` 固定为双递送，`CooperativeDirection::Retraction` 固定为双撤出；两种方向均忽略手柄模式/方向按键；
- axis1 和 axis6 两只线性手柄分别独立做当前协同方向的门控，错误方向只冻结自身输入；
- 两只手柄在协同 Follow 中均持续接收。两种协同方向下，SN 587 的导管增量只进入 axis1/3/5，SN 582 的导丝增量只进入 axis6；axis6 不再无条件叠加 axis5/axis1 增量。
- 两种协同方向每拍都计算相对增量 `axis6_increment - axis5_increment`：正值表示间距朝远端增大，负值表示朝近端减小；两只手柄同时运动时仍分别保留各自命令。
- axis1 使用固定 `[3,18] mm` 窗口；触发后仅 axis1 换手回退，axis6 夹住导丝保持绝对位置。axis1/axis6 同周期同时触发时仍由 axis1 优先。
- axis6 使用随 axis5 实际位置移动的 `[axis5+1,axis5+21]` 双边窗口。远端触发时冻结 axis1/3/5，切换 cyl3/4 后由 axis6 快进到 `axis5+6`；近端触发时同样冻结导管链路，由 axis6 快退到 `axis5+16`。

### 7.3 单向门控的边界

单向门控只处理人手在 `Follow` 阶段产生的线性增量。无论输入被接受还是拒绝，循环末尾都会刷新两只手柄的上一滤波采样，所以持续做一段错误方向动作后改回正确方向时，不会补发之前被拒绝的位移，也不会先走到窗口另一侧。axis2/axis7 的旋转握把保持双向；触发后的自动目标由统一协调器执行。PLC 保持解除后，正向模式下的回拉仍可解除“请先回拉再接管”锁定，但该回拉只改变锁定状态，不形成线性 refer。仅普通导管递送可在回退交接后自动先行；PI 补偿仍只由门控后的有效正向输入触发。统一 `motion.csv` 记录两只手柄的原始值和滤波值，不再保存旧实验表中的名义命令、最终命令或 PI 中间量。

### 7.4 axis6 触发后的统一阶段

计划动作请求仍使用 `AdsSymbol::axis6_return`，切缸仍使用 cyl3/cyl4；独立导丝移动到锁定窗口对侧，协同递送和协同撤出根据触发侧选择 `axis5+6` 或 `axis5+16`。这些目标策略保持不变，但触发后统一进入 `ClampSettle -> SubmitRequest -> AwaitAccepted -> AwaitDone -> AwaitFreshSnapshot -> PublishHandoff -> AwaitHandoffApplied`，并按 Axis6 或 Cooperative 范围非阻塞重建。

### 7.5 主从位移计算与受限 PI 补偿

该模块仅覆盖普通导管**正向**递送的 axis1，以及独立导丝**正向**递送的 axis6；不接入协同递送、撤出或 PLC 运动逻辑。控制器随主程序运行，不持有磁盘会话或日志门控。导管侧只有在 `cylinder2_cmd == cyl2_clamp` 且 `cylinder1_cmd == cyl1_open` 连续 150 ms 时，导丝侧只有在 `cylinder4_cmd == cyl4_clamp` 且 `cylinder3_cmd == cyl3_open` 连续 150 ms 时，才建立对应 Follow 计算段。这里是命令级“已夹持”假设，不是物理到位反馈。

每段从当前手柄、实际轴位置和 refer 重建锚点；内部累计跨段保留，而段累计不会把夹爪切换、计划回退或手柄积压位移算作器械前进。这些量只服务控制计算，不自动创建任何 CSV。

`tracking_error_mm` 的语义是**尚未补偿的换手前向欠账**，不是普通 Follow 段中“标称手柄累计量减实际轴累计量”的差。正向递送进入 `PlannedReturnCoordinator` 自动换手或夹爪交接期后，医生仍继续前推产生的映射位移会累计为欠账；为恢复行程而回拉手柄时不产生负欠账，也不会抵消已有欠账。欠账默认和硬上限均为 `20 mm`（WPF 可下调但不能超过该上限）；超过上限的原始前推量仍写 CSV，但不再进入待补队列。

补偿默认关闭，axis1/axis6 默认均为 `Kp=0.5`、`Ki=2`、最大增益 `2`、欠账上界 `20mm`。WPF/C++ 的 `Kp` 范围为 `[0,1]`，`Ki` 范围为 `[0,100]`，最大增益范围为 `(1,5]`。换手期间冻结 PI，但保留欠账；恢复有效 `Follow` 段后，只要医生仍有新的正向输入，就将**当前已接受的标称增量**按受限 PI 增益有限放大，跨后续多个正向输入逐步偿还欠账。实际轴位移先结算普通标称命令，只有经确认的额外前进才扣减欠账，避免通信/伺服滞后造成重复补偿。松手、静止或回拉时不追赶，绝不自动反向。输出仍必须经过原窗口、投送停止、速度限制、PLC 平滑和计划回退链路；窗口/停止条件夹紧输出时冻结积分。PI 是否可开启只由这些控制条件和参数决定，与统一实验记录状态无关。

暂停、PLC hold、ADS 回退故障、屈曲恢复、力过渡实验、手动电缸覆盖、启动准备、撤出和模式切换会自动关闭补偿并清除欠账，且不自动恢复。参数只能在补偿关闭时通过 WPF 提交；内部仍有最大增益、欠账上限、积分量和单拍额外位移上限，不能靠 UI 突破。开启 PI 不创建文件，停止统一记录也不关闭 PI。

## 8. 夹爪组合应用确认与稳定等待

六种模式不再各自维护切缸阶段或分步计时。触发被接受后，统一协调器按本次动作一次性生成完整夹爪组合：axis1 链路使用 cyl1/cyl2，axis6 链路使用 cyl3/cyl4，普通导管联动时两组同时包含在同一输出快照中。时序固定为：

```text
发布完整夹爪组合并取得 output generation
-> 等待通信线程确认该 generation 已完成 Sum Write
-> 从确认时刻起稳定 50 ms
-> prepare：全部执行腿 Req=FALSE + 完整运动参数
-> commit：全部执行腿 Req=TRUE
-> Notification 确认本次 ACK 与 Done
```

- 配置中只保留 `axis1_pre_move_cylinder_wait_ms=50ms` 和 `axis6_pre_move_cylinder_wait_ms=50ms`；联动动作取较大值；
- 50ms 是夹爪命令**成功写入 PLC 后**的机械稳定时间，不能从主循环首次构造命令时提前起算；
- 正常完成后，协调器直接发布恢复夹持、清快退标志和按实际位置保持的统一交接输出，并以 generation 确认写入，不再增加固定完成等待；
- 如果夹爪输出一直未被通信线程确认，动作保持在 `ClampSettle`，不会提前触发 PLC 计划运动。

### 8.1 手动电缸覆盖与自动接管

WPF 电缸 1~4 按钮用于调试时，会临时建立“手动开/关覆盖”，因此其命令会在主循环末尾覆盖同拍的自动命令。为避免该调试状态遗留到正式流程，选择普通递送/撤出模式、开始启动准备或直接控制、成功进入独立导丝/协同模式，以及 axis1/axis6 的触发被统一协调器接管时，程序都会自动清除四个电缸的手动覆盖。自动换手、启动准备和 axis6 软件限位锁止期间，新的手动覆盖请求会被拒绝；axis6 锁止期间也不会再把旧覆盖施加到稳定夹持组合上。

## 9. 已知问题 / 待确认点

### 9.1 axis6 右侧窗口余量

窗口右边界固定为 `axis5_from_left + 21mm`，当前上位机没有读取 PLC 内部 `right_slimit` 做二次裁剪。按启动默认 axis5=649mm，窗口为 `[650,670]mm`，右端同时受上位机 `670 mm from-left` 软限位约束。若后续提高 axis5 位置，必须同步核对窗口和软限位余量。

### 9.2 活动计划动作的取消不是简单清标志

上位机取消尚在执行的计划动作时会把对应 `Req` 拉低。若 PLC 正处于禁用外部设定值、绝对运动或收尾阶段（`return_state=10/20/30/31`），PLC 会转入状态 40，保持 `Busy=TRUE、Done=FALSE`，并通过 `MC_Stop` 受控停止；只有真实 `MC_Stop.Done` 才进入状态 30/31，按实际位置重建 `refer` 与平滑链，最后恢复外部设定值。若 `MC_Stop.Error`，PLC 将首次停止错误锁存到 `G.return_cmd[i].Error/ErrorId`（已有原运动错误时保留原错误），同时把 `Execute` 拉低一拍后继续尝试受控停止；持续报错时保持 Busy 和 Error 可见，不静默重试，也不伪造 Done。无错误的主动取消最终同样保持 `Done=FALSE`。

上位机侧会保留 `CancelWait`、任务腿和 Notification 基线，等待 Clear、PLC 停稳、新鲜快照重建及已写入 `refer` 的 motion output generation 全部确认后才回到 Follow。因而“Req 已清除”“主机已重建基准”和“机械轴已安全交还”是三个不同阶段，任何一个都不能替代后两个。

### 9.3 `cooperative_mode` 与 axis1 快退耦合

仅普通导管模式会把 axis6 作为 axis1 回退的反向等位移执行腿加入同一次协调动作。协同递送和协同撤出的 axis1 换手都只运动 axis1；两种协同方向的 axis6 快进/快退只由其相对 axis5 的双边窗口触发。修改该逻辑前必须同时核对两对电缸时序、axis1 优先仲裁和 axis6 相对窗口。

### 9.4 `reverse_switch_trigger_guard_mm` 是软保护

正反向切换瞬间，若 axis 实际位置距离新的触发边太近（≤ 2.0mm），会拉起 `reverse_switch_guard_active`，阻止该次切换立即触发快退。需要 axis 离开 2mm 后才允许触发。这是为了防止"在窗口边缘反复横跳导致连续触发"。

### 9.5 启动最终默认姿态与中间夹持间距相互独立

WPF 与 C++ 的启动最终默认值统一为 axis1/3/5/6=`20/649/649/650 mm`。axis3 与 axis5 的 from-left 相对差由原默认 `10 mm` 缩为 `0 mm`，axis6 与 axis5 的相对差由 `6 mm` 缩为 `1 mm`；正常 Follow 中 axis3/5 接收同一个 axis1 有效增量，因此该相对差会保持。选择 `649/649/650` 而不是 `650/650/651`，是为了让完整运行窗口 `[axis5+1,axis5+21]` 的右端正好为 `670 mm`，不在第一轮换手时触发软件上限。

标准装卸启动的中间夹持位置仍为 axis5=`290 mm`，但 `axis56_ready_gap_mm` 由 `20 mm` 缩为 `15 mm`，因此中间 axis6 目标为 `305 mm`。该中间间距不等于最终姿态的 `1 mm` 相对差。UI 仍可分别修改 axis3/5/6；若 axis6 小于 axis5 或 axis5 小于 axis3，后端会拒绝参数。
