# 可视化界面与本地通信架构说明

更新时间：2026-08-04
适用工程：`ADS.vcxproj` + `AdsControlUI/AdsControlUI.csproj`

本文只描述当前仓库中的 C++ 控制进程和 WPF 界面。项目没有 `ErcpApp`、VTK、C++/CLI 桥接或 3D 渲染依赖。

## 1. 进程边界

```text
ADS.exe（C++ x64）
  |-- 控制主循环
  |-- VisServer 命名管道线程
  |-- ExperimentRecorder / Action4CameraRecorder
  |
  |  \\.\pipe\ADS_Control_Vis
  |     C++ -> C#: VisState，883 字节
  |     C# -> C++: 版本化命令头 + 可选 UTF-8 负载
  v
AdsControlUI.exe（WPF .NET Framework 4.7.2 x64）
  |-- MainWindow
  |-- ForceRealtimeWindow
  |-- CleanForceWindow
  |-- CameraPreviewWindow
  `-- ForceTransitionWindow
```

WPF 只负责显示和发送意图，不直接访问 PLC、手柄、力 DAQ、CSV 或 MP4。控制、安全门控、文件创建和相机独占均在 C++ 进程内。

## 2. 关键文件

| 文件 | 职责 |
|---|---|
| `vis_server.h/.cpp` | C++ 管道服务、协议结构、状态快照和命令队列 |
| `AdsControlUI/VisProtocol.cs` | C# 端 `VisState` 和命令枚举镜像 |
| `AdsControlUI/VisPipeClient.cs` | 连接、断线重连、二进制反序列化和版本化命令发送 |
| `AdsControlUI/AdsControlViewModel.cs` | 状态文本、按钮使能和命令方法 |
| `AdsControlUI/ArmAxisControlModel.cs` | 定位臂五轴行状态、参数编辑与错误文本 |
| `AdsControlUI/MainWindow.xaml(.cs)` | 主操作面板及弹窗生命周期 |
| `AdsControlUI/CameraPreviewWindow.xaml(.cs)` | Action 4 参数、实时画面、缩放和平移 |
| `AdsControlUI/CleanForceWindow.xaml(.cs)` | 原始电压和独立双 Y 轴纯净力曲线 |
| `AdsControlUI/ForceRealtimeWindow.xaml(.cs)` | 实际下发值与反馈目标值曲线 |

## 3. 状态协议

### 3.1 C++ 到 WPF

`VisState` 使用 `#pragma pack(push, 1)`；C# 使用 `[StructLayout(LayoutKind.Sequential, Pack = 1)]`。当前线长固定为 **883 字节**：

- C++：`static_assert(sizeof(VisState) == 883)`；
- C#：`VisStateWireSize = 883`，连接线程启动前用 `Marshal.SizeOf<VisState>()` 校验；
- C++ `bool` 在 C# 必须声明为 `[MarshalAs(UnmanagedType.I1)] bool`；
- 两端字段顺序必须完全一致，不能只更新一端。

主循环生成快照，`VisServer` 线程只发送最新 dirty 状态。WPF 后台线程反序列化后保存最新帧，`DispatcherTimer` 约每 33 ms 刷新绑定属性，避免管道线程直接操作 UI。

统一实验记录新增的状态包括：

```text
recording_state / recording_error / recording_elapsed_us
force_writer_dropped / motion_writer_dropped
force_schedule_missed / motion_schedule_missed
force_sample_valid / clean_force_valid
clean_force_n / clean_handle_torque_nm
camera_state / camera_input_format / width / height / fps
camera_preview_enabled / camera_recording / elapsed / frame_count / dropped / error
physical_button_event_counter / physical_button_event_code
```

### 3.2 WPF 到 C++

命令消息由固定 24 字节头和可选负载组成：

```text
magic:uint32          0x31434D56（"VMC1"）
version:uint16        1
header_size:uint16    24
type:int32
param1:int32
param2:int32
payload_size:uint32
payload:byte[]        UTF-8，最多 1024 字节
```

命令 7 和 20 是已删除旧日志功能留下的数值空洞，不得复用。当前记录相关命令为：

| 值 | 命令 | 参数 |
|---:|---|---|
| 25 | `StartExperimentRecording` | UTF-8 负载为实验名称 |
| 26 | `StopExperimentRecording` | 无 |
| 27 | `SetCameraPreview` | `param1`：0 关闭，1 打开 |
| 28 | `SetCleanForceMonitor` | `param1`：0 关闭，1 打开 |
| 29 | `SetArmManualEnable` | `param1`：0 关闭，1 开启 |
| 30 | `SetArmAxisEnable` | `param1`：轴号 1..5；`param2`：0 断电，1 上电 |
| 31 | `RequestArmAxisReset` | `param1`：轴号 1..5 |
| 32 | `SetArmAxisJog` | `param1`：轴号 1..5；`param2`：-1/0/1 |
| 33 | `SetArmJogParameter` | `param1=(轴号-1)*4+字段号`；`param2=值*1000` |
| 34 | `SetAxis4ManualJog` | `param1`：-1 后退、0 停止、1 前进（物理语义） |

服务端先校验 magic、版本、头长、负载上限和完整消息长度，再放入 16 槽命令队列。主循环消费命令；队列满时新命令被忽略，因此 UI 不应高频连发控制命令。

## 4. 主窗口

`MainWindow` 是操作员第一屏，右侧“实验记录”区包含：

- 外置“实验名称”标签和普通 `TextBox`，`MaxLength=64`；
- “开始实验记录”“停止实验记录”“相机预览”按钮；
- 会话状态、会话时长、CSV 队列/调度丢样、相机状态和实际参数；
- 记录期间禁用名称编辑；`Starting/Recording/Stopping` 状态下按钮严格互斥。

输入框没有覆盖式占位文字，保留 WPF 原生中文 IME、退格、Delete、选择替换和撤销行为。名称的最终清洗由 C++ 完成，UI 不自行改写用户文本。

相机缺失时主界面和预览窗口使用固定文本：

```text
无法找到摄像设备：OsmoAction4
```

这不会禁用统一记录；只有 C++ 管道未连接时禁止开始。

模式区允许在屈曲恢复运行时点击其他普通或协同模式。C++ 会先停止恢复、等待轴3/5/6稳定并执行重同步，再应用最后一次目标模式请求。物理 SN 582 的 `B0/B6` 只在按下沿触发；事件计数变化后 WPF 以实际后端模式更新单选项，并显示一行红色“物理按钮触发”提示。

左侧轴面板提供 axis4 和定位臂的按住点动按钮。鼠标按下发送方向，按住期间每 100 ms 续约，松开、失去鼠标捕获、主窗口失焦或退出时发送停止；C++ 端在 300 ms 未收到续约后也会强制清除 UI 点动。axis4 的 C++ 端继续执行现有反接线方向交换，因此 WPF“前进/后退”描述的是实际物理方向。定位臂总使能在 ADS 健康后由独立服务自动请求，各轴仍需单独点击上电。

## 5. 弹出窗口

### 5.1 力反馈实时窗口

`ForceRealtimeWindow` 显示现有反馈链路的四条曲线。标题和图例明确区分“实际下发值”和“反馈目标值”。这些值经过反馈链路的门控、重力补偿选项、死区、限幅和快退处理，不能当作纯净传感器值。

### 5.2 纯净力感窗口

`CleanForceWindow` 打开时发送 `SetCleanForceMonitor=1`，关闭时发送 0：

- 原始 `Fn/Ft` 电压在有效采样到达时始终显示；
- 未调零时显示“等待零点采集”，不伪造纯净值；
- 调零后绘制 `clean_force_n` 与 `clean_handle_torque_nm`；
- 两条曲线各自缩放 Y 轴，时间窗为最近 30 s；
- 该窗口不依赖力反馈开关、运动模式、PI 或完整记录会话。

### 5.3 Action 4 预览窗口

`CameraPreviewWindow` 可独立于实验记录打开，显示设备状态、实际输入格式、输出编码、分辨率、帧率、录像时长、帧数和源时间戳检测出的丢帧数。

交互：

- 窗口可调整大小和最大化；
- “适应画面”恢复 1 倍并居中；
- 鼠标滚轮在 1x 到 8x 之间缩放；
- 按住左键拖动画面；
- 缩放和平移只作用于 WPF 预览，不改变 MP4。

关闭窗口会发送 `SetCameraPreview=0`。未录像时 C++ 释放采集设备；录像中只停止向共享内存发布预览帧，录像继续。

### 5.4 力过渡实验窗口

`ForceTransitionWindow` 只控制力过渡状态机和参数。是否有统一记录会话不作为状态机启动条件；专用 CSV 是否创建由 C++ 在力过渡启动瞬间决定。

## 6. 预览共享内存

视频帧不进入 `VisState`。C++ 将 1280x720 BGRA32 预览写入版本化双缓冲共享内存：

```text
映射名：Local\ADS_Action4_Preview_v1
事件名：Local\ADS_Action4_PreviewEvent_v1
头大小：64 字节
缓冲：2 x (1280 x 720 x 4)
```

写端先填充非活动缓冲，再发布 `active_index` 和递增 `frame_sequence`，最后触发自动复位事件。WPF 在复制前后复核 sequence/index；若写端在复制期间切换帧，本次帧直接丢弃，下一事件再读，避免撕裂。

共享内存只在本地会话命名空间使用。若 C++ 尚未运行，WPF 每 250 ms 尝试重新打开映射和事件；失败路径会释放已经打开的部分句柄。

## 7. 窗口生命周期

`MainWindow` 持有各弹窗的单例引用：重复点击只激活已有窗口。窗口 `Closed` 后清空引用，并对需要后台采样的窗口发送关闭命令。

`Vm_StateUpdated` 把同一份 `VisState` 分发给已打开窗口。弹窗不自行建立第二条命名管道，也不拥有控制状态。

## 8. 修改协议或 UI 的检查清单

1. 新增 `VisState` 字段只追加在末尾，并同步 C++/C# 字段、类型和 wire size。
2. 新命令使用新的枚举值，不填补 7/20 空洞；需要文本时使用 UTF-8 payload。
3. UI 只发送请求，安全前置条件由 C++ 再校验。
4. 弹窗关闭时撤销对应 monitor/preview 请求，录像例外逻辑留在 C++。
5. 新增固定格式画面时设置明确尺寸/最小尺寸，检查窄窗口中文本不重叠。
6. 同时构建 x64 Debug/Release；旧版 C++ 和新版 WPF 不能混用。
