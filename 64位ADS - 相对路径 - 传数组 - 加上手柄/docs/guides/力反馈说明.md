## 1. 总体架构

力反馈链路由四个层次组成：

```
[机器人传感器] -> [PLC 四路力变量] -> [AdsCommunicationService 100 Hz Sum Read]
                                                   |
                                                   v
                                        [AdsFastSnapshot]
                                                   |
[TCP_DAQ 人工回退源] -------------------------------+--> [主循环 ForceSampleFrame]
                                                   |
                                                   v
                                          +---------+---------+
                                          |                   |
                                          v                   v
                                  纯净力固定公式        反馈标定/门控链
                               force.csv/纯净力窗口     手柄实际下发
                                               |
                                               v
                           (可选) ForceSignalProcessor 在线尖峰/零点处理
                                              |
                                              v
                          process_force_feedback (force_feedback.cpp)
                              |          |
                              |          +-- calibrate_force (force_calibration.h)
                              |                  零点扣除 -> F_direct -> axis2角度重力补偿(可选) -> 解耦旁路 -> 死区/限幅
                              |
                              +-- 快退锁存：实际下发值锁存，理论未锁存值继续刷新
                              |
                              v
                           ForceOutputCmd (force_582_f, force_582_n, force_587_f, force_587_n)
                              |
                              v
                Handle::setforce_axis(F, axis, N)  -> sendForce(...)  (FLCatheter SDK)
```

## 2. 数据流详解

### 2.1 默认 ADS 采集与 TCP 回退（`plc_io.cpp` / `tcp_force_daq.cpp`）

- 默认 `cfg.force_sample_source == ADS`。TwinCAT 应将轴向力接到 `G.fn_1_value : INT`、扭矩接到 `G.ft_1_value : INT`；两路必须保持有符号量，并约定 `1000 counts = 1 V`。
- `AdsCommunicationService` 每个 100 Hz 周期在同一次 Sum Read 中取得四路原始 `INT` 和 7 轴位置；`plc_io::read_force_sample` 在正常模式只复制该快照并完成 `raw / 1000.0` 换算。后续仍传递伏特值，但物理力必须再按 `F_direct` 的 `N/V` 斜率换算，不能把电压数值直接当作 N。
- `TCP_DAQ` 仍可通过代码配置显式采集原始数据，但本次 `F_direct` 只由 ADS/PLC 计数标定；在确认 TCP 与 ADS 为同一返工前端、同一缩放和同一通道前，TCP 模式拒绝采零，因此不会启用纯净力或反馈输出。

- TCP 回退协议：Modbus-TCP 查询，固定 12 字节命令字 `00 03 00 00 00 06 01 04 00 40 00 08`，对端返回 25 字节，其中第 9\~20 字节为 6 通道 INT16 大端。
- 解析：
  ```cpp
  short raw = (hi << 8) | lo;
  voltage = raw / 1000.0;        // INT16 计数 -> 电压(V)
  ```
  含义：上位机约定 `1000 counts = 1 V`。板卡返工后电压与力不再按旧的一比一假设换算，必须使用 2026-08-03 实机 `F_direct` 系数。
- 线程模型：
  - 一条 worker 线程死循环：connect -> send query -> recv 25 字节 -> 解析 -> 加锁更新 `latest_v_[6]` 和该帧 QPC。
  - 收发各 300 ms 超时；断线自动 200 ms 重连。
  - 主线程通过 `get_latest_raw(double[6], tick_ms, qpc_ticks)` 拿"最近一帧"，**非阻塞**；若 worker 还没拿到第一帧则返回 false。
- 通道映射（见 `tcp_force_daq.cpp::get_latest_ft1_fn1` 和 `main.cpp` 中 `force_sample` 赋值）：
  ```
  v[0] -> fn_1_value_v   (轴向力通道电压)
  v[1] -> ft_1_value_v   (扭矩通道电压，对应切向拉压传感器)
  v[2..5] -> 当前链路未使用
  ```

### 2.2 主循环采样（`main.cpp` 主循环步骤 15，力采样节拍段）

> 步骤编号见 [项目架构总览.md §4](项目架构总览.md#4-主循环骨架maincpp-主循环-whiletrue)。2026-06-26 校对时本段约在 L2272-L2360。

每份新的 100 Hz ADS 快照到达后执行：

1. 若 `force_sample_source == TCP_DAQ`：读取最新 TCP 帧，把 v\[0] -> `force_sample.fn_1_value_v`、v\[1] -> `force_sample.ft_1_value_v`，并要求帧龄不超过 500 ms；axis1/axis2 位置复用当前 PLC 快照。
2. 若 `force_sample_source == ADS`：所有四路力都来自当前 `AdsFastSnapshot`（PLC 变量 `G.ft_1_value` / `G.fn_1_value` / `G.fn_2_value` / `G.ft_2_value`），不会从主循环再次读取 PLC。
3. 快速 Sum Read 失败、PLC 时序跨度不合格或 TCP 回退源没有新鲜帧时标记 `force_sample.valid=false`。其中 ADS 的 PLC 时序跨度只影响力采样有效位，不会把位置快照判成通信失败；力反馈阻断提示仅在原因变化时输出一次，避免控制台被周期信息淹没。
4. 这里**没有对原始电压做任何滤波**——也就是说传给标定的就是 INT16/1000.0 的瞬时电压。
5. ADS 快速快照无论反馈开关是否开启都按目标 100 Hz 获取；完整会话的 `force.csv` 对每个尝试序号最多写一行。仅使用 TCP 回退源且只有 PI 需要健康门控时，消费节流为约 20 Hz且不写文件。

### 2.3 标定/解耦旁路（`force_calibration.h::calibrate_force`）

输入：四路传感器电压、`axis2_deg`（ADS 读到的 axis2 角度值）、配置 cfg、状态 state。

步骤：

```text
1) 零点扣除（必须先调用 zero_force_sensor，否则 zeroed=false 直接返回 0）：
   导管：df_582_v = fn_1 - f_zero；dft_582_v = ft_1 - ft_zero
   导丝：df_587_v = fn_2 - fn_2_zero；dft_587_v = ft_2 - ft_2_zero

2) F_direct 增量映射。绝对曲线截距在 F(raw)-F(raw_zero) 中抵消。以下为 2026-08-31 传感器本体标定结果：
   df_582_n  = 0.701461986 * df_582_v   // 传感器2 / fn_1，N
   dft_582_n = 0.620117055 * dft_582_v  // 传感器1 / ft_1，N
   df_587_n  = 1.139996290 * df_587_v   // 传感器3 / fn_2，N
   dft_587_n = 0.130548347 * dft_587_v  // 传感器4 / ft_2，N

3) 重力补偿（只保留在导管对，且仅 `gravity_comp_enabled && gravity_comp_validated` 时执行；当前 validated=false）：
   theta_deg = axis2_deg mod 360
   theta0    = cal_state.theta0_deg mod 360  // 零点采集时记录的 axis2 角度
   dft_n -= ft_grav(theta_deg) - ft_grav(theta0)
   df_n  -= fa_grav(theta_deg) - fa_grav(theta0)

4) 解耦暂时旁路：
   F_dec  = df_n
   Ft_dec = dft_n

   旧解耦参数来自返工前系统标定，重新启用前必须基于新物理量重新标定。

5) 主端反馈量映射：
   F_theory = F_dec                                      [N]
   T_theory = k_feedback * Ft_dec * handle_radius_mm * 0.001
            = 1.0 * Ft_dec * 3.0 * 0.001                 [N·m]

6) 两对反馈共用死区与运行限幅：
   |F_theory| < deadband_f_n(0.02 N) -> 0
   |T_theory| < deadband_t_nm(1e-4 N·m) -> 0
   F_theory 限幅 ±f_max_n(5.0 N)
   T_theory 限幅 ±t_max_nm(0.020 N·m，即20 N·mm)
```

> `±5 N / ±20 N·mm` 是用户指定的运行上限，明显超过本次 `0–50g` 单向砝码实验的验证范围；它不是“已验证量程”。

### 2.4 纯净力（`force_calibration.h::calculate_clean_force`）

纯净力只在原始采样有效且已经调零时成立：

```text
clean_force_n = 0.701461986 * (fn_raw_v - fn_zero_v)
clean_handle_torque_nm = 0.620117055 * (ft_raw_v - ft_zero_v) * 3.0 * 0.001
```

它不应用重力补偿、串扰矩阵、`k_feedback`、死区、限幅、轴向符号、模式门控、快退锁存、PI 或力过渡处理。`force.csv`、力过渡专用表和“纯净力感”窗口共用此函数。未调零时保留原始电压，零点和纯净值写/显示为无效。

### 2.5 力反馈输出（`force_feedback.cpp::process_force_feedback`）

参数：当前采样帧、两个 Handle 引用、模式状态（导丝/导管）、各类使能位、`axis1_fast_return`、`axis6_fast_retract`、配置。

输出策略：

```text
output_enabled = ff.enabled && control_active && !freeze_active && !estop_hold_active && cal_state.zeroed && sample.valid

if (output_enabled):
    if guidewire_mode in {None, Cooperative}:
        // 传感器2/1 -> 导管/582手柄
        out_cmd.force_582_* = calibrate_force(fn_1_v, ft_1_v, ...)
        快退时由 freeze_582_* 锁存
    else:
        out_cmd.force_582_* = 0

    if guidewire_mode in {Independent, Cooperative}:
        // 传感器3/4 -> 导丝/587手柄
        out_cmd.force_587_* = calibrate_guidewire_force(fn_2_v, ft_2_v, ...)
        快退时由 freeze_587_* 锁存
    else:
        out_cmd.force_587_* = 0
else:
    // 未启用 / 暂停 / 急停 / 无效采样
    全部置 0

双手柄：分别向 catheter_feedback_handle 与 guidewire_feedback_handle 下发582/587命令
单手柄：两个逻辑角色指向同一Handle，只按当前模式调用一次setforce_axis，避免后一条零命令覆盖有效命令
```

`Handle::setforce_axis(F, axis=1, N)` 会构造 `fForce[3] = {0, F, 0}` 并调用 `sendForce(fForce, N, iID1)`：

- 线性反馈力作用在手柄第 1 轴（与 `cfg.axial_force_axis = 1` 对应）；
- 力矩作用在手柄旋转关节（SDK 内部）；
- 其余两个线性方向恒为 0。
- `force_582_*` 表示“导管/582语义”，由传感器2/1驱动；`force_587_*` 表示“导丝/587语义”，由传感器3/4驱动。
- 独立导丝模式只输出587；导管模式只输出582；双手柄协同模式同时输出582和587。
- 单手柄模式会把当前模式对应的逻辑输出重定向到唯一可用物理手柄；单手柄不允许进入协同模式。
- `force_582_f/n` 始终表示最终实际下发给 `setforce_axis` 的导管语义值；快退期间它们是锁存值。
- `force_582_theory_f/n` 表示同一帧传感器数据经过零点、可选重力补偿、标定、解耦旁路、死区和限幅后的理论未锁存值；快退期间继续实时更新，但不直接下发。

### 2.6 主循环耦合点（`main.cpp`）

- 启动时：`std::cout << "力反馈：关闭"` + `clear_force_output()`。`ff.enabled = false`。
- 按键 `F`：切换 `ff.enabled`，并 `ff.reset()`；关闭时立刻清零双手柄。
- 按键 `Z`：调用 `zero_force_sensor("")`。默认 ADS 源会同步读取一帧 ADS 数据，同时采集 `f_zero / ft_zero / fn_2_zero / ft_2_zero`，并记录该帧 `axis2_pos_rel` 为 `theta0_deg`；TCP\_DAQ 尚未完成同源标定，当前会明确拒绝采零且不会回退到 ADS。
- 每周期最后调用 `process_force_feedback(ff, force_sample, *catheter_force_output_handle, *guidewire_force_output_handle, guidewire_mode, control_active, freeze_active, estop_hold_active, axis1_fast_return, axis6_fast_retract, loop_count, cfg, cal_cfg, cal_state);`
- 力反馈值日志：每 1 秒按当前模式打印 `[FF-582]`、`[FF-587]`；协同模式两条都打印。
- 单手柄模式下，导管/导丝逻辑输出均指向唯一初始化成功的 `Handle`，`process_force_feedback` 只下发当前模式的一条命令。
- WPF 力反馈区提供“重力补偿”开关，通过 `VisCommandType::SetGravityCompensation` 设置 `cal_cfg.gravity_comp_enabled`。UI 的 `GravityCompEnabled` 绑定来自 `VisState.gravity_comp_enabled`，显示以主程序真实状态为准。
- WPF 实时力窗口只允许在 `ff_enabled && cal_zeroed` 时打开；打开后条件失效则停止追加并显示不可用状态。窗口同图显示四条曲线：红/蓝实线为实际下发 `force_582_f/n`，红/蓝虚线为理论未锁存 `force_582_theory_f/n`，30 秒滚动窗，y 轴按四条曲线共同自适应。

## 4. 状态机：快速回退期间的力反馈处理

### 4.1 触发源

`axis1_fast_return` 和 `axis6_fast_retract` 这两个布尔位由 `main.cpp` 主循环的爬行/快退状态机置位，**仅在状态机阶段为 TRUE**：

- `axis1_fast_return`：导管模式下 axis1 进入 `SwitchWait / FastMove / RestoreWait` 三阶段时被置位。
- `axis6_fast_retract`：导丝模式或导管联动模式下 axis6 进入对应三阶段时被置位。
- 每个主循环开头都先清零，再在状态机内重新置位。
- 这两个位也会通过 ADS 写回 PLC（`G.axis1_fast_return` / `G.axis6_fast_retract`），用于下位机平滑旁路。

### 4.2 freeze\_582 / freeze\_587 机制

`ForceFeedbackState` 分别保存582与587两组快退锁存字段。

- 进入快退（任一标志为 TRUE）：当前激活的582/587输出分别锁存进入时刻的标定值。
- 退出快退：清除对应锁存状态，恢复每拍实时映射。
- **副作用**：快退入口的一瞬采样如果本身已经失真（接触瞬间、夹爪切换等），冻结值就会"卡在一个错值"上；快退退出瞬间会从冻结值跳变到实时值，操作者会感到明显突变。

> 这正是用户提到的"快速回退阶段机器人力数据不准、要靠卡尔曼滤波让反馈连续"的痛点所在。

### 4.3 其他清零路径

- `ff.enabled = false` -> `ff.reset()` -> 双手柄输出 0。
- `freeze_active`（582 暂停键）-> 每拍 `clear_force_output()` 并清 ff。
- `estop_hold_active`（PLC 保持）-> 同上。
- 普通导管模式只保留582；独立导丝模式只保留587；协同模式同时保留两路。
- `sample.valid == false`（ADS 读失败或 TCP 回退源无有效帧）-> 输出 0；"力反馈等待..."仅在阻断原因变化时提示一次。

## 6. Kalman 滤波接入方案（在 TCP 采集线程内）

### 6.1 目标

让"快速回退阶段被冻结的力反馈值"过渡到"快退结束后的实时值"时不出现阶跃，且在 TCP 偶发抖动 / 重连过程中输出可平滑外推。

### 6.2 选定接入点

**TcpForceDaqClient worker 线程，紧跟在** **`parse_response_to_voltage`** **之后、写入** **`latest_v_`** **之前。**

理由：

- 该线程是力数据的**最高频率源**（受网络/PLC 节拍约束，但远高于主控制环），在这里滤波获得最佳信噪比、相位延迟最小。
- `latest_v_` 是 TCP 模式下主循环的唯一入口；在此处过滤可同时服务反馈链和统一记录的采样快照。
- 与现有 `freeze_582_active` 机制解耦：力反馈输出层依旧保留"快退期冻结"逻辑做保险，但冻结对象会改成"卡尔曼滤波后的值"，离场更连续。

### 6.3 信号同步：fast\_move 状态如何到达 worker 线程

worker 在独立线程跑，不能直接读 `ForceFeedbackState`。需要新增一个**原子布尔**（或位掩码）由主线程写、worker 线程读：

```cpp
// tcp_force_daq.h (新增)
public:
    void set_fast_move_flag(bool active);  // 主线程在每拍调用，o(1) 原子写
private:
    std::atomic<bool> fast_move_flag_{false};
```

主循环中：

```cpp
const bool fast_move_active = axis1_fast_return || axis6_fast_retract;
tcp_force_daq.set_fast_move_flag(fast_move_active);
```

worker 线程在每解析完一帧后读 `fast_move_flag_.load(std::memory_order_relaxed)` 用于切换 Q/R。

### 6.4 滤波模型

针对 v\[0] / v\[1] 两路（fn\_1\_v / ft\_1\_v）分别建立独立 1D KF：

状态：`x = [value, value_rate]^T`\
模型：恒速度（匀变化率）\
A = `[[1, dt], [0, 1]]`，B = 0，H = `[1, 0]`

- `dt`：用相邻两帧 `GetTickCount64()` 差，clamp 到 \[1ms, 50ms]，避免长时间无帧时 dt 爆掉。
- 过程噪声 Q：
  ```
  Q_normal = diag(q_pos_normal^2, q_vel_normal^2)         // 慢速跟随
  Q_fast   = diag(q_pos_fast^2,   q_vel_fast^2)            // 快退/抖动时放大
  ```
- 测量噪声 R：
  ```
  R_normal = r_normal^2
  R_fast   = r_fast^2        // r_fast >> r_normal，让滤波器在 fast_move 期间几乎忽略测量、纯靠预测
  ```

切换规则：

- `fast_move_flag == true` -> 用 Q\_fast / R\_fast，等价"靠模型外推、忽略噪声测量"。
- `fast_move_flag` 由 true 翻 false 后维持几十毫秒过渡期 R 线性插值回 R\_normal，避免回切瞬间又跳变。

### 6.5 数据契约（最小侵入）

- worker 维护 `filtered_v_[6]`，初次帧 raw 直接复制为初始状态，之后每帧调用 `kf.update(raw)` 得到滤波值写入 `filtered_v_`。
- `get_latest_raw` **保持不变**（仍然返回未滤波电压和 QPC，供统一 `force.csv` 写原始真值）。
- 新增 `bool get_latest_filtered(double out_v[6], std::uint64_t& ts) const;` 用于力反馈消费侧。
- `process_force_feedback` 改读 filtered，`force.csv` 保持 raw 契约。若研究确需 filtered 列，应显式扩展统一表 schema，而不是恢复独立日志器。
- 推荐 CSV 加列：`ain0_filt_v, ain1_filt_v, kf_q_mode (0=normal/1=fast)`。

### 6.6 建议参数起点

> 这些值应在调参阶段以 CSV 回放为依据微调；以下仅作起点。

```
dt_typical ~ 5–20 ms（视实际 TCP 节拍）
q_pos_normal = 0.005 V       // 缓慢漂移容忍
q_vel_normal = 0.05 V/s
r_normal     = 0.01 V        // 实测电压噪声标准差量级，需从静止段 CSV 估
q_pos_fast   = 0.05 V        // 模型不确定性放大约 10x
q_vel_fast   = 0.5 V/s
r_fast       = 10.0 V        // 极大，等价忽略测量
```

`r_normal` 强烈建议从历史 `Force_sensor_*.csv` 的静止段经验估计：取一段 push\_pull\_code=0 且 rot\_sign\_code=0 的连续区间，对 `fn_1_raw_v / ft_1_raw_v` 计算样本方差，开方即得。

### 6.7 与现有 `freeze_582` 的关系

- 一阶段方案：保留 `freeze_582_active` 作为最后的安全网（KF 万一发散也不会让手柄抖）；KF 滤波后的电压只是"喂得更平滑"，freeze 仍然锁存进入瞬间的 cal.f\_feedback\_n，但因为 KF 已抹平了入口尖峰，锁存值更可信、退出瞬间的差也更小。
- 二阶段方案（验证 KF 稳定后再做）：把 freeze 改成"用 KF 在 fast\_move 期间的预测序列实时下发"，彻底取消硬冻结，实现"快退期间力反馈跟随机器人推理的虚拟力"。这一步要等 §6.4 的 Q\_fast/R\_fast 调到位之后再切换。

### 6.8 验收方法

1. 重新跑一组快进/快退操作，导出新版 CSV（含 raw + filtered + kf\_mode）。
2. 用 Python 脚本对比 `fn_1_raw_v` 和 `fn_1_filt_v` 在 fast\_move 边界（kf\_mode 0->1, 1->0）的差分，量化突变幅度。
3. 操作者主观评价：在不告知开关状态的情况下，对比是否仍能感到回退结束时刻的"顿一下"。
4. 把对比图（类似 `加入二阶滤波器整体.png` / `二阶滤波局部平滑.png`）归档到本目录。
