## 已明确的功能边界

| 功能 | 数据源 | 主端职责 | 当前 ADS 从端职责 |
|---|---|---|---|
| DSA 机械臂三维状态 | 未来提供的独立 DSA 机械臂控制程序 | 使用旧 URDF、旧数值语义显示；现在预留输入接口 | 无，不使用它的七轴驱动旧模型 |
| 海康监控 | 现场海康设备 | 直接登录、H.264/UDP 预览 | 无，不承担海康中转 |
| DSA 屏幕影像 | 另一台安装影像软件的电脑 | 接收从端转发的屏幕画面 | 从端电脑接收截屏并转发；建议用独立媒体进程实现 |

海康监控与 DSA 截屏是两条不同链路。已明确 H.264/UDP 用于海康监控。DSA 截屏暂按旧 JPEG 截图方式设计；步骤 5 暂定使用独立 TCP 连接传输 JPEG。如果用户明确 DSA 也要 H.264/UDP，应先调整步骤 5，不能把暂定方案当成已确认要求。

## 步骤 2：预留独立机械臂状态接口

```text
执行步骤2：为RobotViewport增加独立DSA机械臂状态入口。该机械臂程序尚未提供，本步实现数据契约和离线注入，不绑定真实网络协议。

最小接口：一个DsaArmDisplayState类型和一个发布/更新方法即可，例如PublishDsaArmState(state)。包含：sj[7]、xj[2]、v1、v2，以及用于新鲜度判断的本地接收时间；未来网络会话/序号在适配器中处理。不要为未确定的协议创建多层接口或模拟设备框架。

规则：
1. 接口接收“已经转换到旧显示坐标的值”。sj1/sj2/sj6是米；其余6个动态关节是弧度。v1/v2沿用旧ct显示值，核对GetV1/GetV2来源再命名单元，不凭名字认为是速度或弧度。
2. 一次提交完整快照；复制输入数组，严格检查长度与NaN/Infinity。非法输入不覆盖上一次有效姿态，不刷新有效数据时间。
3. 后台调用者只发布最新完整快照。UI线程以有界频率取最新值、MoveJoint和Render；没有新值时无需重复渲染。
4. 模型状态与现有RemoteRobotLink完全分开。未接入保持旧默认；曾有数据后超时保持最后有效姿态并显示“机械臂状态过期”。使用本地单调时钟判断接收新鲜度。
5. 提供显式离线测试入口，标签写“测试数据”；不自动把无网络当作有实时数据。
6. 保存未来独立发送端需要履行的契约，说明标定转换只能在一个边界执行，已经转换的sj/xj不能二次加偏移。

旧转换基准来自A/RobotSystem/Robot/Motions/Motions.Cycles.cpp：
sj1 = u1 + 4.12288*0.001
sj2 = u2 - 96.2203*0.001
sj3 = -(u3 + 18.2306/180.0*3.14159)
sj4 = u4 - 1.47907/180.0*3.14159
sj5 = u5 + 1.34638/180.0*3.14159
sj6 = u6 - 5.50232*0.001 + P6*0.001
sj7 = u7 - 25.2479/180.0*3.14159
xj1 = d1
xj2 = d2 - 2.0/180.0*3.14159
这里只保存旧标定依据，不导入DSA类或启动其构造函数。未来发送端若提供原始u/d/P6，再由适配器实施该转换；若提供显示sj/xj则直接使用。

验收：留一个可运行离线检查，覆盖九关节逐一变化、非法长度、非有限值、发布后修改原数组、过期/恢复。确认递送机器人状态不会移动此模型。若使用旧注释测试姿态，完整标明来源并仅用于显式测试。
```

## 步骤 5：DSA 截屏经从端转发到主端

```text
执行步骤5前，先查看用户对DSA影像传输的最新确认。此提示词采用JPEG截图+独立TCP传输；海康仍保持H.264/UDP。若用户明确DSA也用H.264/UDP，先重写本步骤的媒体方案再实现。

目标链路：DSA影像电脑的截屏程序 → 从端电脑的媒体接收/转发程序 → MasterConsole影像控件。
媒体接收/转发程序建议作为从端电脑上的独立C# net472进程，与ADS.exe同机运行。这样不把图像编码、网络阻塞或异常引入控制进程。该部署方式应在启动说明中明确。

工作内容：
1. 复用A/ScreenCut的区域截图和JPEG编码。把源截图矩形、目标地址、帧率、JPEG质量放进配置；保留负坐标多屏支持，校验矩形位于可捕获桌面内。频率参数可调，先以旧300ms周期为基准。
2. 修正截图对象生命周期：Bitmap/Graphics/MemoryStream/编码参数及时Dispose，若用GetHbitmap则匹配DeleteObject。截图、压缩和发送在后台，UI只负责配置和状态。
3. 从端媒体进程监听两条独立入口：截图源发布入口、主端订阅入口。端口做配置，建议值仅在本机冲突检查后采用32100/32002。主端主动连从端，从端持续返回已接收帧。
4. 把帧格式、端序、版本、字段大小和限制写入独立媒体协议。至少有magic、version、streamId、sessionId、frameId、源时间戳、width、height、codec、payloadLength、JPEG数据及认证约定。使用固定上限校验长度/尺寸/像素数后再分配和解码，处理TCP拆包、粘包和中途断开。
5. 源端与主端分别以自己的媒体凭据认证到中继；复用现有HMAC挑战设计时给媒体单独的协议标识/密钥用途，不能混用机器人控制会话或控制租约。仅绑定所需实验网地址，真实token不入库。
6. 从端转发原始JPEG字节，不解码再压缩。每一路最多保留当前在发送帧和最新待发送帧；慢客户端有发送截止时间，超过就断开重连，避免TCP发送缓冲长期积累旧画面。
7. 数据源关闭后，中继不能反复发送缓存画面冒充新帧；通知源离线或等待主端超时。保留源sessionId/frameId，重连后清理旧待发送帧。
8. 主端后台解码最新完整JPEG，使用OnLoad并Freeze后交给UI；Dispose输入流。保持图像比例，显示帧龄/来源/断线状态，过期画面必须有明显标识。
9. 本地单调时钟计算“距离收到最后一帧多久”。源时间戳未经跨机同步不能直接算单程延迟，测端到端延迟用同屏计时/拍摄或已验证时钟同步方法。
10. 旧ScreenCut的UDP格式只是一个5字节头加8192字节裸分块，没有帧号或分片号。此方案保留其截图能力但替换发送/接收传输，不宣称新TCP端与旧UDP发送端直接兼容。
11. 媒体启动、断网、重连和退出都独立于现有100Hz控制/触觉线程；海康画面不经过此中继。

验收：
- 用假截图源跑通“源→中继→主端”，图案包含递增帧号，核对显示源一致。
- 覆盖超长帧/非法尺寸/损坏JPEG/认证失败/截断帧/断开重连。
- 限速验证最新帧策略和发送截止时间；数据源停止后不能一直显示在线。
```
