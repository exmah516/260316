## 已明确的功能边界

| 功能 | 数据源 | 主端职责 | 当前 ADS 从端职责 |
|---|---|---|---|
| DSA 机械臂三维状态 | 未来提供的独立 DSA 机械臂控制程序 | 使用旧 URDF、旧数值语义显示；现在预留输入接口 | 无，不使用它的七轴驱动旧模型 |
| 海康监控 | 现场海康设备 | 直接登录、H.264/UDP 预览 | 无，不承担海康中转 |
| DSA 屏幕影像 | DSA 电脑上的独立 ScreenCut 程序 | 默认直接接收 JPEG、解码并显示；必要时支持中继入口 | 默认无职责；仅在网络隔离时启用可选 JPEG 中继 |

海康监控与 DSA 截屏是两条不同链路。海康使用 H.264/UDP；DSA 影像保持旧项目的 JPEG 截屏格式。旧项目的 ScreenCut 是运行在 DSA 电脑上的独立程序，并直接向主端发送影像。当前项目默认实现主端直收和显示；只有现场网络不允许 DSA 电脑直达主端时，才增加从端中继，不把截图采集程序并入本项目。

## 步骤 2：预留独立机械臂状态接口

```text
执行步骤2：为RobotViewport增加独立DSA机械臂状态入口。该机械臂程序尚未提供，本步实现数据契约和离线注入，不绑定真实网络协议。

最小接口：一个DsaArmDisplayState类型和一个发布/更新方法即可，例如PublishDsaArmState(state)。包含：sj[7]、xj[2]、v1、v2，以及用于新鲜度判断的本地接收时间；未来网络会话/序号在适配器中处理。不要为未确定的协议创建多层接口或模拟设备框架。

规则：
1. 接口接收“已经转换到旧显示坐标的值”。sj1/sj2/sj6是米；其余6个动态关节是弧度。v1/v2沿用旧ct显示值，核对GetV1/GetV2来源再命名单元，不凭名字认为是速度或弧度。
2. 一次提交完整快照；复制输入数组，严格检查长度与NaN/Infinity。非法输入不覆盖上一次有效姿态，不刷新有效数据时间。
3. 后台调用者只发布最新完整快照。UI线程以有界频率取最新值、MoveJoint和Render；没有新值时无需重复渲染。
4. 模型状态与现有RemoteRobotLink完全分开。未接入保持旧默认；曾有数据后超时保持最后有效姿态并显示“机械臂状态过期”。使用本地单调时钟判断接收新鲜度。
5. 提供显式离线测试入口，标签写“测试数据”；不自动把无网络当作有实时数据。
6. 保存未来独立发送端需要履行的契约，说明标定转换只能在一个边界执行，已经转换的sj/xj不能二次加偏移。

旧转换基准来自A/RobotSystem/Robot/Motions/Motions.Cycles.cpp：
sj1 = u1 + 4.12288*0.001
sj2 = u2 - 96.2203*0.001
sj3 = -(u3 + 18.2306/180.0*3.14159)
sj4 = u4 - 1.47907/180.0*3.14159
sj5 = u5 + 1.34638/180.0*3.14159
sj6 = u6 - 5.50232*0.001 + P6*0.001
sj7 = u7 - 25.2479/180.0*3.14159
xj1 = d1
xj2 = d2 - 2.0/180.0*3.14159
这里只保存旧标定依据，不导入DSA类或启动其构造函数。未来发送端若提供原始u/d/P6，再由适配器实施该转换；若提供显示sj/xj则直接使用。

验收：留一个可运行离线检查，覆盖九关节逐一变化、非法长度、非有限值、发布后修改原数组、过期/恢复。确认递送机器人状态不会移动此模型。若使用旧注释测试姿态，完整标明来源并仅用于显式测试。
```

```text
可选中继链路（仅在网络隔离、路由或防火墙要求下启用）：
现有 DSA 电脑 ScreenCut → B 的从端 JPEG 接收适配器 → 主端 JPEG 接收接口 → DSA 影像显示控件。

实现要求：
1. 先读取并记录旧 ScreenCut 的真实协议，不凭猜测重写发送端：
   - 影像入口默认兼容 UDP 36661（流编号 0）和 UDP 36663（流编号 1），端口必须可配置；
   - 每帧先发送 5 字节头：1 字节流编号 + 4 字节大端 JPEG 长度；
   - 随后发送 JPEG 裸数据报，单个数据报最大约 8192 字节；
   - 36662/36664 是旧程序接收“快/慢发送”控制命令的端口。当前项目只有在确实需要控制发送频率时才实现该控制回路，否则只接收影像，不伪造控制命令。
2. 主端默认监听 UDP 36661 和 36663，按旧协议在后台重组 JPEG；配置中的 ScreenCut 目标 IP 应填写主端 IP。主端不能假设 JPEG 每个 UDP 包就是完整图片。
3. 对旧协议做输入边界校验：长度必须在配置的最大值内，流编号必须有效，分片累计长度不能超过声明长度；超时、长度不一致、截断、异常 UDP 包和损坏 JPEG 都丢弃当前帧并等待下一帧。旧协议没有帧号、分片号和校验和，这是兼容层的已知上限；不要把不完整帧显示成新画面。
4. 主端显示接口只接收完整 JPEG 字节，不解码再压缩。每路生成本地 frameId、接收时间、streamId 和 payloadLength，用于状态和帧龄显示。
5. 主端按旧项目需要向 ScreenCut 的 UDP 36662/36664 发送两字节快慢控制命令；如果本项目不需要根据布局调速，就不要伪造控制命令。
6. 只有在现场确认 DSA 电脑不能直接访问主端时，才启用可选中继：
   - 从端监听旧 UDP 36661/36663，按长度重组完整 JPEG；
   - 从端转发原始 JPEG，不解码、不重压缩；
   - 主端接收中继数据，媒体线程与控制、触觉、手柄线程隔离；
   - 中继增加 sessionId/frameId 等本地元数据，但不要求旧 ScreenCut 修改协议；
   - 中继可以是现有从端中的最小后台适配器；没有网络隔离证据时不要新建独立媒体服务。
7. 主端提供独立的 JPEG 接收接口和 DSA 影像显示占位控件：
   - 接收、完整性校验、JPEG 解码全部在后台；
   - WPF 更新在 UI 线程，使用 OnLoad 加载并 Freeze 图像对象后交给界面；
   - 每一路只保留“当前显示帧 + 最新待显示帧”，慢接收或慢 UI 时丢弃旧帧，禁止无限队列；
   - 显示来源、streamId、最后一帧时间/帧龄和“未连接/接收中/在线/过期/失败”状态；
   - 没有有效帧时显示等待占位，不得把静态占位图标记为在线；
   - 保持图像比例，损坏帧不能替换最后一张有效图；超过过期阈值后明确标记画面过期。
8. 没有有效帧时显示等待占位；损坏帧不能替换最后一张有效图；源停止后不能继续用缓存帧冒充在线；窗口关闭时清理 Socket 和后台任务。
9. 提供假 JPEG UDP 发送端和离线回放检查，至少覆盖：主端直收、两路 streamId、超长声明、截断帧、损坏 JPEG、乱序/丢包后的丢帧、源断开、主端关闭重开、慢 UI 丢旧帧。若启用中继，再增加“源→从端→主端”的检查。
10. 本步骤的完成标准是：不改 DSA 电脑端 ScreenCut，也不依赖 DSA 电脑端程序源码编译，能够用假发送端或现有 ScreenCut 的真实输出证明“JPEG 源 → 主端接口 → 显示占位控件”链路可用；若现场确有网络隔离，再证明可选中继链路。真实三机联调、DSA 端截图区域和发送频率仍标为待现场验证。
```
