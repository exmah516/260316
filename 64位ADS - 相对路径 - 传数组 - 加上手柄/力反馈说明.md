## 1. 总体架构

力反馈链路由四个层次组成：

```
[机器人传感器] -> [放大器/采集卡] -- TCP --> [TcpForceDaqClient (后台线程)]
                                              |
                                              v (锁保护的"最新一帧"缓存)
                                       主循环每周期取最新帧 (ForceSampleFrame)
                                              |
                                              v
                          (可选) ForceSignalProcessor 在线尖峰/零点处理
                                              |
                                              v
                          process_force_feedback (force_feedback.cpp)
                              |          |
                              |          +-- calibrate_force (force_calibration.h)
                              |                  零点扣除 -> axis2角度重力补偿(可选) -> 标定 -> 解耦旁路 -> 死区/限幅
                              |
                              +-- 快退锁存：实际下发值锁存，理论未锁存值继续刷新
                              |
                              v
                           ForceOutputCmd (force_582_f, force_582_n, force_587_f, force_587_n)
                              |
                              v
                Handle::setforce_axis(F, axis, N)  -> sendForce(...)  (FLCatheter SDK)
```

主要源文件（同目录，未拆分到子目录）：

| 文件                        | 角色                                                                                                                                                                |

## 2. 数据流详解

### 2.1 TCP 采集层（`tcp_force_daq.cpp`）

- 协议：Modbus-TCP 查询，固定 12 字节命令字 `00 03 00 00 00 06 01 04 00 40 00 08`，对端返回 25 字节，其中第 9\~20 字节为 6 通道 INT16 大端。
- 解析：
  ```cpp
  short raw = (hi << 8) | lo;
  voltage = raw / 1000.0;        // INT16 计数 -> 电压(V)
  ```
  含义：放大器把 ±5N 的力映射成 ±5V，DAQ 把电压 ×1000 量化成 INT16 输出；上位机再除回 1000。
- 线程模型：
  - 一条 worker 线程死循环：connect -> send query -> recv 25 字节 -> 解析 -> 加锁更新 `latest_v_[6]` -> 触发可选 `on_sample` 回调。
  - 收发各 300 ms 超时；断线自动 200 ms 重连。
  - 主线程通过 `get_latest_raw(double[6], tick_ms)` 拿"最近一帧"，**非阻塞**；若 worker 还没拿到第一帧则返回 false。
- 通道映射（见 `tcp_force_daq.cpp::get_latest_ft1_fn1` 和 `main.cpp` 中 `force_sample` 赋值）：
  ```
  v[0] -> fn_1_value_v   (轴向力通道电压)
  v[1] -> ft_1_value_v   (扭矩通道电压，对应切向拉压传感器)
  v[2..5] -> 当前链路未使用
  ```

### 2.2 主循环采样（`main.cpp` 主循环步骤 15，力采样节拍段）

> 步骤编号见 [项目架构总览.md §4](项目架构总览.md#4-主循环骨架maincpp-主循环-whiletrue)。2026-06-26 校对时本段约在 L2272-L2360。

每个主循环周期执行：

1. 若 `force_sample_source == TCP_DAQ`：调用 `tcp_force_daq.get_latest_raw`，把 v\[0] -> `force_sample.fn_1_value_v`，v\[1] -> `force_sample.ft_1_value_v`；同时通过 `plc_io::read_force_sample` 拿到 fn\_2 / ft\_2 / axis1\_pos\_rel / axis2\_pos\_rel（仍走 ADS）。其中 axis2\_pos\_rel 直接作为角度值供重力补偿使用。
2. 若 `force_sample_source == ADS`：所有四路力都来自 ADS（PLC 变量 `G.ft_1_value` / `G.fn_1_value` / `G.fn_2_value` / `G.ft_2_value`）。
3. 标记 `force_sample.valid = true`，否则 `valid = false` 并打印告警（限频 1Hz）。
4. 这里**没有对原始电压做任何滤波**——也就是说传给标定的就是 INT16/1000.0 的瞬时电压。

### 2.3 标定/解耦旁路（`force_calibration.h::calibrate_force`）

输入：`f_sensor`, `ft_sensor`（电压 V）、`axis2_deg`（ADS 读到的 axis2 角度值）、配置 cfg、状态 state。

步骤：

```text
1) 零点扣除（必须先调用 zero_force_sensor，否则 zeroed=false 直接返回 0）：
   df  = f_sensor  - f_zero
   dft = ft_sensor - ft_zero

2) 重力补偿（cfg.gravity_comp_enabled，默认 false，可由 UI “重力补偿”开关开启）：
   theta_deg = axis2_deg mod 360
   theta0    = cal_state.theta0_deg mod 360  // 零点采集时记录的 axis2 角度
   dft -= ft_grav(theta_deg) - ft_grav(theta0)
   df  -= fa_grav(theta_deg) - fa_grav(theta0)

3) 单通道线性标定：
   F_cal = axial_k * df     = 1.913504 * df
   T_cal = torque_k * dft   = 18.440851 * dft

4) 解耦暂时旁路：
   F_dec = F_cal
   T_dec = T_cal

   代码中保留原矩阵公式为中文注释，后续可按需要恢复：
   F_dec = decouple_ff * F_cal + decouple_ft * T_cal
   T_dec = decouple_tf * F_cal + decouple_tt * T_cal

5) 主端反馈量映射：
   F_theory = F_dec                                            [N]
   T_theory = k_feedback * T_dec * (handle_radius_mm / slave_lever_mm) * 0.001
                 = 1.0 * T_dec * (3.0 / 37.0) * 0.001               [N·m]

6) 死区与限幅：
   |F_theory| < deadband_f_n(0.02 N) -> 0
   |T_theory| < deadband_t_nm(1e-4 N·m) -> 0
   F_theory 限幅 ±f_max_n(5.0 N)
   T_theory 限幅 ±t_max_nm(0.030 N·m)
```

### 2.4 力反馈输出（`force_feedback.cpp::process_force_feedback`）

参数：当前采样帧、两个 Handle 引用、模式状态（导丝/导管）、各类使能位、`axis1_fast_return`、`axis6_fast_retract`、配置。

输出策略：

```text
output_enabled = ff.enabled && control_active && !freeze_active && !estop_hold_active && cal_state.zeroed && sample.valid

if (output_enabled && guidewire_mode == None):       // 仅导管模式下输出
    cal = calibrate_force(fn_1_v, ft_1_v, axis2_pos_rel, cal_cfg, cal_state)
    force_582_theory_f = cal.f_feedback_n
    force_582_theory_n = cal.t_feedback_nm
    if (axis1_fast_return || axis6_fast_retract):    // 快速回退阶段
        if (!freeze_582_active):
            // 首次进入快退：锁存当前帧的理论输出
            freeze_582_f = force_582_theory_f
            freeze_582_n = force_582_theory_n
            freeze_582_active = true
        out_cmd.force_582_f = freeze_582_f
        out_cmd.force_582_n = freeze_582_n
    else:
        freeze_582_active = false
        out_cmd.force_582_f = force_582_theory_f
        out_cmd.force_582_n = force_582_theory_n
    // 587（导丝侧）目前在导管模式下恒输出 0
    out_cmd.force_587_* = 0

elif (output_enabled && guidewire_mode != None):
    // 导丝模式下强制 582/587 都为 0
    全部置 0，force_582_theory_* 同步置 0
else:
    // 未启用 / 暂停 / 急停 / 无效采样
    全部置 0，force_582_theory_* 同步置 0

catheter_feedback_handle.setforce_axis(out_cmd.force_582_f, cfg.axial_force_axis(=1), out_cmd.force_582_n)
guidewire_feedback_handle.setforce_axis(out_cmd.force_587_f, cfg.axial_force_axis(=1), out_cmd.force_587_n)
```

`Handle::setforce_axis(F, axis=1, N)` 会构造 `fForce[3] = {0, F, 0}` 并调用 `sendForce(fForce, N, iID1)`：

- 线性反馈力作用在手柄第 1 轴（与 `cfg.axial_force_axis = 1` 对应）；
- 力矩作用在手柄旋转关节（SDK 内部）；
- 其余两个线性方向恒为 0。
- `force_582_*` 表示“导管/582语义”的反馈值，不再等同固定物理 SN 582；`main.cpp` 会在单手柄模式下把导管力输出重定向到唯一可用的物理手柄（例如仅有 587 时输出到 587）。
- `force_582_f/n` 始终表示最终实际下发给 `setforce_axis` 的导管语义值；快退期间它们是锁存值。
- `force_582_theory_f/n` 表示同一帧传感器数据经过零点、可选重力补偿、标定、解耦旁路、死区和限幅后的理论未锁存值；快退期间继续实时更新，但不直接下发。

### 2.5 主循环耦合点（`main.cpp`）

- 启动时：`std::cout << "力反馈：关闭"` + `clear_force_output()`。`ff.enabled = false`。
- 按键 `F`：切换 `ff.enabled`，并 `ff.reset()`；关闭时立刻清零双手柄。
- 按键 `Z`：调用 `zero_force_sensor("")`，从 TCP 当前帧采集 f\_zero / ft\_zero 写入 `cal_state`，并同步记录当时 `plc_act_pos[1]` / `force_sample.axis2_pos_rel` 为 `theta0_deg`；若 TCP 无帧且采样源是 TCP\_DAQ，则**不会回退到 ADS**；若采样源是 ADS 才会用 ADS 当前值。
- 每周期最后调用 `process_force_feedback(ff, force_sample, *catheter_force_output_handle, *guidewire_force_output_handle, guidewire_mode, control_active, freeze_active, estop_hold_active, axis1_fast_return, axis6_fast_retract, loop_count, cfg, cal_cfg, cal_state);`
- 力反馈值日志：每 1 秒打印一次 `[FF] AI0/f=, AI1/ft=, dft, df -> 582.setforce_axis(...)`，并带 theory、gravity、theta、theta0 字段；仅在 enabled+zeroed+valid+导管模式且控制激活时打印。
- 单手柄模式下，`main.cpp` 根据哪只 `Handle` 初始化成功选择导管力反馈物理输出对象：若只剩 587 或只剩 582，导管/582语义的力反馈都会下发到这只可用手柄，另一只未打开设备不会调用 SDK 力输出。
- WPF 力反馈区提供“重力补偿”开关，通过 `VisCommandType::SetGravityCompensation` 设置 `cal_cfg.gravity_comp_enabled`。UI 的 `GravityCompEnabled` 绑定来自 `VisState.gravity_comp_enabled`，显示以主程序真实状态为准。
- WPF 实时力窗口只允许在 `ff_enabled && cal_zeroed` 时打开；打开后条件失效则停止追加并显示不可用状态。窗口同图显示四条曲线：红/蓝实线为实际下发 `force_582_f/n`，红/蓝虚线为理论未锁存 `force_582_theory_f/n`，30 秒滚动窗，y 轴按四条曲线共同自适应。

## 3. 标定数值核对

> 与 `RUNTIME_CALIBRATION_DECOUPLING_PARAMETERS.md` 中的标定表交叉验证。

| 项目                            | 文档值                                 | 代码值 (`force_calibration.h`) | 一致性                           |

| slave\_lever\_mm              | 37.0                                | 37.0                        | OK                            |

| 重力补偿正向模型 (ft)                 | A=0.4983 / phi=-53.54 / off=-0.1119 | 同                           | OK                            |

| K\_feedback                   | (默认 1.0)                            | 1.0                         | OK                            |

> 量纲核对：
>
> - `f_zero` / `ft_zero` 保存的是 **电压(V)**（zero\_force\_sensor 写入的是 `raw_v[0]` / `raw_v[1]`，对应 `fn_1` / `ft_1`），主循环传入 `calibrate_force` 的也是 `fn_1_value_v` / `ft_1_value_v` 电压。
> - 由于放大器把 ±5N 映射到 ±5V，且 DAQ 又把 ±5V 量化为 ±5000 INT16 计数除以 1000 还原电压，因此"电压数值 = 对应的力数值（N）"。所以 `axial_k = 1.913504` 直接乘在电压差上得到的就是已标定的 N。**单位上自洽。**
> - `T_cal = 18.440851 × dft` 的单位是 N·mm（≡ mN·m）。
> - 当前 `F_dec = F_cal`、`T_dec = T_cal`，原解耦矩阵只作为注释保留。
> - 主端扭矩输出 `t_feedback_nm` = `T_dec × 3/37 × 0.001` ，单位 N·m，与 SDK `sendForce` 的 torque 参数一致。

## 4. 状态机：快速回退期间的力反馈处理

### 4.1 触发源

`axis1_fast_return` 和 `axis6_fast_retract` 这两个布尔位由 `main.cpp` 主循环的爬行/快退状态机置位，**仅在状态机阶段为 TRUE**：

- `axis1_fast_return`：导管模式下 axis1 进入 `SwitchWait / FastMove / RestoreWait` 三阶段时被置位。
- `axis6_fast_retract`：导丝模式或导管联动模式下 axis6 进入对应三阶段时被置位。
- 每个主循环开头都先清零，再在状态机内重新置位。
- 这两个位也会通过 ADS 写回 PLC（`G.axis1_fast_return` / `G.axis6_fast_retract`），用于下位机平滑旁路。

### 4.2 freeze\_582 机制

`ForceFeedbackState` 含 `freeze_582_active`、`freeze_582_f`、`freeze_582_n`。

- 进入快退（任一标志为 TRUE）：若 `freeze_582_active==false`，则把**进入时刻**的 `cal.f_feedback_n` / `cal.t_feedback_nm` 锁存到 freeze\_582\_\*，并设 `freeze_582_active=true`；后续整个快退阶段都使用这两个常数下发。
- 退出快退：`freeze_582_active=false`，恢复每拍实时映射。
- **副作用**：快退入口的一瞬采样如果本身已经失真（接触瞬间、夹爪切换等），冻结值就会"卡在一个错值"上；快退退出瞬间会从冻结值跳变到实时值，操作者会感到明显突变。

> 这正是用户提到的"快速回退阶段机器人力数据不准、要靠卡尔曼滤波让反馈连续"的痛点所在。

### 4.3 其他清零路径

- `ff.enabled = false` -> `ff.reset()` -> 双手柄输出 0。
- `freeze_active`（582 暂停键）-> 每拍 `clear_force_output()` 并清 ff。
- `estop_hold_active`（PLC 保持）-> 同上。
- `guidewire_mode != None`（导丝模式）-> 582 输出强制 0。
- `sample.valid == false`（无 TCP 帧）-> 输出 0，并触发"力反馈等待..."告警（限频 1Hz）。

### 5.1 解耦当前旁路，原矩阵仅保留为注释

```cpp
F_dec = F_cal;
```

### 5.4 `ForceSignalProcessor` 在 main 中未接入

`ForceSignalProcessor.h` 描述了一套尖峰检测 + 零位 EMA + 置信度的链路，但 `main.cpp` 没有声明 `ForceSignalProcessor` 实例，也没有在 `process_force_feedback` 前调用 `update`。`INTEGRATION_GUIDE.cpp` 给的只是接入指导。
**含义**：当前线上跑的是 raw 电压直接进 `calibrate_force` -> setforce\_axis，没有任何尖峰滤波、零位再跟踪、置信度。
**与本次卡尔曼方案的关系**：见 §6，新滤波器更接近原始信号，可以独立于 ForceSignalProcessor 接入。

## 6. Kalman 滤波接入方案（在 TCP 采集线程内）

### 6.1 目标

让"快速回退阶段被冻结的力反馈值"过渡到"快退结束后的实时值"时不出现阶跃，且在 TCP 偶发抖动 / 重连过程中输出可平滑外推。

### 6.2 选定接入点

**TcpForceDaqClient worker 线程，紧跟在** **`parse_response_to_voltage`** **之后、写入** **`latest_v_`** **之前。**

理由：

- 该线程是力数据的**最高频率源**（受网络/PLC 节拍约束，但远高于主控制环），在这里滤波获得最佳信噪比、相位延迟最小。
- `latest_v_` 是所有下游消费者（主循环采样、`force_logger`、`on_sample` 回调）的唯一入口；在此处过滤一次即可全链路受益。
- 与现有 `freeze_582_active` 机制解耦：力反馈输出层依旧保留"快退期冻结"逻辑做保险，但冻结对象会改成"卡尔曼滤波后的值"，离场更连续。

### 6.3 信号同步：fast\_move 状态如何到达 worker 线程

worker 在独立线程跑，不能直接读 `ForceFeedbackState`。需要新增一个**原子布尔**（或位掩码）由主线程写、worker 线程读：

```cpp
// tcp_force_daq.h (新增)
public:
    void set_fast_move_flag(bool active);  // 主线程在每拍调用，o(1) 原子写
private:
    std::atomic<bool> fast_move_flag_{false};
```

主循环中：

```cpp
const bool fast_move_active = axis1_fast_return || axis6_fast_retract;
tcp_force_daq.set_fast_move_flag(fast_move_active);
```

worker 线程在每解析完一帧后读 `fast_move_flag_.load(std::memory_order_relaxed)` 用于切换 Q/R。

### 6.4 滤波模型

针对 v\[0] / v\[1] 两路（fn\_1\_v / ft\_1\_v）分别建立独立 1D KF：

状态：`x = [value, value_rate]^T`\
模型：恒速度（匀变化率）\
A = `[[1, dt], [0, 1]]`，B = 0，H = `[1, 0]`

- `dt`：用相邻两帧 `GetTickCount64()` 差，clamp 到 \[1ms, 50ms]，避免长时间无帧时 dt 爆掉。
- 过程噪声 Q：
  ```
  Q_normal = diag(q_pos_normal^2, q_vel_normal^2)         // 慢速跟随
  Q_fast   = diag(q_pos_fast^2,   q_vel_fast^2)            // 快退/抖动时放大
  ```
- 测量噪声 R：
  ```
  R_normal = r_normal^2
  R_fast   = r_fast^2        // r_fast >> r_normal，让滤波器在 fast_move 期间几乎忽略测量、纯靠预测
  ```

切换规则：

- `fast_move_flag == true` -> 用 Q\_fast / R\_fast，等价"靠模型外推、忽略噪声测量"。
- `fast_move_flag` 由 true 翻 false 后维持几十毫秒过渡期 R 线性插值回 R\_normal，避免回切瞬间又跳变。

### 6.5 数据契约（最小侵入）

- worker 维护 `filtered_v_[6]`，初次帧 raw 直接复制为初始状态，之后每帧调用 `kf.update(raw)` 得到滤波值写入 `filtered_v_`。
- `get_latest_raw` **保持不变**（仍然返回未滤波电压，供 `force_logger` 写 CSV 真值用，便于后处理对比）。
- 新增 `bool get_latest_filtered(double out_v[6], std::uint64_t& ts) const;` 用于力反馈消费侧。
- `process_force_feedback` 改读 filtered，`force_logger` 保持读 raw。这样 CSV 里就同时拥有 raw 真值和"经过滤波的状态"（如果同时把 filtered 也加列，则更便于事后调参）。
- 推荐 CSV 加列：`ain0_filt_v, ain1_filt_v, kf_q_mode (0=normal/1=fast)`。

### 6.6 建议参数起点

> 这些值应在调参阶段以 CSV 回放为依据微调；以下仅作起点。

```
dt_typical ~ 5–20 ms（视实际 TCP 节拍）
q_pos_normal = 0.005 V       // 缓慢漂移容忍
q_vel_normal = 0.05 V/s
r_normal     = 0.01 V        // 实测电压噪声标准差量级，需从静止段 CSV 估
q_pos_fast   = 0.05 V        // 模型不确定性放大约 10x
q_vel_fast   = 0.5 V/s
r_fast       = 10.0 V        // 极大，等价忽略测量
```

`r_normal` 强烈建议从历史 `Force_sensor_*.csv` 的静止段经验估计：取一段 push\_pull\_code=0 且 rot\_sign\_code=0 的连续区间，对 `fn_1_raw_v / ft_1_raw_v` 计算样本方差，开方即得。

### 6.7 与现有 `freeze_582` 的关系

- 一阶段方案：保留 `freeze_582_active` 作为最后的安全网（KF 万一发散也不会让手柄抖）；KF 滤波后的电压只是"喂得更平滑"，freeze 仍然锁存进入瞬间的 cal.f\_feedback\_n，但因为 KF 已抹平了入口尖峰，锁存值更可信、退出瞬间的差也更小。
- 二阶段方案（验证 KF 稳定后再做）：把 freeze 改成"用 KF 在 fast\_move 期间的预测序列实时下发"，彻底取消硬冻结，实现"快退期间力反馈跟随机器人推理的虚拟力"。这一步要等 §6.4 的 Q\_fast/R\_fast 调到位之后再切换。

### 6.8 验收方法

1. 重新跑一组快进/快退操作，导出新版 CSV（含 raw + filtered + kf\_mode）。
2. 用 Python 脚本对比 `fn_1_raw_v` 和 `fn_1_filt_v` 在 fast\_move 边界（kf\_mode 0->1, 1->0）的差分，量化突变幅度。
3. 操作者主观评价：在不告知开关状态的情况下，对比是否仍能感到回退结束时刻的"顿一下"。
4. 把对比图（类似 `加入二阶滤波器整体.png` / `二阶滤波局部平滑.png`）归档到本目录。
