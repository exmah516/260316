## 1. 实验目的与判读

§6.1 的核心问题：**换手回退后器械摩擦重新加载产生的"力先升后平"现象，是位移相关还是速度/时间相关？**

判读法（§6.1 步骤 5）：
- 同一条接触条件下扫描 3–4 档进给速度，每档执行多次换手循环
- 同步记录力、**从端实际位移**、时间
- 画两幅图：`F vs 从端位移` 与 `F vs 时间`
- 若不同速度的"力-位移"曲线重叠 → **位移相关**
- 若随速度分离 → **速度/时间相关**

**横轴必须用从端编码器读数**（不可用主端指令位移）——统一专用表使用 PLC 快照计算的 `axis1_from_left_mm`。

## 2. 上位机操作步骤

### 2.1 启动顺序

1. 启动 C++ 主控（运行 `ADS.exe`，确保 `FLCatheter.dll` 与之同目录）
2. 启动 WPF UI（`AdsControlUI.exe`）。状态栏"连接"圆点应变绿
3. 在 UI 上完成：
   - **启动准备** 或 **直接控制 (C)** → 状态进入 `控制激活`
   - **零点采集** → `已标零` 显示 True
   - 力反馈开关可按实验目的选择；它不是状态机启动条件
   - 模式必须为 **导管递送** 或 **导管撤出**（实验目前只跑 axis1；guidewire_mode 必须为 0）

### 2.2 打开实验窗口

主窗口"力反馈"分组 → 点击 **"力过渡实验"** 按钮 → 弹出独立窗口（800×900）。

### 2.3 参数填写（左列）

| 参数 | 含义 | 推荐起点 |
|---|---|---|
| 档位数 N | 2–6 档速度 | 4 |
| 速度1..v6 (%) | 每档占 v_limit 的比例 | 25 / 50 / 75 / 100 |
| 每档重复 M | 每档完整试次数 | 3 |
| 起始位置 (mm) | axis1 每次试次开始位置（绝对坐标） | 10 |
| 推送目标 (mm) | axis1 推送终点（绝对坐标） | 70 |
| 回退触发 (mm) | 到达此位置触发 PLC 计划回退 | 85 |
| 接近速度比例 (%) | 拉到起点时的安全速度 | 20 |
| 档间静置 (ms) | 两试次之间、与档间的等待时间 | 1500 |

**几个不变量**（UI 会校验，不满足拒绝启动）：

- `起始位置 < 推送目标 ≤ 回退触发 ≤ 99 mm`
- 所有速度比例 1–150 %
- 档间静置 100–60000 ms

### 2.4 启动 / 停止

- 点击 **"开始实验"**：
  - C# 端先把参数全部下发到 C++（`SetFtExpParamA/B`），再发 `StartForceTransitionExperiment`
  - C++ 状态机做前置检查：`control_active && cal_zeroed && !freeze_active && !estop_hold && guidewire_mode == None && startup.completed`。失败原因会打印在控制台
  - 通过 → 状态机立即运行；若此刻“完整实验记录”已经开启，则在当前会话创建 `force_transition_001.csv`
- 实验自动按 `N × M` 次试次顺序执行，全部完成自动结束（状态变为 "已完成"）
- 中途点击 **"停止实验"** 或触发急停/暂停/掉离/标定丢失 → 立即 Abort，安全收尾（清 axis1 计划回退请求 + 还原 v_limit + 关闭专用 CSV）
- 中途只点击主界面的 **"停止实验记录"** → CSV/视频停止并封装，但力过渡状态机继续运行

### 2.5 右列实时观察

- **F vs t (秒)**：横轴是当前试次自 PushForward 开始的时间，纵轴是 `force_582_theory_f`（实时理论力，未受快退冻结影响）
- **F vs 从端位移 axis1 (mm)**：横轴是 `axis_pos[0]`，纵轴同上 —— 这就是 §6.1 判读的核心图
- 不同档位用不同颜色（最多 6 档）；跨试次保留所有曲线，便于直接看"族曲线是否重叠/分离"
- 重绘节流约 10 Hz，数据采集仍按管道节拍（约 30 Hz）
- 右上"清空"清除全部曲线；"导出 PNG" 分别导出 `_Ft.png` 与 `_Fx.png`

## 3. 实验状态机相位（用于排查）

| phase_code | 名称 | 行为 |
|---|---|---|
| 0 | Idle | 等 `start()` |
| 1 | ArmWait | 进入实验前的静置 |
| 2 | ApproachStart | 以接近速度把 axis1 拉到起始位置 |
| 3 | **PushForward** | 以当前档位速度推送至推送目标 — 主记录段 |
| 4 | ReachTriggerPos | 已到回退触发位，下发 PLC 计划回退 |
| 5 | FastReturn | 等 PLC 报告 `Done`（最多 15 s 超时） |
| 6 | ReturnWaitDone | 单拍：清 Req + 还原 v_limit |
| 7 | SettleHold | 试次间静置 |
| 8 | AdvanceTrial | 推进试次/档位计数 |
| 9 | Done | 全部完成 |
| 10 | Abort | 中止（安全收尾后） |

CSV 中 `phase_code` 字段与上表一致；切片时只取 3/4/5/6/7 这一段就是"完整换手循环"，其中 3 是真正的力过渡段。

## 4. CSV 字段与离线复绘

只有在力过渡开始瞬间统一记录已经运行时，才在当前会话创建 `force_transition_###.csv`。无统一会话时实验照常运行但不落专用表；统一会话中途开始时不补建残缺文件。

### 4.1 列表

```text
elapsed_us,valid,trial_id,velocity_level,repeat_in_level,
phase_code,phase_elapsed_ms,v_ratio,axis1_from_left_mm,
clean_force_n,clean_handle_torque_nm
```

- `elapsed_us` 与 `force.csv`、`motion.csv`、视频旁车共用会话 QPC 时间轴
- `phase_elapsed_ms` 是相对当前 phase 起点的毫秒
- `axis1_from_left_mm` 是从端实际位置 — 论文要求的横轴
- `clean_force_n / clean_handle_torque_nm` 只经过零点和固定标定比例，不受反馈门控/重力补偿/死区/限幅影响
- `valid=0` 时位置或纯净力无效，相应值写 `NaN`
- `phase_code` 见上表
- 一次完整扫描全部试次写在同一个 CSV 文件中

### 4.2 离线判读（Python 示例）

```python
import pandas as pd
import matplotlib.pyplot as plt

df = pd.read_csv(r"records\20260729\101500_session\force_transition_001.csv")

# 只看 PushForward 段（力过渡主记录段）
push = df[df.phase_code == 3].copy()

# 每次试次的 t 从 0 开始
push["t_s"] = push.groupby("trial_id")["phase_elapsed_ms"].transform(
    lambda x: (x - x.min()) / 1000.0)

# 按档位分色
fig, (ax_t, ax_x) = plt.subplots(1, 2, figsize=(12, 5))
for level, g in push.groupby("velocity_level"):
    # F vs t
    for trial_id, gt in g.groupby("trial_id"):
        ax_t.plot(gt.t_s, gt.clean_force_n, color=f"C{level}", alpha=0.5)
    # F vs 从端位移
    for trial_id, gx in g.groupby("trial_id"):
        ax_x.plot(gx.axis1_from_left_mm, gx.clean_force_n, color=f"C{level}", alpha=0.5)

ax_t.set(xlabel="t (s)", ylabel="clean force (N)", title="F vs t（族曲线分离 = 速度/时间相关）")
ax_x.set(xlabel="axis1 from-left (mm)", ylabel="clean force (N)", title="F vs 位移（族曲线重叠 = 位移相关）")
plt.tight_layout()
plt.show()
```

### 4.3 判读经验

- 若同档不同重复之间方差很大，先排查：装夹是否松动、循环泵是否开（水态下还有粘滞力）、零点是否漂
- 若不同档曲线在"F vs 位移"图上几乎重叠，但在"F vs t"图上明显分离 → **位移相关**，把这套数据回填到论文组件二
- 反之 → **速度/时间相关**，需要换建模

## 5. 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| 点击"开始实验"无反应，控制台打印"前置条件未满足" | 控制未激活 / 未标零 / 模式不是导管 / 启动准备未完成 | 按 §2.1 顺序完成；力反馈开关本身不是前置条件 |
| 实验启动后状态卡在 ApproachStart | axis1 当前位置距离 `起始位置` 太远 | 减小 `接近速度比例` 风险，或先手动把 axis1 拉到大致起点附近再启动 |
| 控制台打印 "axis_return timeout" | PLC 计划回退 15 s 未完成 | 检查 PLC 状态、急停、回退目标位置是否非法 |
| 控制台打印 "external freeze during push" | 推送过程中按了暂停 | 这是正常的安全中止；CSV 已落盘但试次不完整 |
| 控制台打印 "guidewire_mode changed" | 实验进行中切换到导丝模式 | 不要在实验期间切模式 |
| UI 曲线只画了一档颜色 | 只完成了一档；或档位数 N 填错 | 检查 N 与 v 比例 |
| 没有专用 CSV | 力过渡开始时统一实验记录尚未开启 | 先开始完整记录，再开始下一轮力过渡；中途开启不会补表 |
| CSV 文件存在但只有表头 | 实验刚启动就被立即终止，或完整记录随即停止 | 看控制台日志的 last_error 和 `session.json` |

## 6. 与现有控制系统的边界

实验期间状态机**只接管 axis1**：

- 接管 `pos[0]`（refer）、`v_limit[0]`、`axis1_fast_return` 三项
- 实验启动时读一次 PLC 的 7 元 v_limit 作为快照；实验结束时按快照还原
- 其他轴（axis2/3/4/5/6/7）、所有气缸、力反馈输出、UI 和统一记录器均沿用现有主循环逻辑
- 实验不直接动气缸——夹爪切换仍由主循环既有的"窗口边界 + CrawlState"动作链处理
- 实验全程力反馈下发到手柄（582）仍开启，便于操作者感知，但**实验判读不依赖手柄**
