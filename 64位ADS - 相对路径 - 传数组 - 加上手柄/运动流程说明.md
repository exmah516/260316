## 2. 坐标系约定

机器人共 7 个轴：

| 索引 | 角色 | 单位 | 备注 |
|---|---|---|---|
| 0 (axis1) | 导管线性 | mm | 主推/拉轴，物理 SN 587 手柄控制 |
| 1 (axis2) | 导管旋转 | deg | 跟随手柄旋转 |
| 2 (axis3) | 导管线性镜像 | mm | 跟随 axis1 平移 |
| 3 (axis4) | Y阀点动 | — | 仅 PLC 侧手动控制 |
| 4 (axis5) | 导管线性镜像 | mm | 跟随 axis1 平移 |
| 5 (axis6) | 导丝线性 | mm | 物理 SN 582 手柄控制 |
| 6 (axis7) | 导丝旋转 | deg | 跟随手柄旋转 |

**三套坐标基准**（容易混淆，务必区分）：

| 名称 | 基准 | 用途 | 字段 |
|---|---|---|---|
| **绝对坐标 abs** | PLC 机械原点 | PLC 内部、`G.axisN_return_cmd.TargetAbs`、窗口边界 `start_abs`/`end_abs`/`target_abs` | `plc_act_pos[i] + plc_init_pos[i]` |
| **相对坐标 rel** | `init_pos` | `G.refer`、`G.Act_pos` 的写入读出值 | `plc_act_pos[i]`、`pos[i]` |
| **from-left** | 左限位 | 监测/门控（如 axis3 投送停止位、axis6 入门门控） | `abs - leftlimit[i]` |

换算函数（`motion_sync`）：
```
from_left_to_abs(i, from_left_mm) = leftlimit[i] + from_left_mm
from_left_to_rel(i, from_left_mm) = from_left_to_abs(i, from_left_mm) - init_pos[i]
```

## 3. 窗口与跟随基准

### 3.1 axis1 爬行窗口（导管侧）

固定窗口，由 `ControlConfig` 决定：
```
axis1_window_left_from_left_mm  = 3.0   mm  (距左限位)
axis1_window_right_from_left_mm = 18.0  mm
```
窗口宽度 15 mm。`axis1_window_left_abs()` / `axis1_window_right_abs()` 输出绝对坐标边界。窗口边界**不随模式变化**，每次 `sync_axis1` / `sync_all` 都重置。

### 3.2 axis6 爬行窗口（导丝侧）

轴5相对窗口，进入独立/协同导丝模式时直接重建：
```
axis5_from_left_mm = axis5_abs - axis5_leftlimit
window_start_abs   = axis6_leftlimit + axis5_from_left_mm + axis6_window_min_gap_from_axis5_mm(6.0)
window_end_abs     = window_start_abs + axis6_window_size_mm(20.0)
```
因此窗口的 from-left 语义固定为 `[axis5 + 6, axis5 + 26]`，宽度 20 mm。

**窗口锁定机制**（`axis6_window_locked` + `axis6_locked_window_start/end_abs`）：
- 每次进入**独立导丝模式**时都按轴5当前实际位置直接重建并锁定，不再使用覆盖阈值判断；其快速回退和后续 `sync_axis6(..., rebuild_window=false, ...)` 继续复用锁定窗口。
- **协同递送与协同撤出**都不使用该固定边界：两个链路都处于 `Follow` 时，每拍按 axis5 的当期命令位置重建 `[axis5+6, axis5+26]` 窗口；进入、方向切换或回退恢复时的同步只负责重建初始基准。
- 导管模式 Follow 阶段轴6仍保持不动；仅在轴1触发快退、计算轴6反向联动目标时，按当时轴5实际位置建立同样的 `[axis5+6, axis5+26]` 边界并夹紧联动目标。

**axis6 上位机内部软限位（670 mm from-left）**：`axis6_abs - axis6_leftlimit` 允许等于 `670 mm`，但任何候选目标大于 `670 mm` 都会触发一次性锁止。检查覆盖 axis6 独立/协同 Follow 候选目标、axis6 自身计划回退终点，以及普通导管模式中 axis1 回退导致的 axis6 联动终点。普通导管回退会在切缸、进入 `SwitchWait` 和写 PLC `return_cmd` **之前**完成预测；预测越限时不触发该回退，不切换夹爪，并将 axis1/2/3/5/6/7 的 refer 保持在当前实际位置（axis4 独立手动链路不受影响）。锁止拍和后续锁止态会维持 cyl2/cyl4 夹紧、cyl1/cyl3 打开的稳定抓持组合。控制台与 WPF 都会给出警告，锁止不自动解除，需要现场安全处理后重启上位机并重新同步。该保护只存在于 C++ 上位机，不新增 PLC ADS 符号，也不替代 PLC/NC 硬限位。

### 3.3 axis1 跟随基准与镜像（capture_axis1_follow_baseline / apply_axis1_mirror_from_abs）

每拍在 `Follow` 阶段：
1. `axis1_crawl.handle_ref` / `rot_ref` 保存上一拍手柄线性/旋转滤波值；
2. `axis1_crawl.base_rel` = 当前 axis1 实际 rel；`axis1_crawl.rot_base_rel` = 当前 axis2 hold；
3. axis1 abs 目标 = `base_rel + (handle_now - handle_ref) × k_handle_to_mm × axis_push_sign`；
4. axis3 / axis5 镜像 axis1 的位移差（`apply_axis1_mirror_from_abs`）：`pos[2] = axis3_base_rel + (axis1_abs_cmd - init_pos[0] - axis1_crawl.base_rel)`，axis5 同；
5. 导管模式 Follow 阶段 axis6 保持在 `axis6_mirror_base_rel`，**不**镜像 axis1（注释明确说明这是设计决定）。

**镜像基准的初始化**：`sync_axis1` / `sync_all` 把 axis3/5/6 镜像基准都设为当前实际位置，避免基准陈旧导致突变。

## 4. 导丝模式（`guidewire_mode.cpp`）

### 4.1 模式枚举

```cpp
enum class GuidewireMode { None, Independent, Cooperative };
enum class CooperativeDirection { None, Delivery, Retraction };
```

- `None`：导管模式，物理 SN 587 控制 axis1/2/3/5；axis6/7 保持。
- `Independent`：导丝模式，物理 SN 582 控制 axis6/7；axis1/2/3/5 冻结（用 `independent_axisN_hold_rel` 锁存）。
- `Cooperative`：协同模式，物理 SN 587 控制 axis1 链路（含 axis3/5 镜像），物理 SN 582 控制 axis6/7；axis6 还会叠加 axis1 的位移增量（见 §7）。实际运动方向由独立的 `CooperativeDirection` 决定：`Delivery` 为双递送，`Retraction` 为双撤出。

### 4.2 进入门控（`check_axis6_guidewire_entry_gate`）

```cpp
axis6_abs = plc_act_pos[5] + plc_init_pos[5];
axis6_from_left_mm = |axis6_abs - leftlimit[5]|;
gate_passed = axis6_from_left_mm < guidewire_entry_axis6_from_left_max_mm (667.0);
```
即"axis6 必须距离左限位足够近才能进入导丝模式"。这是为了防止 axis6 处于撤出位置时进入导丝模式导致碰撞。

### 4.3 进入独立模式（`enter_independent_guidewire_mode`）

1. 读 PLC 当前实际位置；用 axis1/2/3/5 当前值填充 `independent_axisN_hold_rel`（后续主循环会把这些值写到 `pos[0..4]` 来冻结）；
2. 平均 20 个手柄样本重建 axis6 `handle_ref` / `rot_ref`；重置 axis6 滤波器与 prev 基准；
3. 调用 `rebuild_axis6_window_from_axis5`，直接按轴5当前实际位置建立并锁定 `[axis5+6, axis5+26]` 窗口；
4. axis6_crawl 全部字段重置为 Follow 阶段初始态；
5. `enabled = true`；
6. 写一帧 refer，axis1/2/3/5 锁在 hold 值，axis6/7 跟随当前实际。

### 4.4 进入协同模式（`enter_cooperative_guidewire_mode`）

协同方向只由 UI 显式请求：`SetCooperativeDelivery=19` 进入双递送，`SetCooperativeRetraction=23` 进入双撤出。物理 `SN 587` 始终承担导管/axis1 语义，物理 `SN 582` 始终承担导丝/axis6 语义；进入协同后两只手柄的 b0/b6 不再切换方向或模式。axis4 点动和电缸5保持原语义。

两种方向共用入口门控：两只手柄必须在 C++ 进程启动时均成功打开，启动准备完成且控制激活，无暂停/PLC 保持/ADS 回退故障/屈曲恢复/力过渡实验，axis1 与 axis6 均在 `Follow`，并且没有残留 PLC Busy 回退或协同换手拥有者。两者还必须满足 axis6 相对 axis5 位于 `[6,26] mm` 动态窗口内；仅**协同递送**额外要求 `axis6_from_left_mm < 667`，**协同撤出**不使用该门限。

通过后调用 `sync_cooperative_guidewire(ctx, 20, true)`，同时重建两只手柄滤波基准、axis1/axis6 命令基准、旋转保持位和 axis6 窗口。协同递送与协同撤出可一键切换，但切换前必须再次通过门控并完成同一次双手柄重同步；该同步拍不产生 `refer` 位移，操作者重新移动手柄后才按新方向运动。任一门控或同步失败会保留既有安全状态，并由后端快照校正 UI 选中项。

协同 `Follow` 阶段中，导管手柄控制 axis1/2/3/5，导丝手柄控制 axis6/7；axis6 本拍命令增量为“导丝手柄已接受的增量 + 已被 axis1 窗口和投送停止条件接受的导管增量”。两种方向的 axis6 窗口均按 axis5 的**命令**位置动态计算为 `[axis5+6, axis5+26] mm`，不是入口时的固定窗口。

协同换手采用串行仲裁 `CooperativeReturnOwner`：同一周期两轴都满足触发条件时 axis1 优先。拥有者处于 `SwitchWait/FastMove/RestoreWait` 时，另一条链路保持线性与旋转目标、丢弃手柄积压增量，也不会下发第二条 PLC `return_cmd`。拥有者回退完成或报错恢复后，调用 `sync_cooperative_guidewire(ctx, 3, false)` 再释放另一条链路；同步失败会停用上位机运动控制并清除协同请求。

协同期间沿用导丝模式的力反馈保护，两个物理手柄的力输出持续为零；退出回普通导管模式后才按既有力反馈开关和标零状态恢复。暂停、PLC 保持、自检重新开始、ADS 回退故障、屈曲恢复请求和力过渡实验启动都会清除协同请求，防止恢复后自动重入。高频力日志 `mode_code`：`0=导管`、`1=独立导丝`、`2=协同递送`、`3=协同撤出`。

### 4.5 退出（`exit_guidewire_mode_to_normal`）

1. 立即把 `*guidewire_mode = None`；
2. 清窗口锁定 / 协同 ff 增量缓存；
3. 读 PLC 当前 axis2/7 实际值刷新 hold（避免陈旧 hold 让 axis2 偶发回零）；
4. 调用 `sync_axis1` 重建 axis1 链路基准（窗口、镜像基准、axis1_handle_filter）。

### 4.6 触发源

- 双手柄：物理 SN 582 上的 b6/b0 保持原独立导丝模式及方向语义；协同递送和协同撤出期间这些按键不切换模式或方向。
- 单手柄：键盘 `1`/`2` 切换导管/导丝角色（`single_handle_requested_mode`）。
- UI：`VisCommand::SetReverseMode` / `RequestModeSwitch` / `SetCooperativeDelivery(19)` / `SetCooperativeRetraction(23)`；普通四个模式按钮会明确退出协同请求。
- 反向键：独立模式下 b0=1 时 `axis6_effective_reverse_pressed=true`，决定爬行方向（正向输送 vs 反向取出）。

## 5. 启动准备序列（`startup_sequence.cpp` + `main.cpp` 状态机）

### 5.1 阶段枚举

```cpp
enum class StartupPhase {
    WaitForEnter,            // 等待用户选择
    ReleaseClamps,           // 阶段1：打开全部夹爪
    MoveAxis56ToLeftReady,   // 阶段2：1/5/6 走到左限位附近的准备点
    ClampCylinder34Wait,     // 阶段3：闭合导丝侧夹爪对 cyl3/cyl4
    MoveAxis356BackToReady,  // 阶段4：按 UI 最终目标移动 1/2/3/5/6/7
    ClampCylinder2AfterAxis3,// 阶段5：在 axis3 到位后闭合 cyl2
    Done                     // 完成
};
```

### 5.2 入口（`start_startup_sequence`）

1. 读 PLC 当前实际位置；锁存 axis1/3/5/6/7 的 hold 基准；
2. 如果 `v_limit_scaled == false`：读当前 `v_limit` 并备份；轴 1/3/5/6 统一取四轴基础上限中的最小值作为共同基准，再乘 `startup_motion_speed_scale` 后写回 PLC，确保四轴限速数值一致且不会抬高任一轴原上限；轴 2/7 仍按各自基础上限乘比例。UI 默认比例为 `0.03`，未经过 UI 提交时配置结构的回退初值为 `0.005`；
3. 切到 `ReleaseClamps` 阶段。

### 5.3 各阶段动作（`main.cpp` 主循环步骤 11 内 startup_sequence 分支）

| 阶段 | 气缸指令 | 轴目标 | 完成条件 |
|---|---|---|---|
| `ReleaseClamps` | 全部开（cyl1/2 open + cyl3=500,cyl4=0） | 维持当前 hold | 经过 `startup_clamp_settle_delay_ms(300ms)` |
| `MoveAxis56ToLeftReady` | 同上 | axis1->startup_axis1_ready_from_left_mm(20mm)；axis5->startup_axis5_ready_from_left_mm(290mm)；axis6-> axis5+axis56_ready_gap_mm(310mm) | 1/5/6 三轴都到容差内；锁存 axis1 阶段2值 |
| `ClampCylinder34Wait` | cyl3=50,cyl4=500（夹紧） | axis5/6 保持准备点 | 经过 300ms |
| `MoveAxis356BackToReady` | 同阶段3 | 按 `startup.final_axisN_from_left_mm`（UI 参数）移动 1/2/3/5/6/7 | 全部到容差内（含 axis2/7 角度容差 0.2 deg） |
| `ClampCylinder2AfterAxis3` | cyl2=600（夹） | 同阶段4 | 经过 300ms 且全部到位 |
| `Done` | 恢复正常导管模式气缸 | `restore_startup_v_limit` 恢复速度上限 -> `sync_all(30)` 重同步 -> `control_active=true` | — |

### 5.4 速度限制恢复（`restore_startup_v_limit`）

如果 `v_limit_scaled == true`，把备份的原速度上限写回 PLC，标志位置 false。
**重要**：阶段4->5 切换时（PLC 自检完成后）也会调用一次，避免启动期速度被永久压制。

### 5.5 触发路径

- 键盘 `S`：调用 `start_startup_sequence`（需 `startup.completed==false && phase==WaitForEnter`）。
- UI `ExecuteStartup`：参数校验（轴位置范围、相对关系、速度范围）通过后，把 `pending_startup` 写到 `startup.final_*`，再调用 `start_startup_sequence`。
- 键盘 `C` / UI `SelectDirectControl`：跳过启动准备，直接 `restore_startup_v_limit` + `sync_all(20)` -> `Done`。**直接控制模式**适合已经手动装夹到位的场景。

### 5.6 启动期平滑旁路

`startup_smoothing_bypass` 在 `startup.is_active()` 时每拍写 `G.startup_smoothing_bypass = true`，告诉 PLC 当前处于启动期、用更宽松的平滑策略。退出后写 false。

### 5.7 手动屈曲恢复（机构间距恢复）

该模式仅由 WPF 的“屈曲恢复”开关显式启停，不做位置判断或自动触发。进入条件为：启动完成、控制激活、普通导管递送、axis1/axis6 均处于 Follow、无计划回退、无急停/暂停/ADS 故障、无力过渡实验。

- 进入时按实际位置锁存 axis1/2/7，axis3/5/6 以各自实际位置作为共同移动起点；
- 电缸1保持打开、电缸2保持夹紧、电缸3写 `cyl3_open`、电缸4写 `100`，等待 `spacing_recovery_clamp_settle_ms(150ms)` 后允许运动；
- 导管语义手柄（物理 SN 587）没有中位，继续使用既有的相邻采样位移差分；仅接受使 from-left 增大的手柄增量，反方向增量丢弃；
- axis3/5/6 每拍叠加完全相同的位移，命令侧速度限制为 `20mm/s`，停止推拉手柄后不继续追赶积压目标；
- 共同可用行程取 axis3/5/6 到各自安全上限（650/670/670mm from-left）的最小值，并要求 axis6-axis5 仍处于 `[6,26]mm` 窗口；
- 恢复期间屏蔽普通模式切换、轴4点动、电缸手动覆盖和导管力反馈；
- 退出时先保持最终目标，等待 axis3/5/6 进入 `0.2mm` 容差并稳定至少 `100ms`（最长等待 `2s`），再调用 `sync_all(20)` 按当前实际位置重建跟随基准；axis3 已离开投送停止区时同时解除投送停止锁存。

## 6. axis1 爬行状态机（`main.cpp` 步骤 11 内常规导管/协同分支；2026-06-26 行号约 L1730-L2140）

### 6.1 阶段

```cpp
enum class CrawlState::Phase {
    Follow,        // 跟随手柄
    SwitchWait,    // 触发快退后的夹爪切换等待
    FastMove,      // 计划回退运动中
    SettleHold,    // (当前未使用，保留)
    ClampWait,     // (当前未使用，保留)
    RestoreWait    // 回退完成后的夹爪恢复等待
};
```

### 6.2 Follow 阶段

1. 计算 axis1 线性增量：`(handle_filtered - prev_handle_filtered) × k_handle_to_mm(750) × axis_push_sign(-1)`；
2. 死区过滤：`|increment| < linear_increment_noise_deadband_mm(0.02)` 时置 0；
3. `axis1_cmd_abs = clamp(axis1_follow_cmd_abs + increment, window_left, window_right)`；
4. 触发保护：
   - `axis1_push_rearm_after_hold`：PLC 保持刚解除，必须反向拉一下才能继续推送（防误推）；
   - `axis1_delivery_stop_latched`：axis3 到达投送停止位（距左限位 ≤ 20mm）后，正向推送被锁；必须切换反向模式才能继续；
   - `axis1_reverse_switch_guard_active`：刚切换正反向时若距离触发边太近，临时锁触发（防抖）；
5. 触发快退条件（`axis1_ready_to_trigger`）：
   - 有有效增量；
   - 增量方向朝向触发边（正向时朝右、反向时朝左）；
   - 跟随未禁用；
   - 进入触发边容差内（`crawl_arrive_tol_mm(0.2)`）；
   - 不被反向切换保护阻塞；
6. 触发动作：
   - 设置 target_abs（反向 -> window_left；正向 -> window_right）；
   - 锁存 `axis1_return_entry_rel` / `axis1_return_settle_rel` / `axis1_return_hold_axis3/5_rel` / `axis6_fast_entry_abs` / `axis6_coupled_settle_rel`；
   - 若导管模式（非协同），先计算 `axis6_coupled_target_raw_abs = axis6_fast_entry_abs - (axis1_target_abs - axis1_fast_entry_abs)`，再把目标限制在按当时 axis5 实际位置得到的 `[axis5+6, axis5+26]` 窗口内；随后检查最终夹紧后的目标是否大于 axis6 的 `670 mm from-left` 上位机软限位；
   - 只有预测安全时才进入 SwitchWait 阶段并开始错峰切缸（见 §8）；预测越限则不发任何 axis1/axis6 PLC 回退请求，相关导管/导丝链路锁止在实际位置。

### 6.3 SwitchWait 阶段（错峰切缸 + 夹爪预紧）

- 等待 `axis1_cylinder_interstep_wait_ms(50ms)` + `axis1_pre_move_cylinder_wait_ms(100ms)`；
- 若 axis6 联动（`axis6_coupled_active`），取 axis1 和 axis6 两个等待时间的最大值；
- axis1_fast_return = true（每拍置位）；axis6_fast_retract = true（联动时）；
- 镜像轴 3/5 用 `axis1_return_hold_axis3/5_rel` 锁住。

### 6.4 FastMove 阶段（PLC 计划回退）

- `pos[0] = target_abs - init_pos[0]`（让 refer 跟随 target_abs）；
- 首次进入时 `request_axis_return(AdsSymbol::axis1_return, target_abs, vel, acc, dec, jerk)`；
- 联动时 axis6 也走 `request_axis_return(AdsSymbol::axis6_return, axis6_coupled_target_abs, ...)`；
- 每拍轮询 `read_axis_return_status`；
- 完成条件：`axis1_return_status.done` +（联动时）`axis6_coupled_done`；或位置进入容差；
- 出错处理：清回退请求 + 单轴 `sync_axis1(3, false, 0)` + 回到 Follow。

### 6.5 RestoreWait 阶段（错峰切缸 + 夹爪恢复）

- 等待 `axis1_post_return_cylinder_wait_ms(100ms)` + `axis1_cylinder_interstep_wait_ms(50ms)`；
- 角色互换：cyl2 先合，cyl1 后开（与 SwitchWait 相反）；
- 完成后 `sync_axis1(3, false, 0)` 重建跟随基准 -> 回到 Follow。

### 6.6 普通导管递送的 axis1 回退后单独先行

该功能常开，只作用于普通导管**正向递送**（非独立导丝、非协同、非撤出）的 axis1 计划回退成功完成后。WPF 的“轴1回退后先行”输入通过 `SetAxis1PostReturnLead=24` 写入，单位为 mm，范围 `[-10, 10]`，默认 `+1.0 mm`；正值表示递送方向（axis1 绝对坐标减小），负值表示反向。

RestoreWait 成功执行 `sync_axis1(3)` 后，控制器只武装一次先行，不立即产生运动。下一次检测到有效递送方向手柄增量时，axis1 先单独走到“回退后的当前 axis1 目标减去先行量”的窗口内终点；此阶段 axis3/5/6 与 axis2/7 都保持当期实际位置，不调用 `apply_axis1_mirror_from_abs`。达到终点后再次执行 `sync_axis1(3)`，重建手柄、axis1 与镜像轴基准，并丢弃先行期间的手柄积压增量，下一拍才恢复正常 Follow。

该先行不绕过原有 axis3 投送停止位；若已经到达投送停止位、先行量为零或窗口内无可用行程，本次武装会被取消而不运动。暂停、PLC hold、ADS 回退故障、屈曲恢复、力过渡实验、启动准备、模式/方向切换和 axis6 软件限位锁止都会取消尚未完成的先行。

## 7. axis6 爬行状态机（`main.cpp` 步骤 11 内 `run_axis6_crawl_state` lambda，独立/协同模式共用；2026-06-26 行号约 L1400-L1560）

axis6 的状态机由 `run_axis6_crawl_state` lambda 封装，独立模式和协同模式共用。与 axis1 状态机的关键差异：

### 7.1 独立模式

- axis1/2/3/5 全部冻结在 `independent_axisN_hold_rel`；
- axis6 线性增量直接来自物理 SN 582 手柄；
- `require_user_increment_for_trigger = false`（即使操作者不推手柄，到达窗口边也能触发快退）；
- 错峰切缸用 cyl3/cyl4（而不是 cyl1/cyl2）。

### 7.2 协同模式

- `CooperativeDirection::Delivery` 固定为双递送，`CooperativeDirection::Retraction` 固定为双撤出；两种方向均忽略手柄模式/方向按键；
- axis1 链路正常工作（当前协同方向的导管跟随/换手）；
- axis6 的"用户增量"叠加 axis1 已接受的命令位移增量：`axis6_combined_increment = SN582_increment + axis1_increment`；
- `axis6_coop_ff_inited` / `axis6_coop_prev_axis1_cmd_abs` 用于 axis1 增量的差分计算；
- axis6 处于快退阶段时 axis1 增量被忽略（`axis6_coop_ff_inited = false`）；
- `require_user_increment_for_trigger = true`（要求物理 SN 582 本人必须有有效增量才能触发反弹，避免 axis1 推送意外触发 axis6 回退）。

### 7.3 axis6 状态机阶段

与 axis1 相同的四阶段（Follow / SwitchWait / FastMove / RestoreWait），但快退请求是 `AdsSymbol::axis6_return`，错峰切缸用 cyl3/cyl4。

### 7.4 主从位移实验记录与受限 PI 补偿

该实验模块仅覆盖普通导管**正向**递送的 axis1，以及独立导丝**正向**递送的 axis6；不接入协同递送、撤出或 PLC 运动逻辑。上位机进程启动时会自动创建一个 `20 Hz` 记录会话并写入 `MasterSlaveTracking_YYYYMMDD_HHMMSS.csv`，不需要在 UI 中先点击“开始记录”。导管侧只有在 `cylinder2_cmd == cyl2_clamp` 且 `cylinder1_cmd == cyl1_open` 连续 150 ms 时，导丝侧只有在 `cylinder4_cmd == cyl4_clamp` 且 `cylinder3_cmd == cyl3_open` 连续 150 ms 时，才建立对应 Follow 实验段。这里是命令级“已夹持”假设，不是物理到位反馈。

每段从当前手柄、实际轴位置和 refer 重建锚点；会话累计跨段保留，而段累计不会把夹爪切换、计划回退或手柄积压位移算作器械前进。CSV 同步记录手柄增量、标称/补偿/最终命令、PI 项、refer/实际位置、电缸命令、力采样和安全失效原因。

`tracking_error_mm` 的语义是**尚未补偿的换手前向欠账**，不是普通 Follow 段中“标称手柄累计量减实际轴累计量”的差。正向递送进入 `SwitchWait/FastMove/RestoreWait` 或其夹爪恢复期后，医生仍继续前推产生的映射位移会累计为欠账；为恢复行程而回拉手柄时不产生负欠账，也不会抵消已有欠账。欠账默认和硬上限均为 `20 mm`（WPF 可下调但不能超过该上限）；超过上限的原始前推量仍写 CSV，但不再进入待补队列。

补偿默认关闭，默认 `Kp=Ki=0`。换手期间冻结 PI，但保留欠账；恢复有效 `Follow` 段后，只要医生仍有新的正向输入，就将**当前已接受的标称增量**按受限 PI 增益有限放大，跨后续多个正向输入逐步偿还欠账。实际轴位移先结算普通标称命令，只有经确认的额外前进才扣减欠账，避免通信/伺服滞后造成重复补偿。松手、静止或回拉时不追赶，绝不自动反向。输出仍必须经过原窗口、投送停止、速度限制、PLC 平滑和计划回退链路；窗口/停止条件夹紧输出时冻结积分。

暂停、PLC hold、ADS 回退故障、屈曲恢复、力过渡实验、手动电缸覆盖、启动准备、撤出和模式切换会自动关闭补偿并清除欠账，且不自动恢复。参数只能在补偿关闭时通过 WPF 提交；内部仍有最大增益、欠账上限、积分量和单拍额外位移上限，不能靠 UI 突破。

## 8. 气缸错峰切换（`staggered_pair` lambda）

每对夹爪在快退切换瞬间不能同时打开/闭合，否则器械会瞬间双开释放。`staggered_pair` 的语义：

```cpp
staggered_pair(close_cmd, close_val, open_cmd, open_val, seq_t0, stagger_ms):
    close_cmd = close_val;                              // 立即下发 close 侧
    if (now_ms - seq_t0 >= stagger_ms):
        open_cmd = open_val;                            // 经过 stagger_ms 后才下发 open 侧
```

- axis1 链路使用 `axis1_cylinder_interstep_wait_ms(50ms)`；
- axis6 链路使用 `axis6_cylinder_interstep_wait_ms(50ms)`；
- 联动时取两侧较大值；
- `seq_t0` 在进入新阶段时刷新为 `now_ms`。

典型用法（axis1 SwitchWait 阶段）：
```cpp
staggered_pair(cylinder1_cmd, cyl.cyl1_clamp,    // cyl1 立即夹
               cylinder2_cmd, cyl.cyl2_open,     // cyl2 等 50ms 后开
               axis1_crawl.cyl_seq_t0, cfg.axis1_cylinder_interstep_wait_ms);
```

## 9. 已知问题 / 待确认点

### 9.1 axis6 右侧窗口余量

窗口右边界固定为 `axis5_from_left + 26mm`，当前上位机没有读取 PLC 内部 `right_slimit` 做二次裁剪。按启动默认 axis5=660mm，窗口为 `[666,686]mm`；PLC axis6 当前右软件限位为距左限位 688mm，仅余 2mm。若后续提高 axis5 位置，必须同步核对右软件限位余量。

### 9.2 `CrawlState::SettleHold` / `ClampWait` 阶段当前未使用

枚举里保留了 `SettleHold` 和 `ClampWait`，但主循环没有 case 分支处理。如果未来需要在 FastMove 和 RestoreWait 之间插入新的等待阶段，可以启用；现在不要把它们误当作"活跃阶段"。

### 9.3 `cooperative_mode` 与 axis1 快退耦合

导管模式（非协同）下 axis1 快退时 axis6 会镜像反向快进（`axis6_coupled_active = true`）。协同模式下相反：axis1 快退时 axis6 **不**联动（`axis6_coupled_active = false`，在步骤 11 的"触发动作"代码块内，配合 `if (!cooperative_mode)` 分支判断，2026-06-26 行号约 L1840-L1860）。这是为了让协同模式下导丝和导管的快退独立触发。修改这个逻辑前务必理解现场工艺。

### 9.4 `reverse_switch_trigger_guard_mm` 是软保护

正反向切换瞬间，若 axis 实际位置距离新的触发边太近（≤ 2.0mm），会拉起 `reverse_switch_guard_active`，阻止该次切换立即触发快退。需要 axis 离开 2mm 后才允许触发。这是为了防止"在窗口边缘反复横跳导致连续触发"。

### 9.5 `startup.final_axis6_from_left_mm` 默认 = axis5 + gap

`main.cpp` 主循环前段（绑定 startup 上下文段，2026-06-26 行号约 L419）初始化 `startup.final_axis6_from_left_mm = cfg.startup_axis5_ready_from_left_mm + cfg.axis56_ready_gap_mm`。但 UI 可以单独设 axis6（`SetStartupAxisPos` case 6）。如果 UI 设的 axis6 比 axis5 小，会触发参数校验失败（`valid = false`）。**这是有意的**——避免导丝轴被设到导管轴后面。
