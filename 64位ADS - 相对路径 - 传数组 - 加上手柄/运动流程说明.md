## 2. 坐标系约定

机器人共 7 个轴：

| 索引 | 角色 | 单位 | 备注 |
|---|---|---|---|
| 0 (axis1) | 导管线性 | mm | 主推/拉轴，582 手柄控制 |
| 1 (axis2) | 导管旋转 | deg | 跟随手柄旋转 |
| 2 (axis3) | 导管线性镜像 | mm | 跟随 axis1 平移 |
| 3 (axis4) | Y阀点动 | — | 仅 PLC 侧手动控制 |
| 4 (axis5) | 导管线性镜像 | mm | 跟随 axis1 平移 |
| 5 (axis6) | 导丝线性 | mm | 587 手柄控制 |
| 6 (axis7) | 导丝旋转 | deg | 跟随手柄旋转 |

**三套坐标基准**（容易混淆，务必区分）：

| 名称 | 基准 | 用途 | 字段 |
|---|---|---|---|
| **绝对坐标 abs** | PLC 机械原点 | PLC 内部、`G.axisN_return_cmd.TargetAbs`、窗口边界 `start_abs`/`end_abs`/`target_abs` | `plc_act_pos[i] + plc_init_pos[i]` |
| **相对坐标 rel** | `init_pos` | `G.refer`、`G.Act_pos` 的写入读出值 | `plc_act_pos[i]`、`pos[i]` |
| **from-left** | 左限位 | 监测/门控（如 axis3 投送停止位、axis6 入门门控） | `abs - leftlimit[i]` |

换算函数（`motion_sync`）：
```
from_left_to_abs(i, from_left_mm) = leftlimit[i] + from_left_mm
from_left_to_rel(i, from_left_mm) = from_left_to_abs(i, from_left_mm) - init_pos[i]
```

## 3. 窗口与跟随基准

### 3.1 axis1 爬行窗口（导管侧）

固定窗口，由 `ControlConfig` 决定：
```
axis1_window_left_from_left_mm  = 3.0   mm  (距左限位)
axis1_window_right_from_left_mm = 18.0  mm
```
窗口宽度 15 mm。`axis1_window_left_abs()` / `axis1_window_right_abs()` 输出绝对坐标边界。窗口边界**不随模式变化**，每次 `sync_axis1` / `sync_all` 都重置。

### 3.2 axis6 爬行窗口（导丝侧）

动态窗口，进入独立/协同导丝模式时建立：
```
shifted_window_right_abs = axis6_current_abs + axis6_window_shift_from_left_mm(3.0)
requested_left_abs       = shifted_window_right_abs - axis6_independent_window_size_mm(20.0)
clamped_left_abs         = max(requested_left_abs, leftlimit[5])
```
窗口宽度默认 20 mm，可平移。

**窗口锁定机制**（`axis6_window_locked` + `axis6_locked_window_start/end_abs`）：
- 进入导丝模式后窗口被锁定，避免后续 axis6 实际位置漂移导致窗口被反复重建。
- `rebuild_axis6_window_if_covered`：当 axis6 远端距 axis5 当前位置小于 `axis6_window_cover_threshold_mm (18.0)` 时（即 axis5 已"压住"了窗口远端），按 axis5 当前位置重建窗口，并重新锁定。这是为了避免 axis5 跟着 axis1 推进后挤压 axis6 的活动空间。

### 3.3 axis1 跟随基准与镜像（capture_axis1_follow_baseline / apply_axis1_mirror_from_abs）

每拍在 `Follow` 阶段：
1. `axis1_crawl.handle_ref` / `rot_ref` 保存上一拍手柄线性/旋转滤波值；
2. `axis1_crawl.base_rel` = 当前 axis1 实际 rel；`axis1_crawl.rot_base_rel` = 当前 axis2 hold；
3. axis1 abs 目标 = `base_rel + (handle_now - handle_ref) × k_handle_to_mm × axis_push_sign`；
4. axis3 / axis5 镜像 axis1 的位移差（`apply_axis1_mirror_from_abs`）：`pos[2] = axis3_base_rel + (axis1_abs_cmd - init_pos[0] - axis1_crawl.base_rel)`，axis5 同；
5. 导管模式 Follow 阶段 axis6 保持在 `axis6_mirror_base_rel`，**不**镜像 axis1（注释明确说明这是设计决定）。

**镜像基准的初始化**：`sync_axis1` / `sync_all` 把 axis3/5/6 镜像基准都设为当前实际位置，避免基准陈旧导致突变。

## 4. 导丝模式（`guidewire_mode.cpp`）

### 4.1 模式枚举

```cpp
enum class GuidewireMode { None, Independent, Cooperative };
```

- `None`：导管模式，582 控制 axis1/2/3/5；axis6/7 保持。
- `Independent`：导丝模式，587 控制 axis6/7；axis1/2/3/5 冻结（用 `independent_axisN_hold_rel` 锁存）。
- `Cooperative`：协同模式，582 控制 axis1 链路（含 axis3/5 镜像），587 控制 axis6/7；axis6 还会叠加 axis1 的位移增量（见 §7）。

### 4.2 进入门控（`check_axis6_guidewire_entry_gate`）

```cpp
axis6_abs = plc_act_pos[5] + plc_init_pos[5];
axis6_from_left_mm = |axis6_abs - leftlimit[5]|;
gate_passed = axis6_from_left_mm < guidewire_entry_axis6_from_left_max_mm (665.0);
```
即"axis6 必须距离左限位足够近才能进入导丝模式"。这是为了防止 axis6 处于撤出位置时进入导丝模式导致碰撞。

### 4.3 进入独立模式（`enter_independent_guidewire_mode`）

1. 读 PLC 当前实际位置；用 axis1/2/3/5 当前值填充 `independent_axisN_hold_rel`（后续主循环会把这些值写到 `pos[0..4]` 来冻结）；
2. 平均 20 个手柄样本重建 axis6 `handle_ref` / `rot_ref`；重置 axis6 滤波器与 prev 基准；
3. 设置/恢复 axis6 窗口（`set_axis6_independent_window` -> `lock_axis6_window_from_current` -> `rebuild_axis6_window_if_covered`）；
4. axis6_crawl 全部字段重置为 Follow 阶段初始态；
5. `enabled = true`；
6. 写一帧 refer，axis1/2/3/5 锁在 hold 值，axis6/7 跟随当前实际。

### 4.4 进入协同模式（`enter_cooperative_guidewire_mode`）

直接 `sync_axis6(ctx, 20, capture_window=true, ..., check_window_cover=true, log_window_cover=true)`。**比独立模式简化**，因为协同模式下 axis1 链路继续工作，不需要冻结 axis1/3/5。

### 4.5 退出（`exit_guidewire_mode_to_normal`）

1. 立即把 `*guidewire_mode = None`；
2. 清窗口锁定 / 协同 ff 增量缓存；
3. 读 PLC 当前 axis2/7 实际值刷新 hold（避免陈旧 hold 让 axis2 偶发回零）；
4. 调用 `sync_axis1` 重建 axis1 链路基准（窗口、镜像基准、axis1_handle_filter）。

### 4.6 触发源

- 双手柄：587 上的 b6（独立模式）/ b0（协同键，但本轮已取消协同入口）。
- 单手柄：键盘 `1`/`2` 切换导管/导丝角色（`single_handle_requested_mode`）。
- UI：`VisCommand::SetReverseMode` / `RequestModeSwitch`。
- 反向键：独立模式下 b0=1 时 `axis6_effective_reverse_pressed=true`，决定爬行方向（正向输送 vs 反向取出）。

## 5. 启动准备序列（`startup_sequence.cpp` + `main.cpp` 状态机）

### 5.1 阶段枚举

```cpp
enum class StartupPhase {
    WaitForEnter,            // 等待用户选择
    ReleaseClamps,           // 阶段1：打开全部夹爪
    MoveAxis56ToLeftReady,   // 阶段2：1/5/6 走到左限位附近的准备点
    ClampCylinder34Wait,     // 阶段3：闭合导丝侧夹爪对 cyl3/cyl4
    MoveAxis356BackToReady,  // 阶段4：按 UI 最终目标移动 1/2/3/5/6/7
    ClampCylinder2AfterAxis3,// 阶段5：在 axis3 到位后闭合 cyl2
    Done                     // 完成
};
```

### 5.2 入口（`start_startup_sequence`）

1. 读 PLC 当前实际位置；锁存 axis1/3/5/6/7 的 hold 基准；
2. 如果 `v_limit_scaled == false`：读当前 v_limit 备份，乘以 `startup_motion_speed_scale` (默认 0.005) 得到缩放后的 v_limit 写回 PLC（让启动期运动速度极慢）；
3. 切到 `ReleaseClamps` 阶段。

### 5.3 各阶段动作（`main.cpp` L1542-L1633）

| 阶段 | 气缸指令 | 轴目标 | 完成条件 |
|---|---|---|---|
| `ReleaseClamps` | 全部开（cyl1/2 open + cyl3=500,cyl4=0） | 维持当前 hold | 经过 `startup_clamp_settle_delay_ms(300ms)` |
| `MoveAxis56ToLeftReady` | 同上 | axis1->startup_axis1_ready_from_left_mm(20mm)；axis5->startup_axis5_ready_from_left_mm(290mm)；axis6-> axis5+axis56_ready_gap_mm(310mm) | 1/5/6 三轴都到容差内；锁存 axis1 阶段2值 |
| `ClampCylinder34Wait` | cyl3=50,cyl4=500（夹紧） | axis5/6 保持准备点 | 经过 300ms |
| `MoveAxis356BackToReady` | 同阶段3 | 按 `startup.final_axisN_from_left_mm`（UI 参数）移动 1/2/3/5/6/7 | 全部到容差内（含 axis2/7 角度容差 0.2 deg） |
| `ClampCylinder2AfterAxis3` | cyl2=600（夹） | 同阶段4 | 经过 300ms 且全部到位 |
| `Done` | 恢复正常导管模式气缸 | `restore_startup_v_limit` 恢复速度上限 -> `sync_all(30)` 重同步 -> `control_active=true` | — |

### 5.4 速度限制恢复（`restore_startup_v_limit`）

如果 `v_limit_scaled == true`，把备份的原速度上限写回 PLC，标志位置 false。
**重要**：阶段4->5 切换时（PLC 自检完成后）也会调用一次，避免启动期速度被永久压制。

### 5.5 触发路径

- 键盘 `S`：调用 `start_startup_sequence`（需 `startup.completed==false && phase==WaitForEnter`）。
- UI `ExecuteStartup`：参数校验（轴位置范围、相对关系、速度范围）通过后，把 `pending_startup` 写到 `startup.final_*`，再调用 `start_startup_sequence`。
- 键盘 `C` / UI `SelectDirectControl`：跳过启动准备，直接 `restore_startup_v_limit` + `sync_all(20)` -> `Done`。**直接控制模式**适合已经手动装夹到位的场景。

### 5.6 启动期平滑旁路

`startup_smoothing_bypass` 在 `startup.is_active()` 时每拍写 `G.startup_smoothing_bypass = true`，告诉 PLC 当前处于启动期、用更宽松的平滑策略。退出后写 false。

## 6. axis1 爬行状态机（`main.cpp` L1669-L2070，导管模式/协同模式）

### 6.1 阶段

```cpp
enum class CrawlState::Phase {
    Follow,        // 跟随手柄
    SwitchWait,    // 触发快退后的夹爪切换等待
    FastMove,      // 计划回退运动中
    SettleHold,    // (当前未使用，保留)
    ClampWait,     // (当前未使用，保留)
    RestoreWait    // 回退完成后的夹爪恢复等待
};
```

### 6.2 Follow 阶段

1. 计算 axis1 线性增量：`(handle_filtered - prev_handle_filtered) × k_handle_to_mm(750) × axis_push_sign(-1)`；
2. 死区过滤：`|increment| < linear_increment_noise_deadband_mm(0.02)` 时置 0；
3. `axis1_cmd_abs = clamp(axis1_follow_cmd_abs + increment, window_left, window_right)`；
4. 触发保护：
   - `axis1_push_rearm_after_hold`：PLC 保持刚解除，必须反向拉一下才能继续推送（防误推）；
   - `axis1_delivery_stop_latched`：axis3 到达投送停止位（距左限位 ≤ 20mm）后，正向推送被锁；必须切换反向模式才能继续；
   - `axis1_reverse_switch_guard_active`：刚切换正反向时若距离触发边太近，临时锁触发（防抖）；
5. 触发快退条件（`axis1_ready_to_trigger`）：
   - 有有效增量；
   - 增量方向朝向触发边（正向时朝右、反向时朝左）；
   - 跟随未禁用；
   - 进入触发边容差内（`crawl_arrive_tol_mm(0.2)`）；
   - 不被反向切换保护阻塞；
6. 触发动作：
   - 设置 target_abs（反向 -> window_left；正向 -> window_right）；
   - 锁存 `axis1_return_entry_rel` / `axis1_return_settle_rel` / `axis1_return_hold_axis3/5_rel` / `axis6_fast_entry_abs` / `axis6_coupled_settle_rel`；
   - 若导管模式（非协同），计算 `axis6_coupled_target_abs = axis6_fast_entry_abs - (axis1_target_abs - axis1_fast_entry_abs)`（axis6 镜像反向跟随 axis1 快退）；
   - 进入 SwitchWait 阶段；错峰切缸开始（见 §8）。

### 6.3 SwitchWait 阶段（错峰切缸 + 夹爪预紧）

- 等待 `axis1_cylinder_interstep_wait_ms(50ms)` + `axis1_pre_move_cylinder_wait_ms(100ms)`；
- 若 axis6 联动（`axis6_coupled_active`），取 axis1 和 axis6 两个等待时间的最大值；
- axis1_fast_return = true（每拍置位）；axis6_fast_retract = true（联动时）；
- 镜像轴 3/5 用 `axis1_return_hold_axis3/5_rel` 锁住。

### 6.4 FastMove 阶段（PLC 计划回退）

- `pos[0] = target_abs - init_pos[0]`（让 refer 跟随 target_abs）；
- 首次进入时 `request_axis_return(AdsSymbol::axis1_return, target_abs, vel, acc, dec, jerk)`；
- 联动时 axis6 也走 `request_axis_return(AdsSymbol::axis6_return, axis6_coupled_target_abs, ...)`；
- 每拍轮询 `read_axis_return_status`；
- 完成条件：`axis1_return_status.done` +（联动时）`axis6_coupled_done`；或位置进入容差；
- 出错处理：清回退请求 + 单轴 `sync_axis1(3, false, 0)` + 回到 Follow。

### 6.5 RestoreWait 阶段（错峰切缸 + 夹爪恢复）

- 等待 `axis1_post_return_cylinder_wait_ms(100ms)` + `axis1_cylinder_interstep_wait_ms(50ms)`；
- 角色互换：cyl2 先合，cyl1 后开（与 SwitchWait 相反）；
- 完成后 `sync_axis1(3, false, 0)` 重建跟随基准 -> 回到 Follow。

## 7. axis6 爬行状态机（`main.cpp` L1342-L1497，独立/协同模式）

axis6 的状态机由 `run_axis6_crawl_state` lambda 封装，独立模式和协同模式共用。与 axis1 状态机的关键差异：

### 7.1 独立模式

- axis1/2/3/5 全部冻结在 `independent_axisN_hold_rel`；
- axis6 线性增量直接来自 587 手柄；
- `require_user_increment_for_trigger = false`（即使操作者不推手柄，到达窗口边也能触发快退）；
- 错峰切缸用 cyl3/cyl4（而不是 cyl1/cyl2）。

### 7.2 协同模式

- axis1 链路正常工作（导管推进/快退）；
- axis6 的"用户增量"叠加 axis1 的位移增量：`axis6_combined_increment = 587_increment + axis1_increment`；
- `axis6_coop_ff_inited` / `axis6_coop_prev_axis1_cmd_abs` 用于 axis1 增量的差分计算；
- axis6 处于快退阶段时 axis1 增量被忽略（`axis6_coop_ff_inited = false`）；
- `require_user_increment_for_trigger = true`（要求 587 本人必须有有效增量才能触发反弹，避免 axis1 推送意外触发 axis6 回退）。

### 7.3 axis6 状态机阶段

与 axis1 相同的四阶段（Follow / SwitchWait / FastMove / RestoreWait），但快退请求是 `AdsSymbol::axis6_return`，错峰切缸用 cyl3/cyl4。

## 8. 气缸错峰切换（`staggered_pair` lambda）

每对夹爪在快退切换瞬间不能同时打开/闭合，否则器械会瞬间双开释放。`staggered_pair` 的语义：

```cpp
staggered_pair(close_cmd, close_val, open_cmd, open_val, seq_t0, stagger_ms):
    close_cmd = close_val;                              // 立即下发 close 侧
    if (now_ms - seq_t0 >= stagger_ms):
        open_cmd = open_val;                            // 经过 stagger_ms 后才下发 open 侧
```

- axis1 链路使用 `axis1_cylinder_interstep_wait_ms(50ms)`；
- axis6 链路使用 `axis6_cylinder_interstep_wait_ms(50ms)`；
- 联动时取两侧较大值；
- `seq_t0` 在进入新阶段时刷新为 `now_ms`。

典型用法（axis1 SwitchWait 阶段）：
```cpp
staggered_pair(cylinder1_cmd, cyl.cyl1_clamp,    // cyl1 立即夹
               cylinder2_cmd, cyl.cyl2_open,     // cyl2 等 50ms 后开
               axis1_crawl.cyl_seq_t0, cfg.axis1_cylinder_interstep_wait_ms);
```

## 9. 已知问题 / 待确认点

### 9.1 `set_axis6_independent_window` 的 left clamp 修正

当 axis6 距左限位太近时，窗口 left_abs 会被强制抬到 `leftlimit[5]`，导致窗口实际变窄。若窄到小于 `crawl_arrive_tol_mm`，函数返回 false 阻止模式切换。这是预期行为，但**没有 UI 提示**让操作者知道为什么进不去导丝模式，只输出一句"axis6 独立窗口距离左限位过近"。

### 9.2 `CrawlState::SettleHold` / `ClampWait` 阶段当前未使用

枚举里保留了 `SettleHold` 和 `ClampWait`，但主循环没有 case 分支处理。如果未来需要在 FastMove 和 RestoreWait 之间插入新的等待阶段，可以启用；现在不要把它们误当作"活跃阶段"。

### 9.3 `cooperative_mode` 与 axis1 快退耦合

导管模式（非协同）下 axis1 快退时 axis6 会镜像反向快进（`axis6_coupled_active = true`）。协同模式下相反：axis1 快退时 axis6 **不**联动（`axis6_coupled_active = false`，见 `main.cpp` L1793-L1799）。这是为了让协同模式下导丝和导管的快退独立触发。修改这个逻辑前务必理解现场工艺。

### 9.4 `reverse_switch_trigger_guard_mm` 是软保护

正反向切换瞬间，若 axis 实际位置距离新的触发边太近（≤ 2.0mm），会拉起 `reverse_switch_guard_active`，阻止该次切换立即触发快退。需要 axis 离开 2mm 后才允许触发。这是为了防止"在窗口边缘反复横跳导致连续触发"。

### 9.5 `startup.final_axis6_from_left_mm` 默认 = axis5 + gap

`main.cpp` L395 初始化 `startup.final_axis6_from_left_mm = cfg.startup_axis5_ready_from_left_mm + cfg.axis56_ready_gap_mm`。但 UI 可以单独设 axis6（`SetStartupAxisPos` case 6）。如果 UI 设的 axis6 比 axis5 小，会触发参数校验失败（`valid = false`）。**这是有意的**——避免导丝轴被设到导管轴后面。
