## 当前状态

新模型在 C++ 中逐点计算，无 Python 运行时依赖，不等待未来采样点。
导管和导丝模式的 fn、ft 图均增加红色虚线“模型处理”；原曲线保留。
正常递送阶段修正量为零。模型不足、标定不一致、输入无效或预热期间不修正。
模型只服务实验显示与记录，没有连接运动指令或力反馈输出。

导丝：15 条标签筛选通过的完成记录，90 个完整往复，按文件划分为 11 条训练、4 条测试。
导管：剔除“电缸不好使”等记录后不足 4 条，不生成可用参数，不借用导丝参数。
最低 4 条仅为软件的数据量门槛，不代表模型已得到充分验证。

在留出导丝记录上，相对事件前参考水平的 RMSE：

| 通道 | 不补偿 | 因果模型处理 |
| --- | ---: | ---: |
| fn | 0.479883 N | 0.537814 N |
| ft | 0.025109 N | 0.015762 N |

fn 尚未改善，ft 有改善；两者仍按实际预测绘制。该结果不是独立真实外力精度，
不能作为透明度改善或临床效果的证据。目录名只是条件标签，不是独立的空载确认。

## 输入、模型和状态

特征顺序：常数、v、abs(v)、a、j、运动端电缸指令、固定端电缸指令、
sin(angle)、cos(angle)、释放指示、回程指示、重夹持指示、阶段经过时间、
经过时间平方、v*a。v 为 mm/s，a 为 mm/s^2，j 为 mm/s^3，角度读入 deg，
时间为 s，电缸为 WORD 指令，输出为 N。经过时间上限 0.5 s。

加速度由速度后向差分得到，再用 alpha=dt/(0.003+dt) 递推平滑；
jerk 由该加速度后向差分及相同递推平滑得到。
这是因果运动特征估计，不对测得的力做低通滤波。
因果并不代表没有估计相位误差，也不能补偿传感器或通信自身的延迟。

预测式：d = ((features - center) / scale) * beta。
拟合采用带未惩罚截距的岭回归，每个往复获得相同总权重。
导出的部署参数只拟合训练文件，未把测试文件重新合并用于拟合。
辅助周期随机划分仅评价同批记录内重复性，不能代替按文件留出的结果。

每个事件前 [-100,-10) ms 的同周期力中位数为拟合参考，至少需要 5 个点。
缺少参考的事件不参加拟合；推断不使用这个参考，也不输入测得的力。
标签仍然可能含实际外力变化，因此称参考水平，不称真值。

逐点计算收到重复或倒退时间戳时跳过该点；无效输入重置历史。
间隔超过 3 ms 重置；初始化或重置后 10 ms 内不补偿。
进入新阶段或新周期重置事件计时；重新取零、切换模式、重新开始清空曲线会话。

## 力值定义

训练和界面均采用安装标定后的增量力：
fn = fn_sensor_N * installation_axial_gain；
ft = ft_sensor_N * installation_torque_gain / tangential_arm_mm。
这是现有 GET_PROGRAM 界面的定义，不是原始计数，也不采用旧模型的解耦力矩字段。
当前轴向增益 2.85 保持用户修改不变。

旧记录先按其记录的传感器斜率还原标度，再应用当前斜率及安装增益。
运行时检查两种安装增益、力臂及四个传感器斜率是否与训练一致；
修改标定后需要重新辨识和构建，否则模型显示不可用。
既有标定链与原始 CSV 字段均未更改。

## 实验显示与保存

后端在原有分块采样到达时逐点更新模型，保留最近 10 秒的完整成对曲线。
PROGRAM_CURVES|after|generation 按游标传回新增点，每次最多 1024 点；
会话变化清空旧曲线，溢出或断续会提示缺段。两条线使用同一采样时间和纵轴范围。
程序模式界面刷新目标为 33 ms，旧模式仍为 100 ms，单次在途轮询防止重入。

PLC 当前块容量 512 点，后台轮询间隔约 10 ms。
界面显示的是实际块时间跨度，不是完整通信延迟；不承诺毫秒级端到端响应。
必须到实机测量发布、传输和接收时间，才能确定完整等待时间。
这里没有修改 PLC 缓冲结构或运动程序以缩短分块等待。

每次新实验目录新增：
- causal_force.csv：序号、PLC 时间、周期、阶段、原力、预测扰动、处理力、
  模型有效性、单点计算耗时。
- causal_model.json：模型版本、可用性、标定常量、系数和标准化参数。

原始 samples_1khz.csv、events.csv 和既有标定文件保持原定义。
新增结果文件使用原记录器的后台写线程；记录失败沿用原有故障处理。

## 验证

Python 单元测试覆盖未来数据不影响过去输出、截断一致、间隔/无效输入重置、
重复时间戳、阶段计时及截距。C++ 测试覆盖数值对齐、两个通道、阶段门控、
不可用模型、断点重置以及曲线游标与容量。
11,639 个真实回放采样的 Python/C++ 最大差异约 4.4e-16 N。
优化构建的单点耗时 P95 约 0.1 us；这是本机测试，不是 PLC 硬实时保证。
verification.json 保留本次耗时、误差和记录测试目录。

两种模式各 600 个合成采样验证独立结果落盘及模型快照，合成数据只在
x64/Debug_causal/records 内，不混入实际训练目录。
WPF 的 --curve-replay <parity_fixture.csv> 模式不打开管道、不连接 ADS，
也不启动后端，可用 --curve-snapshot <png> 导出界面进行检查。
synthetic_catheter_unavailable_fixture.csv 仅用于验证导管无模型时的界面，
不是导管实验结果。正常启动程序则使用真实硬件连接流程。
