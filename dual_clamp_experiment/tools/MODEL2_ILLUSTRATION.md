# Model2 target illustration

This is not a dynamics model, force estimator, or performance validation.
All four display channels compute independently from installed, zero-referenced
original force in N. Neither motor commands nor haptic feedback are modified.

`F2 = F - 0.8 * w * (F - reference)`.
The 0.8 factor is manually chosen, not identified.
The reference is the median of finite original samples aged (10,100] ms,
with at least five samples per channel. It is frozen for the operation.
The existing model1 command/phase gate starts the operation window.
After the gate falls, the correction remains fully applied for 120 ms so
the recorded mechanical response can settle; it then exits with a 40 ms
cubic smoothstep from the current weight.
Reentry before fade-out completes retains the same reference. An invalid
reference remains invalid for that operation. No future samples are used.
Duplicate timestamps do not update state; gaps over 3 ms, backward timestamps,
mode changes, zero changes and experiment restarts reset state.

Checkboxes affect visibility only, default off, remembered separately for each
mode and channel during the UI session. Orange dashed curves denote Model2.
`model2_illustration.csv` and `model2_illustration.json` are independent sidecars.
Missing references are empty CSV fields. Validity indicates reference
availability, not model accuracy; weight zero means no illustration correction.
Original files and model1 results retain their existing format.
Identification code is unchanged and does not use the illustration sidecar.

Offline fixtures are generated by the production C++ Generator from actual
`causal_force.csv` original values and recorded gates. Opposite-mode fixtures
are explicitly named synthetic and are display plumbing tests only.
Any apparent reduction must not be reported as compensation performance,
transparency improvement, or experimental evidence.
